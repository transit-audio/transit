# ADR 0033: Built-in instruments: a port of the Mutable Instruments family

- **Status:** proposed 2026-10-29 (maintainer decision)
- **Date:** 2026-10-29
- **Reopen when:** the crates.io evaluation finds no acceptable starting point and the Rust port proves too costly to carry; the upstream license terms change; the null-test residual floor cannot be measured stably on CI hardware; or a product question asks for engines the family does not cover.

## Context

transit has no built-in instruments beyond what it inherited. The maintainer wants wavetable and granular synthesis. Writing generic engines from scratch would mean months of sound design with no reference to judge them against.

Émilie Gillet's open-source Mutable Instruments DSP (the `eurorack` repository on GitHub, code under the MIT license) is a coherent, proven family:

- Plaits: a macro oscillator with virtual analog, wavetable, FM, additive, physical-model and drum engines. Firmware 1.2 adds six-operator FM, wave terrain, string machine and chiptune.
- Rings and Elements: physical modeling.
- Clouds: granular texture synthesis.
- Warps: a meta-modulator, which is an effect.
- Marbles and Grids: random and drum sequencers, which are MIDI effects.

The modules were built to run on a Cortex-M4, so CPU cost is low, and they share one design language.

## Decision

Port the family as small, focused built-in instruments and effects. They are mono by design where the originals are. Users build bigger instruments by composition: a track chain (an instrument plus inserts) and a group of tracks, the rack of [ADR 0034](0034-racks-layering-instruments-through-track-groups.md).

Order: Plaits first, with a voice allocator and a small editor, as the first slice of v0.6.0. Then Rings, Clouds, Warps, then Marbles and Grids.

Rules, each agreed by the maintainer:

1. Port only from the original repository. Never port from VCV Rack's Audible Instruments, which is GPLv3 and would contaminate transit's MIT/Apache-2.0 licensing.
2. No Mutable Instruments branding on the instruments. They get descriptive names of transit's own (as VCV did with Macro Oscillator, Resonator and Texture Synthesizer). Credit Émilie Gillet explicitly, with her MIT notice, in the about box, in each instrument's help entry and in a third-party license file.
3. Polyphony, the editor window and the rack are transit's own work. Polyphony is a voice allocator around N mono engines with a note-to-macro mapping (pitch, harmonics, timbre, morph). The editor follows the ownership rules of [ADR 0030](0030-editor-window-cohesion.md).

### Implementation

A Rust port in a transit-owned crate with a descriptive, brand-free name (the Plaits port is `transit-macro-osc`; see the amendment below). The shipped app is pure Rust.

Before any port starts, evaluate the existing crates.io port (`mi-plaits-dsp`) for license and fidelity. The evaluation is a prerequisite, not a decision: it informs whether to adopt, fork or write the port, and this ADR does not pre-empt it.

### Gate

Null tests against her C++, wrapped as a dev-only oracle. The oracle is built with the `cc` crate for tests and CI only and is never linked into the app.

- Same model, seeded noise, fixed parameter sweeps, compared sample by sample at 48 kHz with her block size.
- The residual floor is measured first, with FP contraction and fast-math off. The gate is set at that floor with margin. A residual above the floor is an escape.
- The port is tested at the mono-voice level. The allocator, the editor and the rack get ordinary tests.

## Consequences

- A coherent instrument section with one design language and low CPU.
- The DSP risk is retired by the oracle; the design work moves to composition and UI.
- Every ported module adds its own oracle build to CI.
- Third-party license text and credits become a maintained deliverable of each release that ships a port.

## Alternatives considered

- Generic wavetable and granular engines from scratch: months of sound design and no reference to test against.
- The C++ via FFI inside the app: adds a toolchain and an unsafe surface. Rejected; the C++ stays in the test oracle.
- The VCV Rack ports: GPLv3, which conflicts with transit's licensing.
- Shipping under the original names: contrary to the branding request.

## Amendment 2026-10-29: crate naming and the Plaits source decision

Maintainer decision, 2026-10-29. This amendment supersedes the crate naming in Implementation above and records the outcome of the crates.io evaluation (#193).

**(a) Crate naming.** The rule `transit-mi-*` is replaced. The eurorack README asks derivative works not to keep the original module names, so crate names are descriptive and brand-free: each names what the crate does, not whose module it came from. The Plaits port is the crate `transit-macro-osc` (macro oscillator). Later modules take names that describe what they do, for example Rings is `transit-modal-resonator`, not `transit-rings`.

**(b) Source decision (#193, 2026-10-29): option (b), vendor the MIT Rust port.** The port is `mi-plaits-dsp-rs` by Oliver Rockstedt (GitHub `sourcebox`), vendored at commit `effe9864bb` into `transit-macro-osc`. Its terms:

- Rockstedt's MIT notice stays in the source and the crate.
- Émilie Gillet's full MIT notice from `eurorack` and `stmlib` is restored in the crate `LICENSE` and in the third-party license file.
- The source commit (`effe9864bb`) is recorded in the crate and in the third-party file.
- Before any engine ships, each one is corrected against the C++ oracle (#194): per-instance RNG; sample rate as a parameter, not a constant; an audit of the interpolate clamps; the VA auxiliary oscillator phase returned to firmware behavior; and the snare and VOSIM details.

**(c) Fallback.** If the vendored code needs more repair than it saves, port from the firmware instead (option c), behind the same oracle gate. The null tests compare output sample by sample, so the swap is invisible to users.

Related: #193 (the evaluation and this decision), #194 (the C++ oracle that gates each engine). Naming also runs the other way: the devices transit inherited under their old names are retired in stages, twelve in v0.6.0 ([ADR 0040](0040-inherited-built-in-effects-retired-in-stages.md), #264).

## Implementation note: oracle

The Gate oracle is `crates/macro-osc-oracle` (`transit-macro-osc-oracle`, #194): the upstream C++ vendored unchanged, dev-only (`cargo xtask layers` rejects any normal or build dependency on it), with its FFI `unsafe` confined to `src/ffi.rs`; the sweep, the residual and the measured floor are in [gates.md, Oracle null tests](../contributing/evidence/gates.md#oracle-null-tests).

## Oracle deviation note 2026-10-30: the six-op engine after shared RAM

The firmware's engines share one 16 KB RAM arena (`Voice::Init` frees the allocator before each engine's `Init`), and the six-op engine keeps its staggered-render accumulator there without clearing it in `Reset`. On the module, the first block after the voice returns to a six-op bank from the string machine, speech, swarm, particle noise or inharmonic string engine (or the wavetable engine, on a 64-bit host only) therefore adds that engine's leftover bytes, read as floats, to the output: arbitrary values up to a NaN, which the C++ cast turns into a full-scale -32768 click. The port's engines own their memory, so the six-op engine replays its own last partial sum, which is the module's output whenever nothing overwrote it; the port is never louder than the module there. Won't fix: on the module, the first 12-frame block (0.25 ms) after returning to a six-op bank from one of six engines adds that engine's leftover memory to the output, which can be a click; transit plays the six-op engine's own tail instead, as the module does after any other engine. Reproducing it would mean emulating every engine's byte layout and the host's pointer size to replay garbage. The voice gate pins the difference to that one block (`six_op_reentry_after_a_ram_sharing_engine` in `crates/macro-osc/tests/voice_scenarios_vs_oracle.rs`); every other frame of every voice scenario is compared at 0 LSB. This is an oracle deviation, not a transit known issue: no user can hit it, since nobody compares the DAW with the module (#195).

## Implementation note 2026-10-30: the Macro Oscillator instrument (tuning, names, MIDI)

The first instrument of the family ships as the built-in "Macro Oscillator" (`macro_oscillator`, in `transit-dsp` beside the other built-ins, over `transit-macro-osc`; `transit-dsp` takes the same-layer dependency and is no longer standalone, #195).

- **Tuning.** The firmware computes pitch against its corrected rate (47872.34 Hz, the module's codec clock), so the module plays in tune while the same arithmetic at a true 48 kHz plays 4.6 cents sharp. The instrument plays concert pitch by default (A4 = 440 Hz): `Voice::set_tuning(Tuning::Concert)` scales every frequency the firmware derives from its corrected rate (the voice's `a0`, the six-operator voices' reference, the speech formants) by 47872.34 / 48000, and divides the LPC speech pitch shift's corrected rate by the same factor, so A4 is 440 Hz on every path. The firmware's LPC path is pitched differently by design: in `lpc_speech_synth_controller.cc` the corrected rate cancels out of `pitch_shift` and the LPC clock is the raw sample clock / 6, so at a true 48 kHz the firmware's LPC speech is in tune while its other paths are 4.6 cents sharp (on the module, the other paths are in tune and LPC speech is 4.6 cents flat). `crates/macro-osc/tests/voice_pitch.rs` checks every path's absolute pitch at every rate ([E63](../escapes/E63-the-speech-model-played-out-of-tune-away-from-48-khz.md)). The port plays at concert pitch; the firmware's arithmetic is kept bit-exact in the crate (`Tuning::Firmware`, the crate default) for the null tests, and the module itself plays in tune because its audio clock runs at the corrected rate. So there is no switch back to the firmware's pitch: at a true 48 kHz it would only detune the instrument by 4.6 cents while claiming to match the hardware (a "Hardware Tuning" parameter existed briefly on the slice 3 branch and was removed before merge; a session that stored it loads, and the open logs the ignored id).
- **Names.** The 24 models are named by what they do, in the firmware's order: Filtered analog, Phase distortion, Six-op FM 1 to 3, Wave terrain, String machine, Chiptune, Virtual analog, Waveshaper, FM, Grain, Additive, Wavetable, Chord, Speech, Swarm, Filtered noise, Particle noise, Inharmonic string, Modal, Bass drum, Snare, Hi-hat. No module or brand name appears in a UI string or identifier.
- **MIDI.** The held note is the voice's V/OCT input, a note-on raises its trigger and sets its level input from the velocity, a note-off lowers both so the low-pass gate's decay is the release. Mono, last-note priority, legato as the module's trigger input behaves: a note under a held one changes pitch with no new trigger. A new phrase whose note-on shares a 12-frame block with the last note-off gets one low block first, so the voice sees the edge. A legato note sets the level input to its own velocity, so the level steps mid-phrase as the module's level CV does (Ableton and Logic keep the running envelope on legato; documented in the user guide). Sustain holds released notes; pitch bend spans a parameter range (2 semitones by default); the mod wheel adds to a chosen control (Timbre by default).
- **Blocks and output.** The voice renders 12-frame blocks (its envelopes are timed per block) whatever the host block, carrying rendered frames across host blocks, so any host block size renders the same bits; events take effect at the next 12-frame boundary. The int16 frames become floats as `(1 - s) / 32768`: polarity restored and the firmware's +1 truncation offset removed (silence is exactly 0), full scale one LSB under 0 dBFS (+1 reads 32767/32768, -1 reads -32766/32768; only the clip reads 32769/32768, +0.0003 dB); the default level is -6 dB.
- **Credits.** Émilie Gillet's MIT notices (eurorack, stmlib) and Oliver Rockstedt's are in ATTRIBUTION.md, NOTICE and Help > About transit; the panel and its help entries credit the original; the user guide says it is a port, not an emulation of the hardware's analog stages.
- **Rack-ready, not racked.** One mono voice, MIDI in, one audio output on every channel, parameters addressed by automation id (`plugin:instrument:<id>`). Unison and layering are ADR 0034's racks; polyphony inside the one instrument followed in #196 (next note).

## Implementation note 2026-10-30: voices, note-to-macro mapping, editor (#196)

- **Voices.** `voices` (1 to 16, default 8) firmware voices inside the one instrument, all built with the instance (the parameter can change on the audio thread without allocating). Voice `i` is seeded `Random::DEFAULT_SEED + i`, and a reset reseeds every voice, so exports and renders after a reset play the same bits. A note-on takes, in order: the voice already playing that key (held, under the pedal, or in its tail), the lowest-numbered free voice, the quietest voice in its release tail (a peak follower falling 0.5% per 12-frame block; the oldest phrase among equals), else the oldest held voice; a stolen held voice gets one low trigger block first, so it sees a new edge. A note-off leaves the voice's low-pass gate tail playing; a voice is free once it holds no key, its trigger is low and both outputs have stayed within one int16 LSB of silence (-90 dBFS) for 50 ms (six-op FM 2 settles on a ±1 LSB residue, never exact zero), and a free voice is not rendered; every model goes idle within the tail (`every_model_releases_to_an_idle_voice_within_the_tail`). The chiptune model bypasses the low-pass gate and, with no envelope set, holds its note for ever (on the module too, with the TIMBRE attenuverter at 0): a held key keeps it held, and after the note-off the voice sets its envelope from Decay (`chiptune_release`, silent in 0.15 s to 9 s), so its note ends as on the other models. This fixes a slice 3 defect (a chiptune note never ended). Voices above a lowered count release and play out. `voices` = 1 is the mono instrument above, bit for bit in its legato rules. The voices sum in voice order, so the instrument plays exactly the sum of independent mono voices (`n_voices_render_the_sum_of_n_mono_renders_bit_for_bit`). No unison and no automatic gain for wide chords: voices add, as in Ableton's and Logic's synths. The steal order follows the convention of both DAWs' stock synths (steal the oldest note), with a preference for released voices first, quietest first; a stolen held voice is silent for one 12-frame trigger block (0.25 ms at 48 kHz) so its envelopes restart on a clean edge.
- **Note-to-macro mapping.** Velocity (0..1) and the key (-1..1 around middle C, MIDI 60, which Live and Logic both name C3 and Live's key tracking is relative to; ±1 at 60 keys away) drive Harmonics, Timbre, Morph and Decay through a depth each (-100% to +100%, default 0) and a curve per source (Linear, Exponential, S-curve: the clip fades' curves, `FadeShape::gain` called directly). As in the MIDI Learn range model the source's travel spans a part of the target's travel (no change to `depth` for velocity, `-depth` to `depth` for the key) and a negative span inverts. The sum is clamped to 0..1, then the mod wheel adds; with every depth at 0 each target is its knob exactly, so the defaults play as #195 (velocity sets the level, as before). Key tracking of Timbre ships as the "Key Tracked Timbre" factory preset (`key_timbre` +50%).
- **Editor.** Every built-in editor in transit is an egui window inside the main window's viewport (`builtin_editor.rs`), not a separate OS window, so ADR 0030's outcome (minimize, restore and front with the main window, no taskbar entry, never duplicated) holds by construction and the `editor_group` requests do not apply; `ui.inspect` lists it as `builtin` (`the_macro_oscillator_editor_stays_with_the_main_window_and_is_never_duplicated`). Rather than a first viewport for one built-in, the panel grows in place: a Voices section with activity lights (read from the instrument's scope tap, `Plugin::voice_activity`, stored only while the panel is open) and the mapping grid (a row per source, a column per target).
- **Cost.** One voice costs 5 to 70 us per 256-frame block at 48 kHz (0.1% to 1.3% of one core; the median of the eight models measured is 26.6 us, 0.5%) on the development machine, measured by `crates/dsp/tests/macro_osc_cost.rs` (ignored, release); the figures are in the crate README for the rack budget.

## Implementation note 2026-10-31: the Macro Oscillator's shaper and modulation matrix (#243)

The shaper and the matrix are transit's addition, not part of the original module; the panel says so on the line that shows them. Both are off by default: with the shaper off and no active row, the instrument renders the bits it rendered before them, and the null tests against the oracle are untouched (the vendored port's numerics are not changed; everything below lives in `crates/dsp/src/plugins`).

Convention: Ableton's Wavetable and Logic's ES2 and Alchemy route modulation through a matrix of rows (source, destination, amount); the "via" (a second source scaling a row's amount) follows ES2's modulation router (Source, Via, Target), which Alchemy's modulation also has. The curves are the clip fades' shapes, as the note-to-macro mapping's were.

- **Where it sits.** Per voice, after the firmware's low-pass gate and the aux crossfade, before the level and the voice sum: drive (soft clip), the Filter insert's SVF sections (`filter/svf.rs` `Section` and `Coefs`; 12 dB one section, 24 dB a second Butterworth one), then the amp envelope's gain (the built-in instruments' `Adsr`). With the shaper on the gate's level input is held at 1 (open) and the amp envelope is the voice's envelope: a voice is free once no key holds it and its amp envelope has finished. Off, the low-pass gate's decay is the release, as before. Whether the shaper shapes a voice was first taken when the voice's phrase started and kept until the voice was free; since #262 a held voice follows the switch at once and only a voice in its release keeps its path (the held-note rule, in the note of 2026-10-31 below). The LFO is the Filter's, moved to `plugins/lfo.rs` as a pure move, then given a smooth random shape, a seed per instance and `set_phase`.
- **Evaluation order.** Once per voice per 12-frame block, so the firmware's block alignment stays and any host block size renders the same bits (`the_shaper_and_a_full_matrix_render_the_same_at_any_block_size_and_after_save_and_load`). In a block: a new phrase gates the envelopes, draws the note's random value and restarts or picks up the LFOs; a synced, free-running LFO takes its phase from the song position; the sources are read (envelope levels and LFO values as of the block start); the rows run in order, each adding `amount · via · curve(source)` to its destination (a row with source or destination Off, or amount 0, is dropped when the parameters change, and a matrix with no active row is not evaluated); the sums are applied; the filter's coefficients are worked out; the frames are shaped; the LFOs advance. The LFO amount sums act one block later (the LFOs feed the matrix). Fixed storage throughout: the probe with 16 voices, the shaper and every row active allocates nothing (`sixteen_voices_with_steals_the_shaper_and_a_full_matrix_allocate_nothing`).
- **Clamping.** Harmonics, Timbre, Morph and Decay: knob plus sum clamped to 0..1, then the mod wheel (capped at 1), exactly the mapping's rule, and a target no row moves is its knob exactly. Pitch: 24 semitones per unit, the note clamped to ±96. Level: gain `1 + sum` clamped to 0..2. Pan: a balance clamped to ±1 that leaves the near side at unity, so a centered voice's gains are exactly 1 and the voice sum is unchanged bit for bit; with any Pan row the instrument's output is stereo (first channel left, second right, any other their mean). Cutoff: six octaves per unit on top of key tracking and the filter envelope, clamped to 16 Hz .. 0.49·fs. Resonance: the knob's travel. Filter env amount: clamped to ±1. LFO rate: ×2^(4·sum), the sum clamped to ±1, for free-rate LFOs (a synced one follows the tempo). LFO amount: base plus sum clamped to 0..1.
- **Sources.** The rack's eight macros reach a member's instrument through `Plugin::reads_rack_macros` and `set_rack_macros`, which the mix calls each block with the macro knobs or their lanes' values (0 for a track not in a rack). Aftertouch, poly aftertouch and the note-off velocity are read from the instrument's events.
- **Tempo sync (#245).** A synced LFO with retrigger off counts its phase from an anchor (sample and song position) set when playback starts, jumps or changes tempo, in whole frames, so playback from bar 5 and an export from bar 1 place it the same and host block sizes agree bit for bit at a constant tempo; a tempo change re-anchors at the next host block start, the caveat #245 states for the Filter. Both devices use the shared phase rule below and keep their own update grids: the Filter once per host block, the Macro Oscillator once per 12-frame voice block. Bar divisions use the shared rule in `crates/dsp/src/plugins/lfo.rs` (#253): `(zero-based bar + quarters into the bar / quarters per bar) / bars per cycle`, mod 1. A meter change updates the bar anchor at the changed bar start, even mid-cycle, preserving the bar count; it never resets the cycle at a mid-bar host boundary. Meter changes are on bar lines, observed at the next host block start, and the phase includes the elapsed part of the bar. Beat divisions keep the absolute-quarter rule and its arithmetic. Known limit: the anchor places the phase, not the history, so Sample & hold and Smooth random (whose values depend on how many cycles came before) can play different values from bar 5 than an export from bar 1 plays there; the other four shapes match.
- **Migration.** The note-to-macro mapping of #196 is the matrix's first rows: `transit_model::legacy_mapping` rewrites an old session's Macro Oscillator (on load, so every open path applies it) and an old preset (on parse) as one row per depth that is not 0 or that something drives (velocity rows first, then key, each Harmonics, Timbre, Morph, Decay), in the first free rows; the depth becomes the amount, the source's curve the curve (the first three curves keep the mapping's indices). Automation lanes, MIDI mappings and rack macro targets move with them (a curve's lane and macro targets to every row of its source, its MIDI mapping to the first, its range rescaled from the old three curves to the five so the same travel picks the same curve). A track whose depths are all 0 with nothing driving them, which every v0.5 session with a Macro Oscillator stored, loses the old ids silently: no row, no load note, and the session opens unmodified. A track that gets a row or has something moved makes the session open as modified with one load note, which also says when a curve's MIDI mapping now drives only the first row of its source. The proof is two fixtures saved by the build before #243 (`crates/engine/tests/fixtures`): the note-mapping session, migrated, renders the golden hashes that build rendered, at 512 and 64 frames per block, and the plain session renders its golden with the new parameters absent or present at their defaults (`crates/engine/tests/macro_osc_matrix.rs`). The "Key Tracked Timbre" preset is rewritten as a Key to Timbre row and plays its old golden. The mapping's ten parameters and its panel grid are gone.
- **Parameters.** 123 in all (the module's 12, the shaper's 31 with both LFOs, five per row: `mod<n>_source`, `_via`, `_dest`, `_amount`, `_curve`), every one an automation target by its id. Parameter maps up to 128 entries are now tracked inline in a plug-in slot (`APPLIED_INLINE`), so the instrument's values reach it on the audio thread without prepared storage.
- **Cost.** 16 held voices per 128-frame block at 48 kHz (budget 2667 us), median of nine runs of 1600 blocks, Ryzen 9 5900X, `timing_shaper_and_full_matrix_at_128` (ignored, release): with the shaper and all sixteen rows active, Virtual analog 188 to 198 us (7.1% to 7.4% of one core), Six-op FM 1 160 to 164 us (6.0% to 6.2%), Wavetable 244 to 248 us (9.1% to 9.3%), Modal 644 to 659 us (24.1% to 24.7%); the shaper and matrix add about 25 to 36 us per block for the 16 voices (about 2 us per voice, 1% to 1.4% of the block), within run-to-run noise of about 30 us on the heaviest model. The Pi 5 figure waits for #237.

## Implementation note 2026-10-31: same-pitch re-strikes and the held-note shaper rule (#263, #262)

**#263, the same-pitch restart.** On the six-op FM models a key struck again while its note still sounds (a loop replaying a note that ends at the loop end, a quick repeat on the keyboard) could sound hollow for up to 90 ms, the pitch jumping an octave or a twelfth: the firmware starts every trigger's note on the engine's other internal voice and lets the voice that was sounding play its release, so the old note's release (patches whose modulators hold at release level 99 keep it nearly as loud as the note) summed with the new note at the same pitch and a phase offset fixed by the gap, cancelling the fundamental. Derek's decision (2026-10-31): no user-facing switch, "I'd prefer just going with the fix ... to retrigger it properly so it just doesn't happen - it's not something I would want my synth to do in a DAW or live performance." The hardware never sees a zero-gap re-strike (a sequencer's gate drops before the next step), so this is the behavior the module would show if its trigger input saw what a DAW sends.

- **The rule.** `SixOpEngine::set_same_pitch_restart` (through `Voice::set_same_pitch_restart`), an engine field, off in the crate and on in every voice of transit's instrument; never a parameter. On a trigger's rising edge the engine restarts the internal voice already sounding instead of switching when its patch is the one the edge selects, the edge's note input is within half a semitone (`SAME_PITCH_SEMITONES`) of the note that voice was struck at, and that voice still sounds (its gate is high or an operator envelope has not finished its release). The engine has no pitch quantizer, so "the same pitch" is the note input as the engine receives it, bend and pitch offsets (tune, a matrix Pitch row) included: a bend or offset held across both strikes is the same pitch, one moved by half a semitone or more between them is not, and that re-strike switches voices as the firmware does.
- **The restart.** The operator and pitch envelopes start their attack from their current levels (no jump in level), the note and velocity are sampled and the LFO resets, as at a note-on, and the operators' phase is reset when the patch asks (the engine's own rule), so the re-struck note has the first strike's timbre: restarting without the reset measured the held note's drifted spectrum (the second partial leading 7 of 30 windows). A reset in a sounding waveform is a step (a second difference about nine times the held note's), so the voice's next two renders (48 frames, 1 ms at 48 kHz) crossfade on a raised cosine from the voice restarted keeping its phase to the voice restarted with the reset; the restart's corner then stays within the held note's and the attack's own (`a_zero_gap_restrike_has_no_click_and_no_dropout`). Only a restart with a reset renders twice.
- **The proof.** With the restart off every oracle null stays at 0 LSB (`TRANSIT_FULL_ORACLE=1`). With it on, the six-op banks' engine-level sweep (78 points each, out, aux and the random state), voice-level sweep (84 points each) and a scenario of re-strikes at other pitches null at 0 LSB; a scenario of same-pitch re-strikes nulls with it off and differs with it on (`crates/macro-osc/tests/same_pitch_restart_vs_oracle.rs`). In the instrument, re-strikes at 0, 10, 50, 100 and 250 ms gaps, mono and with 8 voices, keep the fundamental leading every window with the first note's worst error (23 cents, the patch's vibrato), and every lap of the hunt's loop does too (`every_lap_of_a_six_op_fm_loop_keeps_the_first_laps_pitch`, un-ignored).
- **Other engines.** Only two engines keep a set of internal voices that a trigger rotates through: the six-op engine (two) and the inharmonic string (three strings; the chord, chiptune and swarm engines' voices sound together and do not rotate). The inharmonic string can lead with its second partial after a re-strike 10 to 50 ms after the note-off (20 and 30 of 30 windows; clean at 0, 100 and 250 ms), but the rule would not change it: at the default Harmonics the string is linear, so a second pluck into the ringing string is the same sum as a pluck on a fresh one. It is a re-plucked string's own superposition, not a voice layering a release; changing it would mean damping the string before the pluck, a different behavior outside this decision. The restart is six-op only.
- **The allocator.** A same-key re-strike within one 12-frame block goes to the voice that plays the key and gets one low trigger block with the low-pass gate held at the velocity. The edge is what restarts the six-op engine, so the low block stays. Closing the gate for that block too was weighed and left out: the six-op models bypass the gate, so it would change nothing there, and on the gated models the vactrol would dip for a block and reopen, a notch rather than an attack. The zero-gap re-strike's level envelope (192-frame RMS every block) never drops 12 dB under the held note's lowest level (`macro_osc_voice.rs`, header).

**#262, the held-note rule.** Turning the shaper on or off now applies to held notes at once. On, a held voice joins the shaper where its envelopes are (they run whether or not the shaper is on, so a note past its decay is at the sustain level, or full level with Sustain 100 %; no attack restarts) and its low-pass gate opens; off, it leaves the filter and the amp envelope and the gate carries it on at its velocity. The block of the switch crossfades linearly from the old path to the new over its 12 frames, the filter starting from rest. A voice already in release keeps the path it has until it is free. Tests: a held chord is filtered within one block of the switch (frames 12 to 480 are 0.015 RMS from a render shaped from the start, against 0.44 between the two paths) and matches it from 100 ms on; neither direction steps past the paths' own steps plus the crossfade's (without the crossfade, switching on steps 2.3 times past that bound); a note switched off ends on the gate's decay, so nothing sticks; a tail switched on renders as without the switch (`macro_osc_shaper_tests.rs`). Voices that never see a switch render the same bits as before.

## Implementation note 2026-10-31: the Resonator instrument (#198, slice 3)

The models keep the names slice 1 proposed: Modal, Sympathetic Strings, Inharmonic String, FM Voice, Chord Strings, String and Reverb. Émilie Gillet is credited under the panel, in the help entry `resonator.credits`, in Help > About transit (the credit line and `crates/resonator/LICENSE-THIRD-PARTY`), in `NOTICE` and in `ATTRIBUTION.md`. The vendored file list is unchanged. The port gained one entry point, `Resonator::reset`, which rebuilds what `Resonator::new` builds without allocating (the instrument resets on the audio thread). No DSP changed, and the null tests are untouched.
- **Voices and events.** The part's own rotation is the allocator. A note-on is a strum: the next voice takes the note and the internal exciter strikes it, at polyphony 1, 2 or 4 (the module's panel settings). Two firmware options are not offered. Polyphony 3 is reachable on the module only through the easter-egg path. The easter egg itself (the string synth) is not in the port and the oracle does not cover it. The chord of Chord Strings follows Structure as the module's CV scaler picks it, without its hysteresis (the oracle sweep's rule). The firmware takes one strum per 24-frame block, so notes that arrive in one block (a chord) queue and strum on consecutive blocks, 0.5 ms apart (at most 16 queued; more drops the oldest).
- **Pitch.** The pitch is the key: `note = key - tonic` over the module's tonic (`tonic`, MIDI 12 to 72, default 36, where the sympathetic strings drone at low Structure), so MIDI 69 (A4) plays 440 Hz. Each voice's pitch is its stored `note` (the key less the tonic at its strum) plus the tonic now, so moving Tonic transposes the voices still ringing until they are struck again; only a new strum plays its key. Tune, the bend and the matrix's Pitch go through the FM input and move every voice at once.
- **Gate, pedal and velocity.** The part has no gate: note-offs do nothing to it and it ignores the sustain pedal (documented in the help and the user guide). All Notes Off (CC 123) clears the held keys, the pedal and the queued strums and leaves the part ringing down by its Damping. All Sound Off (CC 120) also resets the part (`Resonator::reset`, which allocates nothing), the shapers and the edge converter, so a host panic silences the instrument at the next 24-frame block. The Macro Oscillator follows the same rule: CC 123 releases its keys, CC 120 resets its voices (a render with no CC 120 is unchanged). The pedal holds the shaper's envelopes, as a held key does. Velocity is the accent: from each strum on, Brightness is darkened by `accent · (1 − velocity)` of itself, as a velocity CV patched into the module's brightness input would act. Brightness is one control for every voice, so ringing voices darken too. At full velocity or Accent 0, Brightness is the knob.
- **Spread.** `spread` mixes the two outputs. At 100% they stay apart, as the module's two jacks: odd and even voices at polyphony 2 and 4, so strums alternate between the sides. At 0% both sides carry the module's mono mix (the two summed, what its first jack carries alone). The default is 50%, so a single note is not hard-panned.
- **Event placement.** The part renders 24-frame blocks (its control block) whatever the host's block, as the edge converter needs them, counted in output frames. An event takes effect at the first 24-frame block that starts at or after its offset (at most 0.5 ms late at 48 kHz). This is the Macro Oscillator's rule on its 12-frame grid, applied to the resonator's 24-frame block. The shaper and the matrix run per 12-frame half block (the shaper's own block, so its envelope and LFO timing is the Macro Oscillator's). The part's macros and its FM input take the matrix's sums once per 24 frames, at the block's start.
- **Rate (the slice 1 question): resampling, not a rate parameter.** The part runs firmware-exact at 48 kHz only. Its output goes through the shared edge converter (`plugins/resample.rs`, the Texture's and the Time Stretcher's), the up converter only, since nothing enters the part. At 48 kHz the converter is an exact copy and the latency is 0. At other rates the latency is the converter's half length lined up on a whole session sample, reported every block:

  | Session rate | Latency (samples) |
  |---|---|
  | 22.05 kHz | 35 |
  | 32 kHz | 35 |
  | 44.1 kHz | 35 |
  | 48 kHz | 0 |
  | 88.2 kHz | 65 |
  | 96 kHz | 70 |
  | 176.4 kHz | 129 |
  | 192 kHz | 140 |

  That is about 0.73 to 1.6 ms. A block is rendered when the converter first needs one of its frames, not when its last input frame arrives, so the latency is the converter's alone. A rate parameter would rescale the firmware's filters, delays and reverb, a variant the oracle cannot check.

- **Shaper and matrix.** The Macro Oscillator's code is used as it is (`macro_osc::shaper` and `macro_osc::matrix` are already public modules, so no move was needed). The panel sections are the same (the shaper and matrix rows are now shared constants in `panel.rs`), and so are the parameter ids and the help entries where a control does the same thing. Held from the note-on to the next; the matrix's Strength destination adds to it (Aftertouch to Strength plays the pressure input). **Deviation (FM Pair).** The firmware's FM voice opens its output from the strength as well as its envelope (`ominous_voice.cc:223`: `level += strength >= 0.5f ? 2.0f * strength - 1.0f : 0.0f`), so with nothing patched the module's FM voice drones. ## Implementation note 2026-10-30: the granular texture processor port (#199, slice 1)

- **Source: option (c), a port from the firmware.** No MIT Rust port derived from the firmware exists: crates.io has none, and the one GitHub file that names the module's playback modes (`tacogips/vactr`, MIT) declares every mode an "architectural adaptation" with no source port and no firmware table. `transit-granular` is transit's own port of `eurorack/clouds/dsp` at `08460a69` (its granular playback mode) and the stmlib helpers it uses, from her MIT C++ only, never from VCV's GPLv3 Audible Instruments; Émilie Gillet's MIT notices are its license chain (`crates/granular/LICENSE-THIRD-PARTY`, `VENDOR.md`). The oracle gained a module (`granular`, `granular_sweep`, `cpp/granular_oracle.cc`), as the resonator did.
- **Rate.** The firmware runs at 32 kHz, its codec's rate, and its grain sizes, feedback filter, diffuser and reverb are tuned for it; the low-fidelity qualities run the grains at 16 kHz behind the firmware's own 2:1 converters. The port runs at 32 kHz only, the one rate where the null tests mean anything, and a host at another rate resamples to and from 32 kHz at the edges, as the module's codec does. Running natively at the host rate would rescale every constant (a variant the oracle cannot check), so it is rejected; the converter, its latency report and pitch tests at every host rate belong to the device (slice 2).
- **Buffer.** The memory is a constructor parameter (`BufferSize`, the firmware's two blocks; `from_seconds` for a 16-bit stereo length), allocated once. Its range is the firmware's own, 0.768 s to 1.214 s in 16-bit stereo (the module: 1.02 s): a grain's read position is 16.16 fixed point in 32 bits, so no recording may exceed 131072 samples. Longer buffers need a wider phase, a deviation outside what the oracle can null.
- **Gate.** All four qualities null at 0 LSB over the granular sweep, a 60 s run per quality and the scenarios ([gates.md, Oracle null tests](../contributing/evidence/gates.md#oracle-null-tests)). The output is the firmware's int16, so no subnormal ever moves a sample: the tests pass with the port's flush-to-zero turned off as well. The flush is kept so the internal state matches the oracle's bits, but it is unverified by any oracle comparison; a float output path (slice 2) must bring a test that fails without it. The firmware reads one past an array in normal use (the grain window at its peak, the crossfade tables when the dry/wet ramp overshoots 1.0 by rounding, the freeze tail on every resume); the oracle's build pads those arrays so the C++ reads what the port's clamp reads, and it refuses memory sizes whose recording would overflow a grain's 16.16 phase (#199 review).
- **Upstream finding.** At `08460a69` the pitch-shifter / time-stretcher mode is silent: two commits each removed one of two duplicate `done_ = false;` lines in `clouds/dsp/window.h` and the merge `d1d8839` (2023-03-13) kept both removals, so no WSOLA window ever starts. ## Implementation note 2026-10-31: the Texture insert effect (#241, slice 2)

- **Device.** `texture` (`TextureFx` in `crates/dsp/src/plugins/texture.rs`, with `texture/path.rs` and `texture/resample.rs`), a built-in insert in the Delay group (not an offline process: it learns its input level and keeps a buffer). The name "Texture" is final. Émilie Gillet is credited under the panel, in the help entry `texture.credits`, in Help > About transit (the credit line and her notices from `crates/texture/LICENSE-THIRD-PARTY`), in `NOTICE` and in `ATTRIBUTION.md`.
- **Rate per quality.** Each quality runs firmware-exact at its codec rate (dirty tape 24 kHz, vintage digital 32 kHz, clean tape and digital 48 kHz). A 48 kHz session with digital or clean tape converts nothing: a test holds the device's output, 11 frames late, bit-equal to the crate's input stage and chain driven directly in 12-frame blocks.
- **Edge converters.** Streaming rational windowed-sinc converters from the family of the offline resampler (`offline::resample`: Kaiser window, beta 9, 32 zero crossings each side), the kernel tabulated at 512 steps per crossing with linear interpolation, cutting off at 0.91 of the lower Nyquist under a window whose length is the first design's (32 zero crossings of a 0.94 cutoff), so the latency table below is unchanged (see the fix-up bullet for the measured response). Timing is exact integer arithmetic on the rates' common tick, so the output does not depend on the host's block size (tested bit-equal for 64- and 512-frame blocks at 44.1 and 48 kHz, every quality, with parameter changes). The firmware's blocks are gathered across host blocks.
- **Latency.** The firmware block less one frame plus both converters' half lengths, padded to a whole number of session samples, reported per quality and rate (tests: the impulse delay of every path equals it; the dry path's at the device level too). In session samples: 44.1 kHz: dirty tape 137, clean tape 81, vintage digital 105, digital 81; 48 kHz: 149, 11, 115, 11; 88.2 kHz: 273, 148, 210, 148; 96 kHz: 297, 161, 229, 161. Dirty tape's wow and flutter (a modulated delay of 1 to about 172 codec samples after the chain) is the module's effect and is not compensated. A grain's pitch is the firmware's at 44.1, 48 and 96 kHz for every quality to 0.05 cent (E63's class: an absolute frequency, octave aliases refused); the firmware's 22.10 grain increment puts a +7 grain 0.30 cent under the tempered fifth at every rate.
- **Input stage on by default.** `Input Gain: Auto` runs the module's automatic gain (the firmware's processor expects its level); `Manual` maps `Input Level` (0 to 32 dB) onto the firmware's setting (1 to 255, a gain of `1 + 39·(s/255)⁴`). Session floats enter as the codec's 32-bit frames (full scale ±1, saturating). `Mono In` is the module's normalization: `Configure(media, mono)` and the right input copying the left.
- **Rebuild path (a deviation from the brief, for review).** The brief asked for the buffer rebuild outside the audio thread. A built-in receives parameter values only on the audio thread (no control-thread hook), and an asynchronous build would land the swap at a frame that depends on scheduling, so an offline render would not be deterministic. Instead the memory is allocated once, at construction, for the longest buffer (8 s: 3 MB), and `Texture::rebuild` rebuilds the chain in place to exactly what `Texture::new` builds (tested: same output and random state after a dirtied run, every quality, mono and stereo), deferring the lines' clears so the memory is filled once. It runs on the audio thread at the bottom of a 10 ms fade-out, then fades back in; measured informally at about 50 µs (release, this machine; a quality change's `Configure` about 100 µs). Quality and Mono In restart the same way (`Configure`, the codec rate's path, the input stage re-initialized keeping its learned gain). `reset` rebuilds too. A probe counts no allocation or free in the callback through every edit, a rebuild and a reset.
- **Controls.** Every knob with its attenuverter as a Random knob (the module's behavior with no CV patched), Density, Feedback, Dry/Wet, Reverb, Freeze, the SEED button (Seed held, Latch for the long press), the SEED input as `Trigger` with `Trig In` (patched), Quality, Length (4 to 8 s), Mono In, Mono Grains. Not exposed: the CV inputs (automation moves the knobs instead), the output gate setting (it turns the right output into a gate signal) and the Trim gesture.
- **Later.** The Pitch Shifter (#199 slice 2, named Time Stretcher) shares these edge converters (`plugins/resample.rs`, `plugins/codec_path.rs` since then). The instrument form (the synth, freeze and seed from MIDI) is slice 3 (the Texture Synth, see its note below).
- **Review fix-ups (2026-10-31).**
  - *Converter stopband.* The first design (cutoff 0.94 of the lower Nyquist) measured -0.29 dB at 0.89, only -26 dB at 0.985, and -90 dB from about 1.04 of the lower Nyquist: an input at 1.004 of it folded back at -43.6 dB (audible on Dirty Tape, whose Nyquist is 12 kHz). The cutoff is now 0.91 under the same Kaiser window (beta 9, the same half length, so every converter's length and the latency table stay as they were). Measured per down converter (96 to 48 kHz and 44.1 to 24 kHz, `resample.rs` tests): within 0.1 dB to 0.852 of the lower Nyquist, -3 dB at 0.896, -90.6 dB or lower at the Nyquist, and the worst alias of any input from 1.001 to 1.1 of it -91.1 dB. Content from 0.85 to 1.0 of a codec's Nyquist is rolled off (at Dirty Tape's 24 kHz, above about 10.2 kHz). Tests: tones at 1.004 and 1.02 of the lower Nyquist alias at or below -80 dB and 0.85 passes within 0.2 dB, on five down and three up pairs; the E63 pitch, latency, block-split and firmware-exact tests pass unchanged.
  - *Subnormals.* A resampled output, and the output during a restart's fade, is flushed to zero under 1e-25 (`util::flush`, a threshold compare). A steady equal-rate output is not touched, so the firmware-exact path stays a copy bit for bit. Before: 60 s of silence after a loud run put out 222 to 565 subnormal samples through the converters; now none (test).
  - *Restart cancel.* A setting that returns to the running value before the bottom of the fade cancels the restart: the fade turns round from its level and the recording stays (test: after the fade the output is the untouched device's, bit for bit).
  - *Span-only fill.* A rebuild or a `Configure` fills only the memory span the active buffer length uses (`DelayMemory::set_span`), so the default 4 s fills half of the 8 s memory. `Texture::new` allocates exactly its span, so the crate's output and the oracle nulls are unchanged; rebuild-equals-new is tested at 4, 6 and 8 s.
  - *Audio-thread rebuild cost (review measurements, release, before the span-only fill).* `Texture::rebuild` at 8 s: warm median 63 µs, max 84 µs; cold (cache thrashed) up to 683 µs. `Configure` over the 12 quality pairs: warm medians 90 to 106 µs; cold outliers up to 1.66 ms. A whole 64-frame block holding a restart: medians 60 to 120 µs on a quiet machine (a steady block costs 11 to 20 µs), 340 to 490 µs under memory contention. A Pi 5 (taken as 4x slower) would take 240 to 480 µs quiet, inside a 64-frame period at 48 kHz (1333 µs), and 1.4 to 2 ms loaded, which could overrun it. It stays on the audio thread for determinism: parameters reach a built-in only there, and a swap prepared off the thread would land at a frame that depends on scheduling, so an offline render would differ from run to run. The span-only fill halves the memory work at the default 4 s; automating Quality, Length or Mono In restarts the chain every change (a 20 ms dip each time; said in the help).
  - *Offline latency (#251).* The range render now follows reported latency per block: discard overlapping frames on growth, insert silence for gaps on shrinkage, and keep the requested length. The live compensation crossfade, restart fade and Dirty Tape's intentional wow/flutter remain. The exact splice and live-versus-bounce equality rule are in [ADR 0038's amendment](0038-inserts-read-the-tracks-note-stream.md#amendment-offline-latency-changes-251).
  - *Known limits, filed.* Frozen recordings are saved as plain float32 WAV files in Audio Files, at the quality's codec rate with the active mono/stereo span (#252). Clean Tape repeats each stored 24 kHz sample twice at its 48 kHz codec rate; the 4–8 s setting is a memory budget, so lower resolutions and mono retain their longer spans. The WAV restores the recording independently and renders deterministically across reopens. An optional versioned companion preserves grains, random state, effects and converter history for bit-exact continuation; a missing, invalid or unsupported companion restores the WAV with a continuation-not-restored report line. A control-thread loan through two bounded SPSC queues copies raw stored memory without allocation or locks at block boundaries; float conversion and WAV encoding happen on the control thread. Bypassed/inactive inserts service only Freeze and the capture loan, leaving other pending edits alone. Restoration validates the captured header independently of base parameters and rebuilds at that setup off-thread before graph publication; live parameters then apply normally. Frozen-media errors never refuse the session save. Missing or inconsistent WAV media, or an incompatible session rate, opens silent with the track and insert in the load report; a failed restore retains its reference until real recording resumes. Live Freeze, including automation and macros, decides whether a capture is saved. Autosave carries captured media into crash recovery. Without an audio callback capture is skipped with a notice, keeping stored media. Freeze off removes the reference on save; media remains under the existing immutable-media rule for backups. Auto input gain learned over silence lets a following loud burst out at about +12 dBFS until the peak protection catches it, as on the module (said in the Input Gain help).
  - *Presets and Seed.* Frozen Pad no longer sets Freeze (a fresh instance froze an empty buffer and stayed silent); a test renders every preset non-silent on a fresh instance. The Seed button senses drags, so its hold lasts until the pointer button comes up even when the pointer leaves the button (test).

## Implementation note 2026-11-01: the Texture Synth instrument (#241, slice 3)

- **What the firmware's synth is (the brief's reading corrected).** `beads/dsp/synth.cc` is not a source that fills the recording buffer: on the module it replaces the effect chain when no audio is patched (`beads.cc` switches after 10 s without input; not ported, the main loop's glue). It is a wavetable oscillator (`wavetable_voice.h`: TIME scans the 16 waves of a bank with a slow random walk, FEEDBACK picks one of 12 banks through a hysteresis quantizer, 25 ms crossfade) and wavetable grains (`wavetable_granular_player.h`: up to 32, seeded by the same trigger generator as the chain's grains, SIZE, SHAPE and PITCH with their randomness, pan and equal-power amplitude from the scheduler), mixed by DRY/WET (dry the oscillator at 0.5, wet the grains), then the limiters and the reverb. It runs at 48 kHz (`Synth::Init` hard-codes the rate; the quality only sets the resolution: 4-bit, a 16-bit oscillator with 6-bit grains, 7-bit, 16-bit). PITCH is the knob plus the CV (`p.pitch.base + cv`, after which the attenuverter is the grains' randomness). Freeze stops new grains, holds the sounding grains' envelopes (`WavetableGrain::Render` skips the envelope while frozen) and stops the oscillator's random walk. The grains read wavetables, so there is no buffer, no Length and nothing recorded; an audio input for the instrument is out of scope (#274 covers instrument audio inputs).
- **Device and name (final).** `texture_synth`, "Texture Synth", short "TexSyn", after the Resonator in the instrument picker (the Macro Oscillator stays `DEFAULT_INSTRUMENT`); `crates/dsp/src/plugins/texture_synth.rs` with `_params.rs`, `_state.rs` and `_tests.rs`. Émilie Gillet is credited under the panel, in `texture_synth.credits`, and in Help > About transit ("Texture and Texture Synth: a port of ..."); the vendored list is unchanged, so NOTICE and ATTRIBUTION are too.
- **Notes: the firmware's gate semantic.** The brief assumed no gate; the firmware has one. The instrument patches the SEED input with the notes: a key raises the SEED gate (and sets the PITCH CV to `key − 48` semitones over the oscillator's 130.81 Hz root, so MIDI 69 is 439.99 Hz, -0.04 cent), the gate stays high while any key is held, and the trigger generator does what it does with a gate on its input: below DENSITY 0.48 a regular train runs while the gate is high, the rising edge firing the first grain at once; between 0.48 and 0.52 each rising edge fires one grain; above 0.52 a random train runs while it is high; with the button latched the edges clock the divider. A note-off lowers the gate when no key is left (started grains play out). Monophonic in pitch, no voice allocator (the module is one voice with 32 grains). A note-on while the gate is high retriggers: the gate is low on the block's first frame and rises on the second, as a new edge on the jack would. Releasing the sounding key while others are held returns the pitch to the newest held key with no retrigger (mono legato as in Ableton's and Logic's synths). A note shorter than a block holds the gate for its block. The oscillator has no gate on the module (it plays at the last pitch for as long as DRY/WET passes it), so Dry/Wet defaults to 100% (grains only); the shaper's amp envelope gates it when on. The sustain pedal holds the shaper's envelopes only. CC 120 resets the synth in place (`Synth::reset`, allocation-free) with the converter and the shapers; CC 123 lowers the gate (the grains play out): the Resonator's rule.
- **Velocity.** The synth has no level or accent input (the grains' amplitude is the scheduler's `1/sqrt(n)`), and DENSITY's CV is a rate, not an accent, so velocity is a level outside the firmware: `level × (1 − Velocity × (1 − velocity))` from the note on, the step ramped linearly over the note's first 12-frame block; `Velocity` 50% by default; exactly the knob at full velocity or at 0%.
- **Freeze and Seed.** Parameters (`freeze`, `seed` held, `seed_latch`), so they automate and take the per-instance MIDI mapping like any parameter. Seed held is the button held (the gate high whatever the keys do); Latch is the button latched (the divider).
- **Rate, blocks and events.** The synth runs at 48 kHz in the module's 12-frame blocks (its codec block at 48 kHz), rendered as the output needs them, counted in output frames, so any host block size renders the same bits. An event takes effect at the first 12-frame block starting at or after its offset: at most 11 frames late, 0.23 ms at 48 kHz (the Macro Oscillator's rule; the Resonator's on its 24-frame block). The matrix and the shaper run once per block. The edge is the Resonator's (`resonator::edge`, the shared `plugins/resample.rs` up converter): latency in session samples 0 at 48 kHz, 35 at 22.05, 32 and 44.1 kHz, 65 at 88.2, 70 at 96, 129 at 176.4, 140 at 192 kHz (test: the impulse delay equals the reported latency at all eight rates).

The matrix gains three destination slots past Pan (`dst::EXTRA1` to `EXTRA3`, `NDST` 18); the Macro Oscillator's and the Resonator's choice lists stop at Pan, so their rows and renders are unchanged. Destinations: Pitch (24 semitones on the CV), Time, Size, Shape, Density (the four macro slots), Level, Cutoff, Resonance, Filter env amount, the LFO rates and amounts, Pan, Bank, Dry/Wet, Reverb; a control's knob is exact when no row targets it.
- **The frozen cloud saved (the #252 pattern).** The insert's machinery is recording-specific (a 9 MiB recording copied in chunks, setup and generation checks, a WAV beside the session), so none of its code applies and nothing moved; what is reused is the pattern and the crate's checkpoint encoding. - **Pitch (E63).** A 440 Hz sine shifted +12 semitones measures 880.0000 Hz (0.0000 cents) at 44.1, 48 and 96 kHz for every quality (the table's ratio for 12 is exactly 2 and the windows read at 2.0 in 16.16). Other intervals measure a few cents flat because each window splice lands on the correlator's search grid (1.25 to 2 samples): -12 st -0.63 to -0.81 cents, +7 st -2.2 to -2.7 cents, the firmware's behavior, within 0.2 cent of each other across session rates; the test holds +12 within 1 cent and the others within 5 cents and 0.5 cent of 48 kHz.
- **Controls.** Pitch (-24 to +24 semitones) with Fine (cents), Window (the WSOLA size), Position, Diffusion (DENSITY in this mode), Tone (TEXTURE in this mode: low-pass left of center, high-pass right), Feedback, Dry/Wet, Reverb, Freeze, Trigger (the rising edge of a held button, sampled once per firmware block, as the module's trigger input), Quality (the module's four), Input Level (-18 to +18 dB). Not exposed: stereo spread (this mode does not read it) and an automatic input gain (this firmware has none; the Texture's input stage comes from the other module). The firmware's crossfade and soft clipper leave a dry signal at 0.354 of its level (the equal-power table's 0.707 times the clipper's 0.5), so the device multiplies its output by 2√2 (+9.03 dB) and a dry signal leaves at its level; the clipper's ceiling then sits at +9 dBFS.
- **Restart and cost.** A quality change goes through the Texture's pattern: a 10 ms fade out, the firmware takes the quality at the bottom (its next block is silent while it clears the recording, as on the module), a 10 ms fade in; a quality returned inside the fade cancels it; before the first block after a reset it applies at once. Measured (release, this machine, 20 runs, informal): `Granular::reset` 3 µs median warm (it fills 184 KB); the whole 64-frame host block holding the firmware's reset 65 to 100 µs median, 135 µs max, against 16 to 26 µs for a steady block. Budgets: 1333 µs at 48 kHz, 667 µs at 96 kHz; a Pi 5 taken as 4x slower: 260 to 540 µs. The callback allocates nothing through edits, restarts and `reset` (`crates/dsp/tests/time_stretcher_alloc.rs`); a resampled or fading output is flushed of subnormals (60 s of silence after a loud run: none).
- **Tests at the device and engine level.** 64- and 512-frame host blocks bit-equal at 44.1, 48 and 96 kHz for every quality with parameter changes, freeze and a trigger; restart fade, cancel and at-once setup; reset equals fresh; holding the trigger fires once; mono strips; hostile input stays finite and under the ceiling. Through the engine: save and load round-trip the parameters and render the same bits; the live path (the realtime mix engine in 64- and 512-frame blocks) is the offline bounce at the plan's latency, bit for bit.
- **Credits.** The panel's credit line, the help entry `time_stretcher.credits`, Help > About transit (credit line and `crates/granular/LICENSE-THIRD-PARTY`), `NOTICE` and `ATTRIBUTION.md`. The vendored file list is unchanged.
- **Limits.** The recording is not session state (a session reopened with Freeze on is silent until the device hears input again, as #252 records for the Texture). The window splices make non-octave intervals a few cents flat (above). The correlator's timing is the harness's, not the module's. Automating Quality makes a 20 ms dip each change.

Porting found nothing else: the stretch mode nulled on the first full run.

## Implementation note 2026-10-31: the meta-modulator and the Cross Modulator insert (#200)

- **Source: option (c), a port from the firmware.** No usable Rust port derived from the firmware exists. crates.io has none. GitHub code search for the firmware's identifiers finds two Rust files: `ajkachnic/toby` (`src/modulator.rs`) carries no license (all rights reserved) and is a partial adaptation (the comparator commented out, the crossfade rewritten as linear); `tacogips/vactr` (`src/dsp/ported/warps.rs`, MIT) declares itself an architectural adaptation with no source-equivalent row. Neither is used. `transit-modulator` is transit's own port of `eurorack/warps/dsp` and `warps/resources.cc` at `08460a69` (the files last changed in `2a46873`, the author's name in the notices) and the stmlib helpers at `e3bd7c9c`, from her MIT C++ only, never from VCV's GPLv3 Audible Instruments. Émilie Gillet's MIT notices are its license chain (`crates/modulator/LICENSE-THIRD-PARTY`, `VENDOR.md`). Included: the two saturating input amplifiers, the internal oscillator, the six cross-modulation algorithms and their 6x converters, the vocoder (20-band filter bank, envelope followers, limiter). Excluded: the frequency shifter (the module's hidden mode: its quadrature transform and oscillator; not trivial, and nothing asks for it yet), the bypass, the drivers, the UI, the CV scaler and the main loop's normalization detector.
- **Rate.** The firmware runs at 96 kHz in the codec's 60-frame blocks (`modulator.Init(96000)`, `codec.Start(60)`); its pitch table, filter bank and converters assume it, and the 60-frame block takes the circular branch of its 6x down converter (the desktop harness's 96-frame blocks take another). The port runs at 96 kHz only, in whole 12-frame groups up to 60 (the vocoder's 3x and 4x decimators need them), and nulls there; the device converts at its edges with the Texture's converters, so a 96 kHz session converts nothing.
- **Gate.** All 432 sweep points (the external carrier and three oscillator shapes; every algorithm, morph, the vocoder crossfade and release; drive and note axes; ramps and jumps) null bit for bit, main and aux ([gates.md, Oracle null tests](../contributing/evidence/gates.md#oracle-null-tests)); the floor is `-inf`. The output is int16, so the flush to zero is not discriminated (the oracle without it moved no sample); it is kept, as in the family, for the internal state.
- **Defined on a build-time copy (`patches/all/0010`), followed by the port.** The crossfade reads `lut_xfade_in` and `lut_xfade_out` at a ramp that reaches 1.0 (one entry past the table, at a zero fraction) and can overshoot it by rounding; the fold reads `lut_bipolar_fold` from its middle at an index from the signals, which reaches one past its end at full scale and goes beyond either end once the amplifiers and the up converter push the signals over full scale. Both are clamped to their tables. The amplifiers' `level_`, `pre_gain_` and `post_gain_`, which `Init` never writes and the first block reads, start at zero as the module's global does.
- **Device.** `cross_modulator` (`CrossModulator` in `crates/dsp/src/plugins/modulator.rs`, with `modulator/path.rs`), a built-in insert in the Modulation group. Name: "Cross Modulator", because it says what the effect does (it cross-modulates two signals); "Meta Modulator" was the module's own tagline, too close to its branding. The algorithms are named by what they do (Crossfade, Cross-fold, Diode Ring, Digital Ring, XOR, Comparator, Vocoder). Émilie Gillet is credited under the panel, in the help entry `cross_modulator.credits`, in Help > About transit, in `NOTICE` and in `ATTRIBUTION.md`.
- **Inputs (the sidechain route).** The track is the modulator (input 2) and the key from the insert's key picker, the compressor's route ([ADR 0015](0015-io-routing-abstraction.md), section 4), is the carrier (input 1); with no key set the internal oscillator carries, as on the module with nothing patched in input 1 and the oscillator on. `Carrier: Oscillator` keeps the oscillator with a key set, the key then modulating its phase or frequency as input 1 does. `Swap Inputs` exchanges the roles when keyed. Convention: Ableton's Vocoder takes the track as the modulator and an external carrier from its sidechain; the swap covers Logic's habit of vocoding the synth track from a voice key. A stereo track runs two firmware instances (left with the key's left, right with its right; the right's noise from its own seed).
- **The codec's float scale.** The device runs the firmware between its codec's conversions (`Modulator::process_float`): session floats go in as the codec's scale (full scale = full-scale int16) and the main output comes back before its int16 conversion, so nothing is quantized or clipped at the edges. On the int16 grid the output is the oracle's bit for bit (tests: every routing at 96 kHz; through a session, the keyed input in the serial render and the task graph).
- **Latency.** The block less one frame plus both converters' half lengths, padded to a whole number of session samples, constant per session rate: 32 kHz 89, 44.1 kHz 97, 48 kHz 99, 88.2 kHz 125, 96 kHz 59, 192 kHz 257 samples (tests: the impulse delay of the path equals it at every rate; the dry path of `Dry/Wet` is delayed to match). The oscillator's pitch through the converters equals the firmware's own frequency to 0.05 cent at 44.1, 48 and 96 kHz (measured: 0.0000 cent at 110, 440 and 1760 Hz).
- **Controls.** Algorithm (0 to 8, continuous, the firmware's 0 to 1 times 8; the knob is linear where the module's pot has a curve), Timbre, Carrier Level and Modulator Level (the module's level knobs: the drive is the level squared), Carrier (Auto, Oscillator), Osc Shape, Osc Frequency (65 Hz to 2.09 kHz, the module's knob range), Swap Inputs, and transit's Dry/Wet and Output. Presets Ring Bell, Vocoder and XOR Grit. No rebuild path: every control applies at the next firmware block.
- **Upstream findings (for the maintainer to post).** (1) `SaturatingAmplifier::Init` (`warps/dsp/modulator.h`) leaves `level_`, `pre_gain_` and `post_gain_` unset and the first `Process` reads them: harmless for the module's static global, indeterminate for any other instance. (2) `Xmod<ALGORITHM_XFADE>` reads `lut_xfade_in`/`lut_xfade_out` one past their 257 entries at a parameter of 1.0 (the knob's top), and `Xmod<ALGORITHM_FOLD>` reads `lut_bipolar_fold` one past its end at full-scale inputs and further for inputs the amplifiers drive over full scale. (3) `Modulator::Init` leaves `previous_parameters_.phase_shift` unset, which the frequency shifter's interpolator reads on its first block. (4) `EnvelopeFollower::freeze_` is declared `float` and holds a `bool` (harmless). (5) `FilterBank::Analyze` and `Synthesize` silently leave bands unwritten for blocks that are not a multiple of 12 frames (the module's 60 always is).

## Implementation note 2026-10-31: the random sampler and the Random Sequencer MIDI effect (#202, slice 1)

- **License.** The eurorack README says "Code (AVR projects): GPL3.0" and "Code (STM32F projects): MIT license". The topographic drum sequencer (`grids/`) is an AVR project under GPL 3.0 and cannot be vendored or ported under this ADR; it is out of #202. The random sampler (`marbles/`) is an STM32 project, and every one of its 28 vendored files carries Émilie Gillet's MIT notice (2015).
- **Source: option (c), a port from the firmware.** crates.io has no port. GitHub code search finds one Rust derivative, inside `dexterlabs1/openpatch` (`crates/openpatch-core/src/recall_random/`, MIT, two weeks old): a module of an application rather than a crate, with declared deviations from the firmware and no oracle evidence; not used. `transit-random-sequencer` is transit's own port of `eurorack/marbles/random`, `marbles/ramp`, `marbles/resources.cc` and `marbles/scale_recorder.h` at `08460a69` (last changed in `db1566f`, 2023-01-08) and the stmlib helpers at `e3bd7c9c`, from her MIT C++ only, never from VCV's GPLv3 Audible Instruments. Her notices are its license chain (`crates/random-sequencer/LICENSE-THIRD-PARTY`, `VENDOR.md`). Included: the t generator (seven models, jitter, gate ramps), the X and Y generators with the output channels' lag processor and quantizer, deja vu, the clock recovery for a patched clock, the scale recorder, the main loop's dead band, loop lengths and Y divisions, and the six preset scales. Excluded: the drivers, the UI, the CV reader, the calibration and settings storage, the clock self-patching detector, the note filter (it filters the CV input, which a host does not have) and the unused discrete-distribution quantizer.
- **Oracle.** `cpp/sequencer_oracle.cc` drives the generators as `marbles.cc`'s `Process` does, at 32 kHz in 5-frame blocks, the knobs given directly (no CV reader), each instance on its own seeded random generator (the hardware generator never fills the stream, here or in the port). `marbles.cc` and `settings.cc` are vendored for reference only; the wrapper's copies of their tables are checked value for value against them. The fixed sweep has 173 points (every model at five biases, jitter, gate lengths, rates and ranges, deja vu across its dead band and loop lengths, the X distribution, steps, every scale, control modes and ranges, the input-sampling mode, the Y channel, every clock routing including a patched clock steady, swung, paused and restarted and at audio rate, explicit resets, a loaded scale, motion). The floor is exact in one process and across two.
- **Gate.** All 173 points null bit for bit, every frame's three gates and four voltages; blocks of 1 to 4 frames and one-minute deja vu runs too ([gates.md, Oracle null tests](../contributing/evidence/gates.md#oracle-null-tests)). A one-rounding change to the beta sample's interpolation fails 9 of the 173. The port flushes to zero as the family does; the sweep without the oracle's flush moved no value, so the flush is kept for the smoothers that can reach the subnormal range, not discriminated.
- **Defined on a build-time copy (`patches/all/0011`), followed by the port.** A random component of exactly 1.0 (the top 128 words over 2^32) makes a pulse width's beta sample read one past the 387-entry inverse-cdf table at a nonzero fraction, and the drum and clusters models pick one past their pattern lists at a bias end; a channel phase of exactly 1.0 makes the lag processor read `lut_raised_cosine[257]`. Each index is clamped. The Y channel's ramp divider leaves `reset_at_next_pulse_` unset and its first wrap reads it; it starts at zero as the module's global does.
- **The MIDI effect.** `random_sequencer` ("Random Sequencer": it names what it does; no module name), a built-in MIDI effect in the slot of [ADR 0036](0036-midi-effect-slot.md). Convention: Ableton's MIDI effects (Arpeggiator, Random) and Logic's (Arpeggiator, Randomizer) sit before the instrument and run on the transport clock; so does this one.
  - **Clock mapping.** The firmware follows a patched clock at a division its rate knob picks (`p/q` from 1/4 to 4, by the range times a quarter or four). The effect's Rate offers exactly those 21 divisions with the beat as the clock, by note value: 4/1, 3/1, 2/1, 1/1., 1/1, 1/2., 1/1T, 1/2, 1/4., 1/2T, 1/4, 1/8., 1/4T, 1/8, 1/16., 1/8T, 1/16, 1/16T, 1/32, 1/32T, 1/64. Ticks fall on the division's grid from beat 0; the firmware's recovered-ramp tracking is not used (a host knows the beat exactly). Jitter bends each tick by the firmware's multiplier and its pull back toward the straight clock (the phase difference measured against the grid); with no jitter every tick is on the grid. Every decision at a tick is the ported code (the t generator's vector, multiplier and gate ramps; the X and Y draws); the gates' rises and falls are computed from the ramps' slopes in beats, and times become sample offsets only in the block that plays them, so a tempo change keeps the grid and the notes are identical at 37, 64 and 512-frame blocks (tests). A play start, a locate or a loop runs the firmware's reset at the grid point at or after the position.
  - **Notes.** Gate 1 plays X1, the clock (t2, high for half a tick) X2, gate 2 X3 (`Play`). A note lasts while its gate is high: the note length is the firmware's gate width (`Gate Length` its mean, `Length Random` its spread), including the firmware's longer gate before a tick with no pulse; a pulse that starts while the gate is still high retriggers. A key is the quantized voltage at a semitone per twelfth of a volt above `Root` in `Octave` (unquantized voltages, below the steps' center, round to the nearest semitone), folded into 0 to 127; the pelog and raga scales' microtonal degrees round to semitones. Scales: the firmware's six and Chromatic (every semitone at every steps level). Steps spans the firmware's quantizing half (its smoothing half glides a voltage, which a note cannot). A note on a key another voice holds ends that voice's note first.
  - **Velocity.** The Y channel's voltage over its 0 to 5 V range, 1 to 127, drawn at every tick: `Velocity` is its bias, `Dynamics` its spread (its divider fixed at every tick, its steps at none).
  - **Deja vu.** `Deja Vu` is the module's knob (random at 0, the loop exact across its 47 to 53% dead band, shuffled above), `Loop Length` the module's 12 lengths, `Deja Vu On` the sections (gates and pitch, gates, pitch), and `Freeze` the module's locked state (the loop exact whatever the knob).
  - **Seed.** `Seed` picks the sequence; `Latch` (on by default) restarts it from the seed at every start, locate and loop, the hold the Texture's latch gives its seed; off, the sequence runs on across passes. The scale recorder is ported and nulled but not yet wired as "Learn" (a follow-up: it needs the effect's state saved in the session).
  - **Input.** Played note-ons are swallowed unless `Thru` is on; releases and every other message pass.
  - Émilie Gillet is credited under the effect's controls, in the help entry `random_sequencer.credits`, in Help > About transit, in `NOTICE` and in `ATTRIBUTION.md`. Presets Drifting Melody, Locked Loop and Sparse Random Bass.
- **Upstream findings (for the maintainer to post).** (1) `RampDivider::Init` (`marbles/ramp/ramp_divider.h`) leaves `reset_at_next_pulse_` unset and the first wrap of `Process` reads it. (2) `BetaDistributionSample` (`marbles/random/distributions.h`) reads one past the inverse-cdf table at a nonzero fraction when its uniform input is 1.0, which `RandomSequence::NextVector` produces for the top 128 seed words; `GenerateDrums` and the clusters branch of `ConfigureSlaveRamps` index one past `drum_patterns` and `divider_patterns` for such a component at a bias of 0 or 1. (3) `LagProcessor::Process` reads `lut_raised_cosine[257]` (at a zero fraction) when the phase is exactly 1.0, which a Bernoulli slave ramp's held output and the master ramp (it wraps only above 1.0) both reach. (4) `RandomSequence::NextValue` and `RewriteValue` take any loop value of 1.0 or more for a deterministic (shift-register) value; `GetFloat` returns exactly 1.0 for the top 128 words, so such a random draw becomes 0.0. (5) `SlaveRamp::pulse_length_` is an `int` that grows every sample while a Bernoulli ramp never restarts and overflows after about 18 hours at 32 kHz (undefined; it only matters at a zero pulse width).

## Decision note 2026-10-30: the Macro Oscillator is the default instrument, the Subtractive Synth is removed (#234)

With polyphony in (#196), a new instrument track carries the Macro Oscillator (default model, 8 voices) and the built-in Subtractive Synth is removed outright: its code, plug-in id (`subtractive_synth`), editor panel, factory presets, help and README line. transit is alpha software, so there is no compatibility shim for the synth itself; the one rule below keeps old sessions opening. The Sampler is unchanged; the Drum Synth went with the inherited effects in v0.6.0 ([ADR 0040](0040-inherited-built-in-effects-retired-in-stages.md)), which applies the same load rule to its slot.

Convention: Logic opens a new software-instrument track with its default patch loaded and Ableton leaves a MIDI track empty; we keep Logic's "ready to play" default, which is what the Subtractive Synth gave until now. Every path that creates an instrument track (`track.new`, the Add Instrument Track menu and shortcut, MIDI file import, the demo) uses `transit_model::DEFAULT_INSTRUMENT`.

**Substitution rule on load.** An instrument slot that names `subtractive_synth` becomes a Macro Oscillator with defaults when the session loads (`transit_model::legacy_synth::retire_subtractive_synth`, called by `Session::from_json`, so every open path, recovery and session import apply it):

- the old synth's parameters and preset name are dropped, since they mean nothing to the new instrument; the slot's bypass and active flags carry over; the new instrument gets `level` = -19.5 dB instead of its -6 dB default, because the Macro Oscillator at its defaults plays about 13.5 dB louder than the old synth did (derivation below);
- the session's MIDI mappings, the track's automation lanes and the rack macro targets that addressed the old instrument's parameters (`plugin:instrument:<id>`) are dropped; mappings and lanes on inserts, and everything that addresses the slot as a slot (rack membership, zones, routing, volume, pan), keep working;
- the load report gets one line per track that lost something, then the status line "N track(s) used the retired Subtractive Synth and now carry the Macro Oscillator";
- the session opens as modified (the engine keeps the file's own content as the saved state), so the user sees the substitution on save; a saved session no longer names the old id and opens clean.

The corpus keeps the sessions released builds wrote with the old synth (`crates/model/tests/corpus`); `a_release_session_with_the_old_synth_opens_with_a_macro_oscillator_and_one_report` loads them, and the lossless round-trip tests read them with the id swapped. MIDI-mapping profiles are app-level, not session data, and are not rewritten: a profile mapping to an old instrument parameter finds no such parameter and does nothing.

**Level derivation.** The instrument plan-parity golden (`crates/mix/tests/golden/plan_parity/instrument.f32`) holds the same session rendered with the old synth and with the Macro Oscillator at its defaults: peak 0.0569 and 0.2680, a difference of 20 log10(0.0569 / 0.2680) = -13.46 dB (the held-notes golden: 0.271 and 1.346, -13.9 dB). The default level of -6 dB minus 13.5 dB gives -19.5 dB (`SUBSTITUTE_LEVEL_DB`), which lands a substituted track within about 2 dB of its old peak loudness on that golden. RMS differs more (-18 dB on that golden) because the timbres differ, so loudness is matched by peak, and a patch change will still sound different.

**Status line coverage.** Every open path applies the substitution, but only a normal open and open from bytes show the status line. Crash recovery drops the temporary engine's messages and session-data import shows only the video note; both predate this change.

The event queue and ADSR that lived in the synth's file stay, as `crates/dsp/src/plugins/instrument_queue.rs`: the Drum Synth and the Sampler use the queue and the Sampler the ADSR; the Macro Oscillator uses only the queue's two capacity constants (`MAX_EVENTS`, `RELEASE_RESERVE`), not the queue.
