# ADR 0015: I/O routing abstraction: a device channel map, named paths, one route graph

- **Status:** accepted 2026-10-21 (direction pre-approved by the project owner; refutation review round 1 resolved)
- **Date:** 2026-10-21
- **Implementation:** Slice 0 and slices (a) to (e) landed, including (d) hardware inserts f1add1e+074baac. The master hardware repair (#322) and the live cue flag landed as the prerequisites of (f). Slice (f) Low Latency mode remains proposed by the 2026-11-05 amendment below.
- **Reopen when:** a slice's gate proves unmeasurable on the reference machine; or upstream SoundCraft lands its own multi-output or sidechain model that we should converge with; or the TASCAM Model 12 shows that device channel counts differ between input and output (or between USB modes) enough that one channel-map shape cannot describe both; or dependency layers for key edges prove too costly in slice (c) (fallback in section 4). WASAPI shared mode exposing one channel count is a stated limit, not a reopen trigger (section 1).

## Context

The project owner asked for that layer to be abstracted to support large custom routing and mixing configurations. Today transit opens output channels 1 and 2 only, and "Out 3-4" goes nowhere. Verified against `soundcraft` branch `transit`, head 6b81c4b (code paths relative to `crates/`):

- **The stream width follows the main bus, not the device.** `Player::prepare`/open asks for `main_channels(&session)` channels (`playback/src/player/device.rs:198`; `LegacyPlayer::open`, `playback/src/lib.rs:774`). `main_channels` is the main format's channel count clamped to 2..=16 (`mix/src/lib.rs:108`). `open_device` accepts only configurations with `2 <= channels <= want_ch` (`lib.rs:1343`, `1359`); when none matches it falls back to `default_output_config()` (`lib.rs:1376`). On ASIO, cpal lists every width 1..=outs per rate, so a stereo session on the Model 12 matches the 2-channel configuration and opens 2 channels; the default-config fallback bites on WASAPI, where only the mix format is listed (cpal `host/wasapi/device.rs:360-465`, `host/asio/device.rs:97-129`). Either way the other outputs never open. The callback writes main channel k to device channel k and zeroes the rest (`player/audio.rs:603-646`, clamps at 633, 636, 640); a main wider than the device is folded to stereo (`audio.rs:625`, `fold_gains` at `lib.rs:1219`).
- **Hardware routes are input-only, and by string.** `Route` is `None | Main | Bus(BusId) | Hardware(String)` (`model/src/mixer.rs:413`). The mix renders `Route::Hardware` only for monitoring an audio track's input, parsing digits out of a label like "In 1-2" (`mix/src/lib.rs:1824-1828`). `route_into` drops any output that is not `Main` or `Bus` (`lib.rs:1774-1781`); sends to anything but a bus are skipped (`lib.rs:1697`, `1735`). `track.mixer.output = Route::Hardware("Out 3-4")` is accepted from a file and silent. Today's `track.route` command turns an unknown output string into a new bus and maps "out 1-2" to Main (`engine/src/cmd/track.rs:818-838`; UI `ui-studio/src/mixer.rs:410`).
- **`OutputPath` exists; `InputPath` does not.** `OutputPath { name, first_channel, format }` (`model/src/mixer.rs:404`) lives in `Session::outputs` (`model/src/session.rs:317`, no `serde(default)`), seeded with "Out 1-2" (`session.rs:358`). Commands add, edit and remove paths (`engine/src/cmd/setup_more.rs:270-289`). Nothing reads it except `outputs.first().format` as the main format (`mixer.rs:583`, `cmd/surround.rs:105-120`) and the label for `Route::Main` in the UI (`ui-egui/src/mix_window.rs:136`). A 5.1 session stores its format only there.
- **Settings are per machine, but thin.** `AudioConfig { system, output, input, sample_rate, buffer_size }` (`playback/src/devices.rs:27`) lives in `UiState.audio` (`ui-studio/src/lib.rs:54`), saved to `ui.json` in the folder `TRANSIT_CONFIG_DIR` overrides (`apps/transit/src/config.rs`). `DeviceInfo.max_channels` (`devices.rs:44`) is shown but not used to open anything.
- **Input reaches the mix as a flat ring, and recording parses the same label.** The capture stream already opens the configuration with the most channels, uncapped (`playback/src/record.rs:292-306`, `Reverse(c.channels())`); the plan bridge copies it into `input_storage` (`playback/src/plan_bridge.rs:122-165`) and the mix sees `LiveInput.input` (`mix/src/lib.rs:1795`). Monitoring picks `(first + k) % n_in` (`lib.rs:1827-1836`) and recording does the same label parse and wrap (`engine/src/io.rs:1485-1489`, `plan_takes`), so a missing channel wraps silently in both.
- **The route graph, PDC and L22 know three edge kinds.** `EdgeKind` is `Output | Send { slot, pre_fader } | Input` (`model/src/route_graph.rs:36`); hardware and none are not edges (`route_graph.rs:11-12`). Edit-time refusal is `would_create_cycle_all` (`route_graph.rs:667`, from `engine/src/cmd/track.rs:866`); load-time loops are cut by `RouteScratch::solve`, only at the `Input` edge into a component's first track (`route_graph.rs:386-399`), and `dropped` reports only track-to-bus edges (`462-467`); `reserve` sizes edges as sends + 2 per track (`203-206`). PDC is two passes: `pdc_visit` (`mix/src/lib.rs:1643`) records each strip's output latency and each bus's arrival (`main_arrival`, `1659`); `route_into` delays each edge by the summing point's arrival minus the strip's own (`1683-1722`); `path_need_with` (`2594`) sizes the delay lines. Engine latency is `main_arrival + lmax_m` (`1525`) plus master-insert latency (`1498-1507`); delay is clamped at `MAX_LATENCY` (`507`). All of this sees only `Main` and `Bus`.
- **Render order has no track-to-track dependency.** Every non-aux strip runs its whole insert chain in one parallel phase before any routing (`mix/src/lib.rs:1451-1480`, `run_strips` `2486-2501`; plan renderer the same, `mix/src/active.rs:392-405`). `process_strip` gets `&busses` read-only and one `&mut Strip`; the delay lines `tap`/`tap_pre` are written later in `route_into`. `Layering.depth` (`route_graph.rs:100`) orders routing and the aux phase only. "Pre" means after inserts, before the fader (`lib.rs:2013-2018`); `strip.pre` is filled only when a pre-fader send exists (`1975-1981`).
- **Sidechain is not hosted.** VST3 aux buses are inactive (`vst3-host/src/lib.rs:39`); `Plugin::process(&mut self, io: &mut [Vec<f32>], frames)` is one in-place buffer (`dsp/src/lib.rs:223`); the CLAP host binds only the main pair, with bus layout fixed at `activate` (`clap-host/src/plugin.rs:114-130`). The compressor has a sidechain high-pass (`dsp/src/plugins/dynamics.rs:58`) but no key input.
- **Routing changes already travel one safe path.** A control-side compiler builds a `PreparedPlan` (`mix/src/plan.rs:233`) from a `Session` (`mix/src/compile.rs:263`) for a `RenderTarget { device, sample_rate, max_block }` (`plan.rs:55-60`, no channel count). `PlanEnvelope`s go through the bounded publication queue (`playback/src/publication.rs`, `plan_bridge.rs:252-279`); the audio thread adopts at most one per callback at a drained boundary (`active.rs:214`, `Audio::service`, `plan_bridge.rs:524-531`). `DeviceGeneration` means a new device or rate is a new engine (`plan.rs:46-48`). Callback allocation is gated (`mix/tests/plan_alloc_probe.rs`).
- **Offline render is the legacy renderer.** `LegacyPlayer` (`playback/src/lib.rs:641`) is `doc(hidden)` and used only by playback tests; the app's `Player` drives the plan renderer (`MixEngine::render_active`, `active.rs:350`). But `MixEngine::render` (`mix/src/lib.rs:1426`) is the only offline path: `RangeRender::render` (`3480-3485`), `engine/src/io.rs:503-612`, `engine/src/cmd/{mix,instrument,sampler,surround}.rs`, `engine/tests/bounce.rs`, and it is the oracle of `mix/tests/plan_parity.rs`.
- **Discrepancies with the problem statement.** (1) `MAX_CHANNELS` is 16 in the mix (`mix/src/lib.rs:105`) and in `MeterBank`/`Buffers.fold` (`plan_bridge.rs:27`, `125`), 64 in `dsp` and both hosts (`dsp/src/util.rs:14`, `vst3-host/src/gate.rs:12`); 16 binds a path or bus. (2) The output restriction is the `<= want_ch` filter, not a literal "channels 1-2" pick. (3) The path model is per session, not per machine. (4) The `Route::Hardware` label is treated as a channel number, so an input rename silently changes which channel is heard.

Test hardware: TASCAM Model 12 (about 10 outputs and 12 inputs to the host; channel counts may vary with USB mode) and a Focusrite Scarlett 2i2 (2 and 2). Backends: WASAPI and ASIO on Windows, CoreAudio, ALSA, through CPAL in `crates/playback` (pin `derekmwright/cpal`).

## Decision

### 1. Device channel map, with named paths per machine
1. **Open every channel the device offers, up to a cap of 32 outputs and 32 inputs.** The cap is a separate constant, `MAX_DEVICE_CHANNELS = 32`; the 16-channel path/bus width (`MAX_CHANNELS`) is not widened. Meters (`MeterBank.peaks`) and `Buffers.fold` are sized from the `IoMap` (or the 32 cap), not 16. The cap is new only for inputs, which already open at their maximum count uncapped; wider devices open the first 32 and say so in Audio Devices. The output stream is opened at the device's channel count, the `<= want_ch` filter is removed, and selection prefers the highest channel count at the chosen rate and format. **Stated limit:** WASAPI shared mode lists only the system mix-format channel count, so on Windows multichannel means ASIO; Audio Devices says how many channels the current system offers.
2. **A path is a name, a width and a channel set.** `IoPath { name, direction, channels: Vec<u16>, format: ChannelFormat }`, width 1 to `MAX_CHANNELS` (16), `channels` an explicit list so a path may be non-contiguous. `OutputPath` becomes the output half; `InputPath` is added. Defaults when a device opens: "Out 1-2" stereo plus one stereo path per remaining pair, "In 1" mono per input plus stereo pairs. The generated names equal today's labels exactly ("In 1", "In 1-2", "Out 3-4") so existing sessions keep their meaning.
3. **Paths are per machine, and reach the engine as an `IoMap`.** `IoMap { device identity, opened input/output channel counts, named path table, Main's target path }` is loaded by the app from `ui.json` (beside `AudioConfig`; keyed on audio system plus device name, with the channel count stored inside it, so one device in two USB modes is one entry) and handed to the engine with a `setup.io` command. `PlanCompiler::compile`, `Buffers::prepare` and `Player::prepare` take the `IoMap`; `RenderTarget` gains the opened output and input channel counts. Headless and automation (MCP, engine tests) build a default `IoMap` from the device, Main on its first two channels. The path commands (`create_output`, `rename_output`, `delete_output`) edit the `IoMap` the engine holds and the host persists, so they stay scriptable and undoable. **`Session::outputs` stays, in the file, with its current shape, through slices (a) and (b):** it remains the source of `main_format()` and the seed for a first default table, so a 5.1 session never silently becomes stereo (a build that dropped the field would load old files with no error, `mixer.rs:585`). Retiring it needs a versioned migration (`FORMAT_VERSION`, `session.rs:342`; `Session::from_json` has no migration hook today) and its own ADR.
4. **Assignments are per session, by path name.** `Route::Hardware(String)` stays the on-disk variant and means "the I/O path with this name" for inputs and outputs. Names are unique across buses and paths (bus and path share one namespace for `track.route`); `parse_route` resolves path table first, then bus, and creates a bus only on explicit request. On a load collision the bus wins and the route is flagged. Monitoring and recording resolve inputs through one function (`engine/src/io.rs:1485` joins `mix/src/lib.rs:1827`); a missing input path refuses to record with a message and never records a wrong channel.
5. **Resolution when a name is missing on this machine.** An output route to a missing path renders to a **flagged silent sink**: muted, shown in the UI and on load, the session not rewritten. A cue or click mix never lands on the PA. Only the Main path itself falls back to device channels 1-2. A missing input falls back to the first input path of the same width, else silence with a flag. The session keeps the original name, so the right machine restores the routing. Fold or fan-out of widths follows `build_matrix` (`mix/src/lib.rs:3207`). **Bounce is machine-independent:** it renders sinks logically, tracks routed to a named path are excluded from the main bounce, and stems are slice (e).

### 2. Routing matrix
Every track, bus and send may target `Main`, any `Bus`, or any output path; today's default (`Main`) is unchanged. A track's output goes to one target, its sends to as many as it has slots, so main plus cue mixes plus stems are a track output plus sends. The mix keeps one accumulation buffer per device channel (preallocated at the cap) and every path sums into its channel set. Paths overlapping on a device channel sum, with a warning on each ("Out 3-4 shares channel 3 with Headphones"). Metering and clipping apply per device channel after the sum, with the existing clamps (`audio.rs:633, 636, 640`). The device-frame layout travels with `Buffers` (as `fold` does), so render-ahead blocks keep their old layout across a path edit. There is no full matrix-mixer UI (see Alternatives).

### 3. Main as one path among paths
The main mix remains the primary output and still sets the main format (`Session::main_format`, `mixer.rs:583`). Which path Main plays on is stored per machine in the `IoMap` (default "Out 1-2"), which also answers what `Route::Main` shows in the UI (`mix_window.rs:136`).

### 4. Sidechain key inputs are edges in the route graph
An insert gets an optional key: `Insert.key: Option<KeySource>` with `#[serde(default, skip_serializing_if = "Option::is_none")]` like its sibling fields (`mixer.rs:428-443`), so old sessions load. `KeySource { from: KeyFrom, tap: Pre | Post }`, `KeyFrom { Track(TrackId), Bus(BusId) }` (`Route` cannot name a track). *As built:* there is no `KeyFrom::Send`; sends are not key sources, and a key from a track reads that track's pre- or post-fader tap directly. The key belongs to the slot and moves with it on reorder, copy and presets. `EdgeKind` gains `Key { slot, pre_fader }`.

**Execution rule (dependency layering).** A strip whose insert has a key from another strip renders in a later layer than its key source: `Layering` extends from routing edges to key edges, and phase 1 runs as one `run_strips` call per layer. `process_strip` gains a read-only key view (the source strip's tap or pre buffer, written when its layer finishes), a borrow change that is safe because layers are disjoint. Kick-to-bass must work. A bus key reaches only a strip rendered after the bus fills (an aux). A key cycle is refused by L22 like any loop. If layering proves too costly in slice (c), the fallback is a one-block-delayed key with the delay counted in PDC; "aux-only keys" is rejected as a product limit.

**Loops and sizing.** The load-time cut in `RouteScratch::solve` assumed every loop holds an `Input` edge; a two-track mutual key holds none. The cut rule, `dropped` and `reserve` (count insert slots) change, with a test loading a two-track mutual key from a file; edit-time refusal gains `RouteChange::Key`.

**Delivery and alignment.** The mix writes the key tap into a preallocated per-strip key buffer and passes it through `Plugin::process_with_key(&mut self, io, key: &[Vec<f32>], frames)`, default ignoring the key. Alignment point: the keyed slot's input (inserts before it may be latent, `process_strip` accumulates latency per insert, `lib.rs:1928-1947`). A late key (key latency above the keyed signal's) delays the keyed strip's input through a per-strip pre-slot delay line sized at compile and counted in `strip.latency` and PDC; an early key delays only the key. A Pre tap counts as a consumer for `strip.pre`, `tap_pre` and `path_need_with`. Channel mapping uses `build_matrix` (mono kick into a stereo aux bus).

**Hosts.** The VST3 host activates the aux bus and the CLAP host the sidechain port at instance creation whenever the plug-in declares one, and feeds silence (silence flag) when unrouted, so key edits are ordinary plan changes and never touch a live instance. `run_insert`'s suspend logic (`lib.rs:2081-2113`) considers the key as well as the main input, so a silent main with a loud key does not sleep a ducker. Built-in compressor and gate read the key in place of their own input when set. Implementation is slice (c).

### 5. Hardware inserts
A hardware insert is a send to an output path plus a return from an input path: a sibling `Option<HardwareInsert { send, ret }>` on `Insert` (`Insert` is a struct, `mixer.rs:425`), by path name. **Duplex only:** it needs input and output on one clock, which is ASIO on Windows (`player/device.rs:200-232`); on other backends the drift invalidates a fixed measured latency, so the insert is unavailable and flagged. The return for block N arrives in a later callback: the slot is a send, a FIFO of the measured round-trip length, and a read from the input ring, and `latency()` equals that length (the measured value covers the blocks of delay). A ping measurement writes an impulse on the send path, finds it on the return and stores `{ send, return, device identity, rate, buffer, frames }` per machine. No measurement means zero latency and a flag. A missing path bypasses the insert dry, flagged. Offline render is dry bypass with a flag. Implementation is slice (d).

*As built (slice d):* the implementation uses no in-slot FIFO, because the capture ring already delivers the return one round trip late. The loop check is edit-time plus open-time disabling (an offending insert becomes `Disabled` and runs dry), not a graph edge.

### 6. PDC and L22 across all edge kinds
Main and ordinary output paths are padded to one shared device latency **L = max(Main arrival + M, maximum other sink arrival)**, where M is the running master-chain latency (`crates/mix/src/tail.rs::fold_latency`). Main's pre-master alignment target is L - M; direct output paths do not pass through the master. For Main arrival 0, M = 100 and direct-output arrival 300 frames, L is 300, not 400. A path fed only by a zero-latency track is delayed to L, so stems and cues align with Main sample for sample. Hardware sends themselves flush unaligned: their measured round trip already covers the send/return delay (section 5, as built). `routing.rs::path_need` (formerly `path_need_with`) computes a conservative capacity bound, which can exceed rendered L; it is not the latency readout. The existing `MAX_LATENCY` clamp is unchanged. One stated exception: a path declared "live" (a performer's headphone cue) may opt out of sink padding, off by default; this declaration is not implemented on this base and is a prerequisite specified in amendment rule 4. Sidechain edges align at the keyed slot input (section 4); hardware insert latency counts through `latency()`. `route_graph`, `pdc_visit`, `route_into`, `path_need_with` and `RouteScratch` change together per slice. New `plan_parity` cases for sinks and keys compare against hand-computed golden outputs, not the legacy renderer. Outputs to paths are not loopable edges (sinks have no readers); only key edges add cycles. The offline renderer follows chain latency changes per block; see the amendment in ADR 0038 (#251).

**Low Latency mode (2026-11-05 amendment).** During live playback, temporarily bypass the selected high-latency audio inserts on armed/monitored tracks, their downstream buses and the master. Recompute L from that effective bypassed plan; all other paths keep full compensation to the resulting L. This is separate from a live cue's opt-out: the mode removes insert latency, and a cue declared live still skips its sink padding. Neither switch changes the other's rule. Offline rendering ignores the mode.

### 7. Realtime and publication

Low Latency mode adds a control-thread compile input: the set of insert uids to bypass for rendering (amendment below). It travels with `PreparedPlan`, published and adopted like any bypass plan; the audio thread never computes the set or edits session flags.

Path tables, key sources and the channel map reach the audio thread inside `PreparedPlan` through the bounded queue and the single adoption per callback. Accumulation buffers, key buffers, pre-slot delay lines and sink scratch are allocated by the compiler from the `RenderTarget` and `IoMap` and move with the existing cell moves; `RouteScratch::reserve` grows. **Only a device or opened-channel-count change is a reopen** (`DeviceGeneration` bump). Path and route edits are structural plan changes adopted at a drained boundary, never a stream stop, and must not swap a still-audible output buffer (`Audio::service`). `plan_alloc_probe` gains each new route kind. No `unsafe` is added (ADR 0013).

## Implementation plan: slices, crates, gates

Each slice ships alone and gets a refutation review (ADR 0009). Slices 0 through (e) leave stereo behavior unchanged; (f)'s mode override changes live rendering only when enabled. Rule 4 names two separately reviewed prerequisites: the cue declaration and a repair of master hardware processing. Existing off-mode goldens remain unchanged outside those explicitly added or repaired paths.

**(0) Offline render onto the plan renderer.** Move `RangeRender`, `render_range`, `render_bus` and `engine/src/io.rs` export/bounce onto `PlanCompiler::compile`, `adopt_plan`, `render_active` with an offline target; convert the `plan_parity` oracle tests to golden outputs; then delete `LegacyPlayer` and `MixEngine::render`. New sinks, key edges and hardware inserts are built only on the plan renderer. Gate: `plan_parity` goldens and `engine/tests/bounce.rs` pass bit-identical.

**(a) Open all device outputs; Audio Devices shows them; paths editable.**
Files: `playback` (`lib.rs` `open_device`, `devices.rs` identity, `player/audio.rs`, `player/device.rs` `Player::prepare`, `plan_bridge.rs` `Buffers`, `MeterBank`, `fold`), `mix` (`plan.rs` `RenderTarget`, `compile.rs`), `model` (`IoPath`), `engine` (`setup.io`, `cmd/setup_more.rs`, `cmd/track.rs` `parse_route`, `io.rs` shared input resolution), `ui-studio` (`audio_devices.rs`), `apps/transit` (`config.rs`).
Gate: a fake device opens 10 and 2 channels, cap holds at 32; the `IoMap` round-trips through `ui.json`; a session with "Out 3-4" on the 2-channel fake shows the silent flagged sink with unchanged session text; a golden 5.1 session round-trip (load, save, compare) keeps `main_format()`; stereo audio bit-identical; bus/path collision and missing input path refuse as stated. Note-level real-hardware gate on the Model 12: same ASIO buffer size, round trip and overrun count with 2 channels open versus 10 out / 12 in (cpal's ASIO streams share one buffer set, `player/device.rs:239-244`), and the Scarlett 2i2 unchanged.

**(b) Route tracks, buses and sends to any output path, with consistent PDC.**
Files: `mix` (`route_into`, `process_strip`, send filters at `lib.rs:1735` and `pdc_visit` `1663-1666`, `path_need_with` `2615-2625`, accumulation buffers, `compile.rs`, `plan.rs`), `model` (`route_graph.rs` sinks, `RouteGraph::load` send filter `263-268`), `engine` (`cmd/track.rs`, `cmd/mix.rs:463` send creation targets paths), `ui-studio` (`mixer.rs`), `playback` (`plan_bridge.rs`). Sends now target output paths, so cue mixes work.
Gate: two different tracks with different plug-in latencies routed to two different sinks (Main and a path) land sample-aligned after removing L; overlapping paths sum; a missing path is a silent flagged sink; `plan_alloc_probe` shows zero callback allocations across path edits; golden `plan_parity` cases.

**(c) Sidechain key routes and host wiring.**
Files: `model` (`Insert.key`, `KeyFrom`, `EdgeKind::Key`, `RouteChange::Key`, `route_graph.rs` cut and `reserve`), `mix` (dependency layers, key buffers, pre-slot delay, PDC), `dsp` (`process_with_key`, compressor and gate), `vst3-host`, `clap-host`, `engine`, `ui-studio`.
Gate: key loop refused at edit and cut at load, including a two-track mutual key; kick-to-bass key in the parallel renderer and again with `serial` forced, identical output; late and early keys aligned within one sample with a latent earlier insert; a Pre tap; fixture VST3 and CLAP plug-ins receive the key; a compressor ducked by a kick matches a hand-computed curve; no key leaves the plug-in on its own input unchanged; a silent main with a loud key does not suspend the insert.

**(d) Hardware inserts with latency measurement.**
Files: `model`, `mix` (send/return slot, `latency()`), `playback` (loopback ping, duplex only), `ui-studio`, `apps/transit`.
Gate: a fake-duplex loopback with a known delay measures it to the frame and PDC aligns a parallel dry track; a long-run stability test in the fake; unmeasured flags and counts zero; missing return bypasses dry; offline is dry bypass; Model 12 out 3-4 to in 3-4 loopback recorded as a note.

**(e) Stems.** Bounce over output paths on the plan renderer (needs slice 0). Gate: a stem render per path sums to the main bounce for non-overlapping paths.

**(f) Low Latency mode.** Proposed; implement the eight rules in the 2026-11-05 amendment after rule 4's prerequisites. Touches `crates/mix`, `crates/playback`, `crates/engine` and `crates/ui-studio`; the cue prerequisite also touches `crates/model`. Required gate:

- **Selection and persistence:** deterministic fixture engine tests show a latent master insert delays a live impulse by its reported frames with the mode off and removes that delay with it on. Compare the complete serialized session content with the mode off and on, through save/load and another machine's preferences; allow only explicitly requested ordinary session edits, never a mode-induced change to any field. Test limits of 0 ms and above one insert's latency, two inserts whose sum exceeds the limit, numeric-uid tie breaking, an armed seed, a monitored-but-unarmed seed, an intervening bus insert, shared bus readers/sends, and a direct hardware-output route that does not traverse the master.
- **Compensation and protected processing:** with the mode off and on, render deterministic impulses from at least two unarmed, unmonitored tracks with unequal chain latencies through Main and named output paths. Assert mutual sample alignment against hand-computed effective L after a live-path bypass, including a case where an unrelated track still dominates L and the 0/100/300-frame example in section 6. With the mode off and on, verify accepted, transformed notes and resulting audio through an instrument and a MIDI effect, including an instrument whose own latency exceeds the limit. Verify actual fake-duplex send/return audio through a hardware insert on a track and on the master; unchanged flags alone are insufficient. The master fixture first proves rule 4's repair with the mode off. Exercise all four combinations of Low Latency and the declared-live cue opt-out, asserting exact sink padding and effective insert state; the cue fixture first proves the prerequisite declaration works independently.
- **Boundaries and readout:** offline bounce/freeze/Bounce in Place ignore the mode; `query.path_latency` matches adopted-plan figures with injected device latency, including pending/stale plans and unknown device latency. Cover manual bypass, disarm/monitor changes, latency growth and shrinkage, unchanged recorded samples and take placement across a toggle, and the unchanged clamp. Retain existing off-mode goldens and extend the callback allocation probe across adoption.
- **UI and execution:** drive the real transport and Options handlers: preference persistence, recompile request, lit/checked state, dimmed chips and exact tooltip/status text; register help targets. Follow [gates.md](../contributing/evidence/gates.md): injected frames, timestamps and readouts, deterministic plan adoption, no scheduling or wall-clock assertions; force serial rendering unless testing workers. Assert steady-state sample positions outside the existing PDC transition, and test adoption separately. The implementer's gate includes `cargo xtask rt-targets` because this slice touches `crates/mix`, plus the normal contribution gates and `cargo xtask help`.

## Consequences

- A session built on the TASCAM opens on the Scarlett with path-targeted outputs silent and flagged; nothing is lost, nothing is rewritten, and no cue reaches the PA.
- `route_graph.rs`, `pdc_visit`, `route_into`, `path_need_with` and the compiler change together per slice. Slice 0 removes the second renderer first so each change is made once.
- `Plugin` gains a defaulted method, touching `dsp`, `vst3-host`, `clap-host`; upstream offers need care, as with ADR 0012's note API.
- The settings schema grows (`ui.json` `IoMap` tables, measured latencies); old files load with defaults. The session file is unchanged through (a) and (b), so older builds still read it.
- Stereo-only users pay nothing: one stereo path, identical output. The 32-channel cap is a documented limit raised by one constant and the scratch budget. On Windows, multichannel requires ASIO.

## Alternatives considered

- **Ableton Live's Reduced Latency When Monitoring.** It exempts monitored tracks from compensation but retains the latency of devices on their own route, including the master ([documented behavior](https://help.ableton.com/hc/en-us/articles/209072249-Reduced-Latency-When-Monitoring-FAQ)). That leaves exactly the master-chain delay reported in #321. Transit takes Logic Pro's live-path insert-bypass shape instead ([plug-in latency controls](https://support.apple.com/guide/logicpro/work-with-plug-in-latencies-lgcpe11997ba/mac)).
- **Switch Delay Compensation off outright.** Available in Ableton Live and already in transit as `options.delay_compensation`; it sacrifices alignment throughout playback and still cannot remove an insert's own processing delay. Keep it independent; Low Latency does not flip it.

- **Keep two-channel main plus per-track direct outs.** Smallest change. Rejected: a parallel mechanism beside buses and sends, no cue mix summed from several tracks, no home for sidechain or hardware inserts.
- **A full matrix-mixer UI like RME TotalMix.** Rejected for now: asks users to re-solve routing a session already states, duplicates a mixer, and sums at the device without PDC awareness. Revisit if direct-monitor routing for devices without a hardware mixer becomes a goal.
- **Per-session device channel numbers, no named paths.** Rejected: breaks on any other interface and cannot show a human name. Names resolve per machine; numbers do not.
- **Paths stored in the session (today's `Session::outputs`).** Rejected for paths: the session would carry device facts. It stays only as the main-format source (section 1.3).
- **Cap at the main width, or at 16.** Rejected: 16 is the width of a path, not of a device.
- **Sidechain as a special per-plug-in parameter, or aux-only keys.** Rejected: the first hides a dependency from loop refusal and PDC; the second makes kick-to-bass impossible, the common case.

## Amendment 2026-11-05: Low Latency mode

Issue #321: a keyboard-played soft synth felt late at ASIO 128 frames with 7 ms reported output latency. A mastering suite and a bus compressor were on the master; bypassing the mastering suite removed the delay. Section 6 correctly aligns playback, but also makes a live instrument wait for that chain. Logic Pro offers one visible Low Latency switch, a millisecond limit and marked bypassed plug-ins along the record-enabled signal path, including outputs. Ableton Live offers one monitoring-latency switch with a different compensation rule (Alternatives above). Transit follows Logic Pro's shape: temporarily trade processing and, with a live cue, alignment for tighter playing. These rules specify transit's behavior; they do not promise an end-to-end device latency ceiling.

1. **Machine preference and command.** Add `UiState.low_latency: bool = false` and `UiState.low_latency_limit_ms: f64 = 0.0` in `crates/ui-studio/src/ui_state.rs`, serialized as top-level `ui.json` keys `low_latency` and `low_latency_limit_ms`, beside `audio`, `audio_devices_section` and `io_maps`. Retain serde defaults for old files. The limit is finite and nonnegative; reject invalid command values and default invalid saved values to 0. Neither field belongs in `Session` or its undo history: saving with the mode on transfers no mode, limit or bypass override to another machine. Extend `audio_devices.rs::persist_audio`'s atomic merge to write both keys while preserving other preferences; use it on preference changes, honoring the existing no-preferences switches. The limit control lives in Audio Devices > System. Register `options.low_latency`, label `Low Latency`, menu `Options`, params `{value?: bool, limit_ms?: number}`; omitted `value` toggles unless only `limit_ms` is supplied. Return the resulting `{value, limit_ms}`. Use a **UI-owned command**, dispatched through `StudioApp::run` like `window.editors_follow`, with catalog/control-channel registration. The `toggle!` rows in `crates/engine/src/cmd/options.rs` mutate `session_mut().edit`, so that macro is unsuitable even though it says `noundo`. An engine-only host must supply the same runtime preference adapter or return unavailable, never fall back to a session toggle. `transport.rs` and the Options item invoke the same handler.

2. **Live paths and deterministic bypass set.** On the control thread, add `low_latency_bypass` beside the compiler. Seed it with every non-inactive track whose `mixer.record_arm || mixer.input_monitor`, and separately every non-inactive `TrackKind::Master`. The fields live on `Mixer` in `crates/model/src/mixer.rs` (accessed through `Track::mixer`, `track.rs`). Walk the solved section 4 graph using `RouteScratch::layer`, `edges`, `order` and its dropped-edge decisions: follow Output and Send edges into buses, Input edges into their Aux/Folder readers, recursively to Main or a named output sink. The graph omits masters and hardware terminals: append the active master chain at Main, and resolve `Route::Hardware` outputs/sends through the same sink table as the compiler. Direct outputs do not acquire master processing. Include every downstream bus reader and reached output path; never walk backward into unrelated bus feeders. Include sends regardless of their mute/level, as the PDC walk does. Key edges remain alignment dependencies, not new live-path seeds. A master is a seed even with no armed track. `routing.rs::live(t)` is **not** this predicate: it includes ordinary playback strips and excludes masters. Use the same graph/order as `pdc_visit` and `path_need`; `path_need_with` is the older name in this record, absent on this base.

   Convert the preference to frames with `floor(limit_ms * running_sample_rate / 1000)`, saturating at `MAX_LATENCY`; 0 ms adopts the zero added-latency default in the maintainer's Logic Pro convention. For each seed-to-sink audio path, sum its running instrument, audio-insert and hardware-insert latencies, counting shared slots once per path and masters only where traversed. This selection budget excludes device latency and compensation padding from other paths. Start with an empty set. Among active, available, non-user-bypassed **software audio inserts** on any still-over-limit live path, choose the largest positive reported latency; break ties by ascending numeric `(track.id.0, insert.uid.get())`. Add `insert.uid.get()`, subtract its contribution on every containing path, and repeat until all paths fit or no eligible insert remains. Thus two 4 ms inserts with a 5 ms limit lose one, deterministically; an insert below the limit is retained when the whole path fits. Instruments, MIDI effects and section 5 hardware inserts are never candidates. An instrument alone above the limit keeps sounding, nothing is bypassed, and the readout shows the remaining latency. Other unavoidable latency likewise remains after eligible inserts are exhausted. Inactive/frozen chains have no running insert candidates. Unrelated high-latency playback tracks can still set L: this mode does not disable their inserts or automatically opt any sink out of padding.

3. **Compile input, never a session edit.** Pass a control-computed `BTreeSet<u64>` of `InsertUid::get()` values (empty when off) into `PlanCompiler`'s live compile in `crates/mix/src/compile.rs`, separate from `CompileMode`'s Update/NewDocument meaning. Use numeric identity throughout selection and lookup: `InsertUid` deliberately compares equal in model equality and has no `Ord`/`Eq`; do not change those semantics. Compute the set after fresh instances supply `plugin.latency()` and from current reported latencies for retained instances. Preserve raw per-slot latency even while bypassed, so selection can be recomputed from scratch. Store effective bypass in plan-owned slot metadata: `insert.bypass || mode_set.contains(&insert.uid.get())`. Use the **same bypass branch** for rendering, key alignment, note-reader release/parameter servicing and latency accounting (`strip.rs`, `key.rs`); a mode-bypassed slot contributes zero to `path_need` and the running PDC walk. Do not overwrite `Insert.bypass` or `Insert.active`, even in the plan's session snapshot. Include the set in plan-change detection so the compiler's unchanged-description fast path cannot hide a toggle. Unselected paths retain full compensation to the recomputed L (which may stay unchanged if another path dominates).

   Toggle/limit, arm/monitor, route and insert changes use the existing `StudioApp::sync_player_session` (`host/plugin_state.rs`) → `Player::update_session` (`playback/src/player/runtime.rs`) → `SessionControl`/`plan_bridge` compile/publication path, as user bypass does. A preference revision must also invalidate its session-identity early return, since the session itself did not change. The audio thread receives only the prepared override and preallocated storage, adopting at section 7's drained boundary: no set construction, allocation, lock or plug-in destruction there. Refusal leaves the running plan and its displayed bypasses intact and surfaces the existing error; a pending preference is not proof of adoption.

4. **Rendered deliverables and live cues.** Offline render, bounce, freeze, commit, stems and Bounce in Place (#318) always compile with an empty mode set and honor only user bypass flags. The boundary is `crates/engine/src/io.rs`'s render modules (`io/bounce.rs`, `io/paths.rs`) → `crates/mix/src/offline.rs::RangeRender::try_new`/`try_new_paths`: their fresh headless compiler gets no machine preference. Thread the override only through the live Player compile; never use the live effective chain as a bounce source. A render job using a live Player must likewise request the full chain for the job and restore the preference afterward. ADR 0038's offline chain-latency amendment still applies per block. A section 6 live headphone cue is independent: Low Latency bypasses selected inserts, and that cue still skips sink padding; turning either off leaves the other's rule intact.

   **Prerequisites, separately reviewed before (f) can pass:** the cue opt-out is specified in section 6 but absent from this base (`model/src/io_map.rs::IoPath` and `mix/src/sink.rs::SinkSpec` have no flag; `tail.rs::fold_latency` pads every sink). Add `IoPath.live: bool` with `serde(default)`, false, persisted in the per-machine `io_maps` table and copied into plan-owned `SinkSpec`/`Sink`. Declare it in Audio Devices > I/O paths on a named cue output, through `setup.io_map`; restrict it to non-Main output paths. A live cue keeps its own maximum arrival instead of being raised to L; its feeders still align with each other, and it still contributes to the maximum used for other sinks. It changes neither upstream bus/key alignment nor insert processing. Offline compiles ignore this machine opt-out too. Existing maps without the flag retain full compensation.

   Master hardware processing is a separate base defect: `sink.rs::plan_sinks` excludes masters before collecting hardware sends, and `strip.rs::process_master` runs only software slots. Repair sink collection and the master's hardware run/flush path using section 5's existing duplex, missing-path, latency and offline-dry rules before claiming the exclusion works on the master. Prove that repair with Low Latency off, then on; merely keeping a hardware uid out of the bypass set cannot prove a working loop. These prerequisites are required delivery work, not implemented capabilities or changes to the mode's selection rule.

5. **Visible state.** The transport button is lit and Options item checked while the preference is on; show pending application separately until adoption. Every mode-bypassed insert chip in `crates/ui-studio/src/mixer/strip.rs` and device card in `devices.rs` is dimmed with the exact tooltip `bypassed by Low Latency`, using the **adopted** set by uid. Once per toggle, after adoption when a player is open (immediately with zero bypasses and 0.0 ms saved otherwise), write `Low Latency on: <n> inserts bypassed, <ms> ms saved` or `Low Latency off` to the status line. `<n>` counts mode-only bypasses; `<ms>` is one decimal, the nonnegative reduction of shared L versus the same topology/latency snapshot with only user bypasses, not a sum of slot delays. Arm or latency refreshes update chips/readouts without repeating toggle messages. Register help ids in `help/ids.rs` and the help catalog: `TransportLowLatency => "transport.low_latency"`, `OptionsLowLatency => "options.low_latency"`, `AudioDevicesLowLatencyLimit => "audio_devices.low_latency_limit"`, `DeviceLowLatencyBypass => "device.low_latency_bypass"`, and `DiagnosticsPathLatency => "diagnostics.path_latency"`.

6. **Path latency readout and query.** Show `Path latency: <ms> ms` in the Low Latency button tooltip and in diagnostics (`crates/ui-studio/src/diagnostics.rs`, including Copy diagnostics). No permanent transport figure: follow the convention of a mode indicator with details on demand. The displayed total is the current plan's shared L plus backend-reported output latency, not buffer size, CPU load or a UI estimate. On this base `path_need` sizes capacity; it is not the actual readout. Use the effective chain's running `tail.rs::fold_latency` / `MixEngine::latency` (the render counterpart of that walk), after bypass and clamping. Extend the fixed `PlanStatus`/`plan_bridge::StatusReport` with L and the master-chain contribution, tagged by plan and device generation. `required_latency` today is a capacity-growth high-water mark, not current latency. `Player.output_latency: Option<Duration>` and `Player.device_rate` already supply the backend term (`audio_devices.rs::achieved_detail` displays it); `load_readout.rs` reads callback frames/rate and `current_load_ppm`, none of which measures path latency.

   Add read-only `query.path_latency {}` in the style of `crates/engine/src/cmd/query.rs`, backed by the host's latest coherent audio status, mirrored into engine runtime state, never `Session`. Return `{available, device_generation, plan_generation, sample_rate, low_latency, padding, master, engine, device, total}`, each latency component `{frames, ms}`. `engine.frames = L`, `master.frames = M` (running master-chain sum), `padding.frames = L - M` (the pre-master alignment target including upstream chain latency, **not** an individual edge's added delay), `total = engine + device`; thus do not add master twice. Integer plan frames convert using the running sample rate; device frames may be fractional, derived from the reported duration. `low_latency` describes the adopted mode. No running plan means `available: false` and null components; unknown output latency leaves `device` and `total` null, showing `Path latency: unknown (device output latency unavailable)` with known engine figures. Discard reports from another device/plan generation; while a replacement is pending keep the running plan's figures. A live cue's unpadded latency can differ: label this figure as shared/Main path latency, not a physical round-trip measurement or a per-cue promise. All formatting and ms conversion happen off the audio thread.

7. **Interactions.** Toggling while recording is allowed. The recorded input audio is unchanged: `playback/src/record.rs::capture_callbacks` sends device frames to `Shared::capture_at`/`CaptureRing` before mixer inserts, separately from the monitor ring. Do not restart capture or alter its latch/placement when publishing the plan. If the user manually bypasses an already mode-bypassed slot, the ordinary user flag wins and persists; recomputation removes it from the mode-only count, and turning the mode off leaves it bypassed. Disarming restores eligible inserts and repads the path only if monitoring is also off and no other live seed reaches that bus; the master remains eligible. Reported latency changes recompute the set on the control thread and publish another plan. Extend the existing `RuntimeControl::service` in `playback/src/player/runtime.rs` latency-refresh path: its current `capacity_exceeded/required_latency` trigger covers growth beyond capacity only, so also signal any raw per-slot latency change (including shrinkage and bypassed slots) through preallocated, generation-tagged status. Keep the current plan until adoption and keep the existing PDC transition behavior. `MAX_LATENCY = 1 << 20` in `crates/mix/src/lib.rs` is unchanged; the mode neither raises the clamp nor promises zero latency from instruments, hardware, unrelated PDC or the device.

8. **Delivery gate.** Implement as slice (f) above, including rule 4's prerequisites and every engine, UI, allocation and cross-target case. The master-only regression must measure sample positions and compare complete serialized session content through save/load, not merely inspect bypass flags or the selected set. Non-live alignment, instruments, MIDI effects and hardware loops need rendered audio/event evidence with the mode on; cue independence needs all four switch combinations. The readout test must observe an adopted plan through the query, not substitute the requested preference or the compiler's capacity estimate. No real-clock or scheduling assertions.
