# ADR 0028: MIDI Learn mappings

- **Status:** accepted 2026-10-25 (decided by Derek for v0.3.0, #97)
- **Date:** 2026-10-25
- **Reopen when:** a controller needs 14-bit CC pairs, NRPN, relative (endless encoder) CCs or LED feedback; or mappings must follow a track across sessions by name rather than by position (slice 2 and later).

## Context

The only learn features today are the step-input bindings and the MIDI Monitor's Learn spotlight. Nothing maps a controller knob, fader or button to a mixer control (#97). Slice 1 covers the mixer and track controls: fader, pan, mute, solo, record arm and send level. Plug-in parameters (with automation write) are slice 2, transport and global actions are slice 3.

## Decision

1. **A mapping is `source -> target` plus how to apply it.** Source: input port name (`PortKey` display string), channel (0 to 15, or any), kind (`cc` or `note`) and number. Target: a control id, `track:<id>:volume|pan|mute|solo|arm|send<slot>` (session) or `strip:<n>:...` (profile, see 3). Mode: `pickup` (default) or `jump`. Range: `min` and `max` in 0..1 of the control's own travel (fader position, balance, send position); a knob at 0 means `min`. Buttons carry `toggle` (default true: note-on or CC rising through 64 flips; false: momentary, follows note on/off or CC >= 64).
2. **One source drives one target, per store.** `map` replaces any earlier mapping of the same target or of the same source in that store.
3. **Two stores.** The **controller profile** is per machine, saved in `ui.json` (`midi_profile`), keyed by port name; because track ids belong to one session, profile targets address a strip by position (`strip:3:volume` is the third track in session order). **Session mappings** are `Session::midi_mappings`, saved with the session, addressing tracks by id. Both load with none when the field is absent. At resolve time a session mapping wins over a profile mapping that shares its source or its target; the shadowed one stays stored and is shown as "overridden".
4. **Realtime contract.** Main resolves both stores into an immutable `Snapshot` (entries keyed by the ingress input id of the open port) and swaps an `Arc<Snapshot>` into the ingress worker through the existing update channel; the worker never builds, locks or frees one (Main keeps replaced snapshots until the worker's reference is gone). Per admitted message the worker scans the snapshot, with no allocation or lock, and publishes a `MapEvent` (`Copy`) to Main through a preallocated SPSC ring; it applies pickup and jump itself, from a per-entry atomic cell holding the control's last value (Main refreshes the cells once a frame). Main applies each event with the same setters a mouse drag uses. Matching runs on every open input port, routed or not, without popping unrouted ports (a cursor like the monitor's), so a controller no track listens to still maps. With no mappings and no learn armed the worker does nothing extra. **Learn state is Main-side only:** Main arms one atomic flag; the worker forwards exactly the next CC or note-on as a candidate (it clears the flag with a swap) and keeps no learn state.
5. **Undo.** A mapped move of a control is applied through `execute_merged`, keyed per control, and the gesture ends after 400 ms without a move (UI clock, injectable), so a sweep of a fader is one undo step like a mouse drag. Session `midi.map` and `midi.unmap` are ordinary undoable commands. Profile changes are per machine, like the I/O map: they neither dirty the session nor make an undo step.
6. **Commands.** `midi.learn {target, scope?}` arms (the next candidate becomes a `midi.map` with defaults), `midi.learn_cancel`, `midi.map {source, target, mode?, min?, max?, toggle?, scope?}`, `midi.unmap {target, scope?}`, `midi.mappings` (query). Learn arming itself is not an edit.
7. **Mapped messages are consumed by default (decided by Derek).** A CC or note-on that a mapping matches drives its control and is not delivered to the track's routes (instrument, echo, recording); `pass_through` (serde default false, a column in the mappings window) delivers it to both. This is how Logic's Controller Assignments and Ableton's MIDI Map behave, and where they agree transit follows them. The matching note-off is consumed exactly when its note-on was (a bit per channel and key in the worker), so a note held while a mapping is added or removed never hangs. The match runs where a routed port's event is popped, so nothing arriving between a scan and the pop is missed or leaks; an unrouted port is scanned without popping. The learn candidate is not consumed.
8. **A slow UI loses no value.** A continuous control's newest value goes to a per-mapping cell (last value wins, with a publish count for pickup) that Main takes once a frame, so the ring carries only button presses and candidates, and drops are counted and shown in the mappings window. While anything is mapped or a learn waits, the UI repaints at its normal rate. A mapped gesture uses one merge key, so controls moved together are one undo step.
9. **Out of scope:** plug-in parameters and automation write (decided in the slice 2 amendment below); transport, cycle, metronome and MMC (slice 3); relative encoders, 14-bit CC, NRPN, LED feedback.

## Amendment: slice 2, plug-in parameters (2026-10-25, #97)

10. **Plug-in targets.** `track:<id>:plugin:<slot>:<param id>` in a session, `strip:<n>:plugin:<slot>:<param id>` in the profile. The slot and the parameter id are the automation picker's addressing (#65): the slot is an insert letter `a` to `j` or `instrument`, the id is the plug-in's stable parameter id (never an index) and is the rest of the text, colons included. The same target form serves built-in and hosted plug-ins. A target needs a device in the slot and a built-in's parameter must exist (the engine checks at `midi.learn` and `midi.map`). Later, a device that is gone leaves the mapping stored and idle, and it returns with the device (undo).
11. **Range.** The mapping's `min` and `max` still span the knob's travel, and the 0..1 the worker publishes is the parameter's **normalized** travel, not its raw value: Main turns it into the parameter's own units with the function a panel knob uses (`knob::value_at`, which calls `ParamInfo::from_normalized`: the taper honored, whole numbers where the parameter is one). A cutoff on a log taper is therefore centered at the geometric middle, and a choice lands on a whole step. Pickup and jump, consume by default and `pass_through` are as slice 1; a toggle or choice parameter is a continuous control that flips as the knob crosses its steps.
12. **Applying a move.** On Main, through `mix.insert_param` or `mix.instrument_param` under the one gesture merge key, after `touch_param`: the same path as a mouse drag or a hosted editor's edit. The audio thread does nothing new; the realtime contract of decision 4 is unchanged (the snapshot, cells and ring do not know what a target is).
13. **Automation (the Ableton and Logic rule).** Because a mapped move is a touched parameter, Write, Latch and Touch record it into the parameter's lane while the transport plays, exactly as a fader or a knob does, and Read applies the value live and writes nothing. A controller has no pointer, so the touch is held `HOSTED_HOLD_S` (150 ms) after the newest value: Touch lets go that long after the knob stops.
14. **Entry points.** Built-in editors (panel knobs, toggles, choices and the generic rows): right-click offers *MIDI Learn*, *MIDI Learn for this controller (all sessions)*, *Forget MIDI Mapping* and the *Mapped: ...* line; a mapped parameter has the marker, a learning one the pulsing outline. Hosted editors draw their own widgets, so their header strip's menu has **MIDI Learn: next touched parameter**: it arms; the next parameter the plug-in reports as edited (a changed value, not an echo) becomes the target through `midi.learn`, and the next CC or note maps it. The same item again, or Escape, cancels. The result is a session mapping; the controller-wide variant is a known issue.
15. **Refusal.** A hosted parameter that the host registries do not list (they drop hidden, read-only and meter parameters, the same table the picker offers) is refused with a status line, at the menu and at the touch. A plug-in whose table is not cached yet accepts the parameter it just reported; a move of such a mapping is ignored until the table is cached (known issue).

## Consequences

- A mapped CC or note is consumed: a CC mapped to a fader does not also sweep the synth's filter, and a pad mapped to mute plays no drum note. The mapping's *Pass through* option (off by default) sends it on to the track as well, for the rare case.
- Ports are opened while any mapping or learn exists for them (as the monitor does), so mapping opens input ports that no route would.
- A profile mapping to a position follows whichever track sits there; moving tracks changes what the knob moves.
- Sessions saved with mappings load in older builds with the mappings ignored (no `needs` marker: nothing plays wrong).
- A mapped plug-in parameter makes the same undo step and the same automation as a mouse move; recording a controller sweep is a matter of putting the track in Write, Latch or Touch.

## Amendment: takeover modes (2026-10-25, #122)

**Context.** Pickup alone leaves a knob dead until it crosses the control, which reads as a broken mapping (#121). Logic Pro's default is value scaling (its "Scaled" mode: the control moves toward the controller and they meet at the end of the controller's travel), with "Jump" and "Pickup" as the alternatives. Ableton Live defaults to "None" (jump) and offers "Pick-up" and "Value Scaling" per mapping. Where they agree, transit follows: scaling is the behavior that never surprises with a jump and never goes dead, and both offer all three.

**Decision.**

1. **One per-machine setting, `takeover`: `scaled` (default), `jump` or `pickup`.** It lives with the controller profile in the per-machine preferences (`ui.json`, field `midi_takeover`), never in the session, and rules every continuous mapping, strip controls and plug-in parameters through the same worker path. Buttons and toggles are unaffected. A mapping's own `mode` field stays in the file for compatibility and is ignored; `midi.map` accepts `scaled` beside `pickup` and `jump`. The setting is chosen in Window > MIDI Mappings and in a mapped control's context menu.
2. **Scaled.** On each incoming controller value the control moves from its current value by the same fraction of its remaining distance to the end of its travel in the direction of the move as the controller moves of its own remaining distance to that end: moving up by `d`, the control rises by `d / (1 - from) * (1 - at)`; moving down, it falls by `d / from * at`. Both reach the end together, so there is never a jump; the gap between them closes monotonically as the controller moves toward the control's side and widens only when it moves away. Once they coincide (or are within one controller step) the control tracks the controller directly. The first message after a mapping starts only records where the controller is. The control's value is the one the worker last left while Main is behind, else the value Main reports, so a mouse drag or automation is respected. The result is computed in the knob's own travel (the mapping's range applies as before) and is deterministic.
3. **Jump** publishes every value as is. **Pickup** is slice 1's rule, including the "waits for pickup" status; passing through the control's value hands over. Scaled and jump never report a held-back knob.
4. A note on a continuous control still sets it from the velocity, whichever takeover is set.

**Consequences.** New mappings behave without setup. Existing profiles and sessions that stored `pickup` or `jump` per mapping now follow the machine setting; the stored field is not rewritten. A per-mapping override is left for a later amendment if it is asked for.

## Alternatives rejected

- **Match on the UI thread.** Adds a frame of latency and drops fast sweeps at the tap ring's size.
- **Build the table in the worker.** Allocates on the worker and needs session access.
- **Target tracks by id in the profile.** Ids are meaningless in another session.
