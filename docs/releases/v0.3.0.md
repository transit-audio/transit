
# transit v0.3.0

The 0.3.0 release is the MIDI release. You can map hardware knobs, faders and buttons to transit controls and to plug-in parameters with MIDI Learn. A MIDI track can play a hardware synth over a port, and the new External Instrument device measures the round trip of that synth and puts its audio back in time. Around that sit a MIDI Monitor, protection against MIDI feedback loops, and a set of piano roll and step input tools. The plug-in host, Audio Devices and the Linux packages also change. transit is alpha-quality software and the session format may still change, so back up anything you care about.

## Highlights

- **MIDI Learn.** Right-click a mixer control, or use a plug-in header's "MIDI Learn: next touched parameter", move a knob, fader or button, and it is mapped. Mappings live in the session or a per-machine controller profile, and a mapped move is one undo step that records into automation.
- **Takeover modes.** Scaled by default: a knob that does not match its control meets it at the end of travel, with no dead zone. Jump and Pickup are options. A hosted VST3 parameter follows the plug-in's own curve.
- **External Instrument.** A MIDI track can play a hardware synth over a port and channel. The External Instrument device adds the audio return and a Measure that times the synth's round trip, so its audio lands on the grid. Bounce can render in real time to include it.
- **MIDI Monitor and feedback protection.** Every message on every port, in and out, with filters. A loop between a controller's input and output is detected and muted.
- **Piano roll and step input.** Scale mode with named scales, transpose and constrain, quantize strength and swing, sustain and CC lanes, Alt to bypass snap. Step input adds ties, rests and hold-to-lengthen.
- **Clip loops and fades.** A loop handle repeats an audio or MIDI clip inside itself. Audio clips have fade and crossfade handles.
- **Audio Devices.** A sidebar for short screens, pending changes with Apply and Revert, and Copy diagnostics.
- **Plug-in host.** Load phase and time on a Loading slot, editors at the display scale, a header with user presets and bypass, and a searchable automation picker.
- **Packages.** Linux gets an AppImage, a .deb and an .rpm. The Windows MSI shows the standard dialogs. The cpal ASIO path is retired in favor of native ASIO.
- **Mixer.** Bus and FX return strips get their own block beside Master.

## Fixes

- MIDI Learn: a mapped controller moves a mixer fader and a hosted plug-in parameter (#121).
- MIDI Learn: a hosted VST3 parameter follows the plug-in's own curve instead of stepping in plain units (#123).
- MIDI Learn: a hosted instrument's parameters can be set from transit and from a mapped controller (#97, K83).
- External Instrument Measure no longer refuses every run on real hardware with "Input alignment changed during the measurement" (#98).
- A MIDI feedback storm no longer loops until the app is closed (#99).
- Piano roll: a note can be made shorter than the grid with Alt (#100).
- Plug-in editors draw at the display scale on scaled Windows displays (#101).
- VST3 editors that apply the scale factor only after attaching, or that resize themselves, now work (#105).
- A GPU device loss no longer panics the UI and hangs the process in a plug-in unload (#104).
- The Windows MSI shows its installer dialogs (#109).
- Linux (ALSA via PipeWire): the chosen buffer size and the size the stream runs at are both shown (#83).
- Changing the audio driver shows that Apply is needed before dependent settings update (#108).
- The MIDI input thread wakes on input instead of a 1 ms timeout that Windows rounds to its 15.6 ms tick (#62).
- Looped recording continues into the next lap, and each lap is a take (#48).
- Mixer: the pan knob and small controls keep contrast on the selected strip (#102).
- Native JACK, when built from source: Apply asks the server for the chosen buffer size (#111).
- Several timing tests no longer fail under machine load (#106, #110, #76).

## Known issues

Full list: [docs/known-issues](https://github.com/transit-audio/transit/blob/main/docs/known-issues/README.md).

- K24, K25: on the Focusrite Scarlett 2i2, WASAPI measures about 220 to 250 ms round trip in every mode. Use ASIO for tracking.
- K27, K29: the TASCAM Model 12 over WASAPI exclusive is about 270 ms and may be silent, and shows only 2 in / 2 out. Use shared mode or ASIO.
- K31: ASIO loop agreement is verified on the Scarlett 2i2 at 48 kHz only. Run Measure on other drivers and rates.
- K32: an automatic ASIO reopen replaces the player, so plug-in editors close and reopen.
- K10: on macOS, plug-in creation still runs on the UI thread, so a heavy plug-in can freeze the UI there.
- K75: a controller-profile mapping addresses a strip by position, so moving tracks changes what a knob moves.
- K76: MIDI Learn maps absolute 7-bit CCs and notes only. Relative encoders, 14-bit CC, NRPN and LED or motor-fader feedback are not supported.
- K80, K81, K82: a hosted plug-in is learned from its header strip's "MIDI Learn: next touched parameter" as a session mapping; a mapping to a plug-in that has not loaded yet is ignored until it has; a toggle parameter flips as the knob crosses half travel.
- K86: a hosted VST3 parameter's strip knob and automation lane still use an approximate curve, so they can disagree with a mapped controller on where a value sits.
- K84: a lost graphics device closes transit (autosave kept) instead of recovering.
- K74: a plug-in editor that ignores the host's scale draws at 100% on a scaled Windows display.
- K39: editing a clip while one of its notes sounds can leave that note on at an external MIDI port until the next loop wrap, locate or Stop.
- K40, K41: a session with a looped clip or an External Instrument that an older build opens and saves loses that data. Do not save such sessions from older builds.
- K52: while the MIDI Monitor window is open it holds every input port, so on Windows another program cannot open one.
- K64, K65: real-time render does not cover freeze, flatten, stems, normalize, stereo fold-down or bus bounces yet.
- K38: a VST3 plug-in whose module entry never returns can block later VST3 loads. CLAP plug-ins are not affected.
- A plug-in that crashes still takes the app down; out-of-process hosting is planned (#9).

## Downloads

Assets are attached to this release.

| Platform | Asset |
|---|---|
| Windows (x86_64) installer | `transit-v0.3.0-windows-x86_64.msi` |
| Windows (x86_64) portable | `transit-v0.3.0-windows-x86_64.zip` |
| macOS (Apple silicon) | `transit-v0.3.0-macos-arm64.dmg` (holds `transit.app`) |
| macOS (Apple silicon), bare binary with `audio-bench` | `transit-v0.3.0-macos-arm64.tar.gz` |
| Linux (x86_64) tarball with `audio-bench` | `transit-v0.3.0-linux-x86_64.tar.gz` |
| Linux (x86_64) AppImage | `transit-0.3.0-linux-x86_64.AppImage` |
| Linux (x86_64) Debian and Ubuntu package | `transit-0.3.0-linux-x86_64.deb` |
| Linux (x86_64) Fedora and RPM package | `transit-0.3.0-linux-x86_64.rpm` |

A `.AppImage.zsync` file sits next to the AppImage for delta updates. Every archive carries `audio-bench`, which measures your interface (round trip, jitter, xruns).

All builds are unsigned. On Windows, SmartScreen shows "More info", then "Run anyway"; the Windows build includes native WASAPI and native ASIO. The macOS app is ad-hoc signed and not notarized; if macOS blocks it, run `xattr -dr com.apple.quarantine /Applications/transit.app`, or right-click it and choose Open. On Linux, make the AppImage executable (`chmod +x`) and run it, or install the .deb or .rpm with your package manager; none of the Linux packages are signed. The native JACK backend (#55) is available when building from source with `--features native-jack`; the Linux packages do not enable it.
