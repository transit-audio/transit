# transit v0.5.1

This is a point release shortly after v0.5.0, for Linux. It makes the native JACK backend work under PipeWire without `pw-jack`, and makes the Audio Devices window tell the truth about buffers there. Windows and macOS get only the load readout fix. transit is alpha-quality software and the session format may still change, so back up anything you care about.

## Highlights

- **Native JACK connects under PipeWire without `pw-jack`.** When PipeWire's server is running, transit looks for PipeWire's own JACK library first, so Auto reaches the server on Ubuntu and Debian without starting transit as `pw-jack transit`. Audio Devices shows which library is in use, or every library tried and why each failed. `pw-jack transit` still works (#230).
- **Audio Devices shows the buffer you really get on Linux.** Through ALSA under PipeWire, the buffer is split into periods and PipeWire runs transit at the period, so the window now shows buffer, period and the server's quantum, labels each size with its period, and says that PipeWire's quantum sets the period. The latency wording is about the buffer plus the quantum, and the troubleshooting page explains buffer versus period (#230).
- **The buffer picker follows the server.** Under PipeWire it offers only sizes the server allows, one range serves both the list and opening the device, and a saved size the device no longer offers opens at the nearest one it does instead of locking the control (#230).
- **The load readout ignores a stalled callback.** One stalled audio callback no longer skews the load figure in the Callback Telemetry window (#230).

## Fixes

- Tests: a held-source test in the render-task graph no longer lets its deadline pass before the worker wakes; it misses the source by the deterministic deadline instead of a 5 ms wait. No user-facing change (E66).

## Known issues

Full list: [docs/known-issues](https://github.com/transit-audio/transit/blob/main/docs/known-issues/README.md).

- K88: mixer strips render on the render workers by default, and `TRANSIT_RENDER_POOL=0` renders them serially on the audio thread. A session with sidechain keys renders through the task graph by default, and `TRANSIT_RENDER_GRAPH=0` is its opt-out. The auxes, busses and masters still render serially on the audio thread after the strips until slice 2 of #174.
- K89: a plug-in that hangs inside a render worker keeps its track silent and refuses session changes until you close the device or Reconnect. The hung track shows the Unresponsive marker after two seconds, and the engine cannot say which plug-in on that track hangs.
- K90: a plug-in that never returns on the host thread cannot be stopped. Give up quarantines it, but its editor window stays as a ghost until transit exits, so choose Later first and do not End Task the ghost.
- K91: fixed for PCM takes at the session's rate (#187, slice 1). Takes at another rate, or in a compressed format, that are too long to decode are still refused, with a message and an entry under unplaced takes.
- K92: Linux editor windows do not speak XEmbed, so keyboard focus can stay with the main window or nowhere until you click into the plug-in's field. Keyboard shortcuts typed into an editor are not forwarded to transit.
- K93: Linux editor windows keep the scale they opened with, and they do not rescale between monitors with different scaling. A native Wayland surface is later work.
- K94: Linux editor windows have no header strip and no transient-for link to the main window, so with Follow transit on they hide and return with a minimized main window, and activating transit does not lift them above it on every window manager. The strip and the link are slice 2 of #147.
- K95: Macro Oscillator, raising Voices from 1 while several keys are held legato leaves them all on voice 0; replaying one of the older held keys drops the others there. Reachable only by changing the voice count mid-phrase from mono (#196).
- #184: one recording on an overloaded machine showed a 4.7 s stretch of exact zeros in both armed inputs; a one-hour recording under heavier compile load did not reproduce it. Input stalls are not yet counted or marked on the take. Please report it if you see it.
- #215: items 1 and 3 remain. The scheduling gate's deterministic seam cannot produce every miss outcome yet, and the testing feature's coverage of the fingerprint seam is incomplete.
- #219: a bypassed insert receives no parameter values, and a Save As right after a skipped block can still read the previous value.
- KC5: Linux, native JACK under PipeWire: connecting without `pw-jack` is verified only where PipeWire's JACK library is not blocked by JACK 2's; it needs a tester on Ubuntu 24.04 with both `jackd2` and `pipewire-jack` installed. If the Audio Devices window says another libjack was already loaded, start transit as `pw-jack transit`.
- KC6: Linux, ALSA under PipeWire: the buffer you choose is the ALSA buffer, split into four periods, so PipeWire runs transit at about a quarter of it; the window shows the buffer, the period and the server's quantum. Making the chosen size the period itself is an open question.
- KC7: Linux: the window recognizes PipeWire's ALSA `default` device only where pipewire-alsa's default configuration file is installed in the standard place; another route to PipeWire shows the plain buffer list.
- Open items: compressed formats, recording straight into a disk-backed source and the UI setting for long takes are slice 2 of #187. Clip tools slices 2 and 3 are open in #181, and the range gesture that Crop and the range tools need is #224. More help catalog areas follow in #178. The return time for Touch mode is a constant 0.2 s until #223 makes it a setting. Browser preview converts sample rates with linear interpolation, so a 96 kHz file previewed at 48 kHz can alias; #225 proposes a streaming sinc stage to bring preview to import quality, and it also tracks a cue output path for preview.

## Downloads

Assets are attached to this release.

| Platform | Asset |
|---|---|
| Windows (x86_64) installer | `transit-v0.5.1-windows-x86_64.msi` |
| Windows (x86_64) portable | `transit-v0.5.1-windows-x86_64.zip` |
| macOS (Apple silicon) | `transit-v0.5.1-macos-arm64.dmg` (holds `transit.app`) |
| macOS (Apple silicon), bare binary with `audio-bench` | `transit-v0.5.1-macos-arm64.tar.gz` |
| Linux (x86_64) tarball with `audio-bench` | `transit-v0.5.1-linux-x86_64.tar.gz` |
| Linux (x86_64) AppImage | `transit-0.5.1-linux-x86_64.AppImage` |
| Linux (x86_64) Debian and Ubuntu package | `transit-0.5.1-linux-x86_64.deb` |
| Linux (x86_64) Fedora and RPM package | `transit-0.5.1-linux-x86_64.rpm` |

A `.AppImage.zsync` file sits next to the AppImage for delta updates. Every archive carries `audio-bench`, which measures your interface (round trip, jitter, xruns).

All builds are unsigned. On Windows, SmartScreen shows "More info", then "Run anyway"; the Windows build includes native WASAPI and native ASIO. The macOS app is ad-hoc signed and not notarized; if macOS blocks it, run `xattr -dr com.apple.quarantine /Applications/transit.app`, or right-click it and choose Open. On Linux, make the AppImage executable (`chmod +x`) and run it, or install the .deb or .rpm with your package manager; none of the Linux packages are signed. The Linux builds carry the native JACK backend (#55): it talks to a running JACK 2 or PipeWire server (transit never starts one), and Auto prefers it when a server is up, including PipeWire's, whose own JACK library is probed first when its server runs. More Linux reports are wanted in #55: run `transit --report` and tell us how it went.
