# transit v0.7.0

This is a feature release, and the Sampler release. transit is alpha-quality software and the session format may still change, so back up anything you care about. **Upgrading:** clip group files and track presets saved before 0.7.0 read in 0.7 only; in 0.7, import each clip group file you want to keep and export the clips again, and load each track preset and save it again, before moving to a later version ([Upgrading to 0.7.0](https://github.com/transit-audio/transit/blob/main/docs/user-guide.md#upgrading-to-070)).

v0.6.0 shipped racks, the MIDI effect slot, the ported instruments and effects, take lanes and the Filter insert ([v0.6.0 notes](v0.6.0.md)); v0.6.1 and v0.6.2 were patches for plug-in editors. What is new here: the Sampler is rebuilt as one kit with three views (Pads, Slices and Instrument) and the old one-sample Sampler is removed (Breaking); kit presets; DAWproject open and export; the inherited file tags and fork names are retired (Breaking); Opus export; a reworked Bounce in Place; Low Latency mode; vertical track zoom; transport from MIDI devices; the device design language on the Macro Oscillator, the Compressor and the mixer strip; and a long list of fixes. Two Linux fixes ship unconfirmed on the setup they were reported from (see Fixes and Known issues).

## Highlights

- **The Sampler is one kit with three views: Pads, Slices and Instrument.** A new Sampler opens as an empty kit on the Pads view.
  The view switch changes only the view; all three edit the same kit. Pads: four banks of sixteen pads (A1 to D16) with names, choke groups, mute and solo, Clear pad and Reset note, a per-kit Start note (a new kit starts at MIDI note 36, C1, the General MIDI kick), and Load kit, which fills pads from a folder of WAV, AIFF or FLAC files. Drop a file from the browser onto a pad, or onto the empty Slices bench or Instrument key map. Samples keep their native sample rate (see Fixes).
- **Slices: click to hear a slice; Instrument: key and velocity zones with layers and round robin.**
  Slices shows the loop with numbered flags. Click the waveform to hear the slice under the pointer while you hold the button; in Manual, double-click to add a marker and drag its handle to move it; Auto detects from cue points, transients or a grid and previews the result before you take it. A thin line moves through the waveform at each sounding note, so you can see where a hit sits. Slices to pads puts the slices on pads; Create clip writes them as a MIDI clip. Each slice can loop, forward or ping-pong, with a crossfade. The Instrument view shows every zone as a rectangle over the keys and velocities it plays: drag its edges and its root, set its region and loop with a crossfade, its edge fades, and group zones into velocity layers with round-robin alternatives (sequential, or random with a seed you set). Every edit is one undo step ([ADR 0041](https://github.com/transit-audio/transit/blob/main/docs/adr/0041-sampler-one-instrument-three-views.md)).
- **Sampler kit presets.** The title bar saves and recalls a whole kit as a `.tkit` file.
  The Sampler's title-bar preset browser saves and recalls the whole kit (pads, zones, slices and both marker sets, groups and round robin, every setting, the pad start note) as a `.tkit` file in the settings folder's `presets/sampler`. Samples are referenced by their file paths, not copied: relative when they sit beside or below the kit file, else absolute. A recall is one undo step, and a run of previous and next steps is one undo step too; transit asks first only when the kit has loaded pads and changed since its last recall or save. Deleting a kit file, and Save As onto the name of an existing kit, ask first. A sample that moved, changed or cannot be read loads in the missing state (hatched on the Pads view, `Kick 01.wav is missing`), the note names the path looked for, and the rest of the kit plays. Control channel: `mix.sampler_kit_save` and `mix.sampler_kit_load`; the folder fill `mix.sampler_load_kit` is now labeled Load Kit Folder (#467).
- **Load kit asks before it touches loaded pads:** Replace, Fill free pads or Cancel, each with a preview.
  Load kit... on a kit that already has loaded pads asks what to do once the folder is picked: **Replace** makes the folder the kit from pad A1 on (each pad it fills is cleared first; later pads, the slice markers and the slice loop stay), **Fill free pads** (the default) leaves the loaded pads alone and is unavailable, with the reason, when the folder has more files than free pads, and **Cancel** changes nothing. The question previews the pads of each choice and counts the loaded pads and slices Replace would replace; either choice is one undo step. Control channel: `mix.sampler_load_kit` takes `replace: true` (#465).
- **DAWproject open and export.** Open a `.dawproject` as a new session, or export one with editable MIDI and rendered audio stems. Contributed by @BlueJayLouche.
  File > Open takes a `.dawproject` and opens its tracks, mixer settings, note clips, MIDI expression, tempo and meter, and markers as a new, untitled session; what the importer does not support is counted in the load report (K117). File > Export DAWproject... writes those editable parts, plus a full-length 32-bit float WAV stem for each audible audio and instrument track, so device processing survives even though the devices, routing, groups and parameter automation are not exported. An export was opened in Bitwig during review (#261, #377, #457).
- **Breaking: clip group files and track presets carry transit's name.** Files saved before 0.7.0 read in 0.7 and convert when you write them again; 0.8.0 and later refuse them.
  transit inherited two file tags from the SoundCraft fork: clip group files (`file.export_clip_groups`) were tagged `soundcraft.clipgroup` and track presets (`track.save_preset`) `soundcraft-track-preset`. From 0.7.0 transit writes `transit.clipgroup` and `transit-track-preset`; new clip group files are named `.tclips` and new track presets `.tpreset`. Every 0.7 release still reads the old files: reading one leaves it unchanged, and the status line and the command result's `note` say to import it and export the clips again (or load the preset and save it again) "to keep it opening in 0.8.0 and later". From 0.8.0 an old file is refused with "This file was saved by a version before transit 0.7.0. Open and save it in transit 0.7.0 first", with a link to this release. A file with a tag transit does not know is refused with a message naming the tag, and one from a newer transit says so. Sessions are not affected. Session files now register as `application/x-transit-session`; on Linux, a default app you set by hand for `.transit` files needs setting once more. Files written by 0.7.0 do not open in 0.6.x ([ADR 0049](https://github.com/transit-audio/transit/blob/main/docs/adr/0049-inherited-file-identifiers-retire.md), K115).
- **Breaking: the old one-sample Sampler is gone.** An older session opens with an empty Sampler kit in its place.
  Opening an older session gives each one-sample Sampler an empty Sampler kit: its sample assignment and settings are dropped, and so are the automation, MIDI mappings and rack macros that pointed at them. The sample file stays in the session (it is in the Clip List) and can be dropped onto a pad again. The load notes name every affected track. The control-channel commands `mix.sampler_load` and `mix.sampler_clear` are removed: use `mix.sampler_zone_source` or `mix.sampler_load_kit`. Tracks imported from an older session, and track presets that hold the old Sampler, get the same empty kit; an import does not bring the sample file along. User pages that pointed at the old settings are dropped too. Built-in Sampler user presets are retired: each startup logs one line per old preset, and the files stay on disk. The Sampler's presets are now kit files (above). A session saved by this version and opened in v0.6.2 or earlier warns that it needs `sampler_patch`, has a silent Sampler, and loses the empty kit if saved there ([ADR 0041](https://github.com/transit-audio/transit/blob/main/docs/adr/0041-sampler-one-instrument-three-views.md), #455).
- **Breaking: transit's own names replace the fork's.** Environment variables start with `TRANSIT_`, plug-ins see the host "transit", and every plug-in is scanned once more.
  The environment variables that began with `SOUNDCRAFT_` now begin with `TRANSIT_` (the control server prints `TRANSIT_CONTROL_PORT=`, and the CLI reads it), and the `SOUNDCRAFT_NO_PREFS` and `SOUNDCRAFT_RENDER_*` aliases are gone. CLAP and VST3 plug-ins now see the host name "transit" (it said "SoundCraft"), so a plug-in that keeps settings per host may show its first-run dialog or per-host defaults again once. The plug-in scan cache lives only in transit's own settings folder: the first launch rescans every plug-in, and the cache in the old `SoundCraft` folder is no longer read (K114). The MCP server reports its name as `transit`. Nothing here touches a session file.
- **Opus export.** Bounce the mix, stems or clips as `.opus` at 96 to 256 kb/s. No MP3, on purpose.
- **Bounce in Place, reworked:** to a new or an existing track, the source left, muted or hidden, and selected clips on their own.
  Track > Bounce in Place opens a form: the destination is a new track under the source or an existing audio track, and the source is left as it is, muted (the default; its plug-ins keep running), muted and deactivated, or hidden. Bounce in Place in the clip menu or the Edit menu prints only the selected clips' span. The source's clips and takes are always kept, and one Undo restores the whole operation.
- **Low Latency mode** bypasses the longest effects on armed and monitored tracks while you play, up to a limit you set.
  Turn it on in the transport bar or Options. It bypasses eligible software inserts on armed or monitored tracks, their downstream buses and the master, largest reported latency first, until each live route is within the Low Latency limit (Audio Devices > System). Instruments, MIDI effects, hardware inserts and your own bypass settings are left alone; bounces, freezes and stems always use the full chain. The mode is saved per machine, never in the session. An output path can also be marked Live (no shared padding) to hear a cue without waiting for slower outputs.
- **Vertical track zoom** from 16 to 440 points, saved in the session, and **View > Grid Over Clips**.
  Drag a track header's bottom edge (Alt resizes every track), Alt+wheel over one track, Alt+= and Alt+- for the presets, View > Track Height to reset. Sessions from older builds that used the default height open at 88 points per track; Reset Track Heights returns them to 46. Grid Over Clips draws the grid above the clips as one structure carrying the tempo, meter and triplets; off by default.
- **Piano roll:** several MIDI clips at once with Focus Mode (contributed by @BlueJayLouche), Fold to scale on F, and a Middle C setting.
  Select several MIDI clips and double-click one (or Ctrl+Alt+K): up to 16 open together, each in its color, edited together in one undo step; N toggles Focus Mode, or hold it, so only the foreground clip is edited (#329). F folds the view to the scale, and Shift only adds to the selection (#421). Options > Middle C names MIDI note 60 C3 (the default) or C4 in every transit window; sessions and mappings keep MIDI numbers.
- **Transport from MIDI devices:** MMC and MIDI Start, Stop, Continue and Song Position drive the transport, with Learn for note or CC buttons.
  Connected MIDI inputs honor MMC Play, Stop, Record, Pause, Fast Forward, Rewind and Locate, and MIDI Start, Stop, Continue and Song Position, without a mapping or an armed track. Audio Devices > MIDI turns this off per device and sets the MMC device ID; Learn Play, Learn Stop and the other transport targets take a controller button. These settings are saved per machine, never in a session.
- **A new look for devices:** the Macro Oscillator, the Compressor and the mixer strip follow the device design language. Dark only for now.
- **Main bus monitoring:** Mono, Dim and Ref on the main bus strip, and an integrated loudness readout (LUFS) under it.
- **Count-in pickups:** notes you play during the record count-in are kept, and the clip starts at the first one, as in Logic (#327).

## Fixes

- **Sampler samples keep their native sample rate.** A session saved after this change and opened in an earlier alpha build misplaces the regions (cues, slices, loops) of native-rate samples, because that build reads their positions at the session rate. `clip.place_source` refuses a source at another sample rate than the session (import the file to the timeline instead), and a damaged session that stores rate 0 for a Sampler source reads it at the session rate (#449, #451).
- Slices: Auto detection no longer places markers where no hit starts. A low attack hidden under brighter material gets its marker at its start, and the audio is read as if silence came before it, so a loop that starts on a hit no longer gets a marker inside that hit (#468).
- Sampler: a file dragged from the browser lands on an empty Slices bench or Instrument key map, not only on pads (#464); a newly inserted Sampler opens as an empty kit on the Pads view and no longer shows the old one-sample panel (#454); a pad can be cleared and its note reset (#438).
- Linux, unconfirmed: recording through ALSA under PipeWire. A record start that runs ahead of the input now waits for the input instead of being refused, the input of PipeWire's ALSA devices (`default`, `pipewire`, `pulse`) opens in stereo instead of its widest upmixed width, and a refused start logs both clocks' figures (#429). It is fixed against the report but not confirmed on the setup it came from; please report back (below).
- Linux, unconfirmed: transit calls the JACK library whose client actually connected (PipeWire's, found the way `pw-jack` finds it) instead of whichever `libjack` was loaded first, so `pw-jack` should no longer be needed (#430). Not yet tested against a live PipeWire server with both libraries installed (below).
- Looped MIDI clips: repeats land on their ticks, so the first note of a loop no longer fires twice at the wrap (a level spike on every repeat), and the two halves of a split looped clip no longer both play the note on the cut (#422).
- Count-in: notes released during the count-in before the session start are left out of the take, and the status line says how many, instead of being squashed into slivers on the first tick (#440).
- Prints: a mono print no longer gains 0.01 dB from the pan law, an offline print starts from a settled chain instead of a ramp, and Bounce in Place refuses an inactive source instead of printing silence (#332, #333).
- Mixer: the strip meter draws its RMS layer from the engine (#395), the peak-hold line falls after its hold time instead of snapping (#413), the docked mixer has a horizontal scroll bar (#414), the aux divider sits centered in its gap (#415), and the peak readout turns hot only above 0 dBFS (#359).
- Hardware inserts on the master track process: before, they were skipped. They count in the shared latency (#322).
- Menus and windows: the top menus get their inner padding back (#386), context menus and popups use the same row style (#409), a menu without checkable rows has no empty check gutter (#418), the piano roll header controls share one center line (#412), the Audio Devices diagnostics lines no longer overdraw each other (#307), and Enter and Escape answer modal questions.
- Lower panes: Mixer and Devices toggle independently and can both be open.
- Files: Save As, Open and Bounce start in the session's folder (#385).
- Clipboard: opening, creating, closing or reverting a session forgets copied audio clips, so a paste can no longer place clips whose sources belong to the previous session (#476).
- Arrangement: Delete after clicking a track header removes the track, not a still-selected clip (#310); an empty-grid click in the piano roll no longer moves the playhead (#316).
- Take lanes: each lane header names the span its take plays, and clips in a stack carry their take number in the label (#317).
- Piano roll Scale mode: Shift only selects, dragged notes follow the pointer, and the folded view shows every row a note can go on (#421).
- Plug-ins: a CLAP or VST3 file that changed on disk since it loaded is refused until transit restarts, instead of running new bytes under old code (#348, #380, K118, K119; contributed by @BlueJayLouche); on macOS, CLAP editors that offer only an embedded Cocoa view (such as JUCE-built ones) open (K116; contributed by @BlueJayLouche); a plug-in whose destructor panics no longer stops the plug-in host thread: destroy, release and editor jobs catch the panic and log it with the plug-in's name (contributed by @jay23606).
- MIDI effects: when the note delay's carry is full, a release no longer arrives before its own note-on, so the note no longer hangs (#281; contributed by @jay23606).
- Windows audio: the ASIO list comes from the registry, so listing drivers no longer loads them (loading one another app is using can take the interface away from it), and transit releases its driver at quit (#363).

## Known issues

See [known issues](https://github.com/transit-audio/transit/blob/main/docs/known-issues/README.md). Row K115 has the dates for the inherited file tags.

- **Linux fixes are unconfirmed.** #429 (recording through ALSA under PipeWire) and #430 (the JACK library) were fixed against the report, but not confirmed on the setup they came from. If you run Linux with PipeWire, please try both and report back with Copy diagnostics (Audio Devices) or `transit --report` attached: [#429](https://github.com/transit-audio/transit/issues/429), [#430](https://github.com/transit-audio/transit/issues/430). The known-issue rows are `issue-429` and KC5.
- **Load Kit Folder holds the window while it decodes.** After you choose Load kit, Replace or Fill free pads, transit does not respond until the folder's files are decoded; a large folder or a slow drive makes this visible. Kit preset recall waits the same way. Nothing is lost, and a load with progress and Cancel is planned (`issue-450`).
- **A Slices playhead can stay drawn.** If audio rendering stops while a slice is sounding (for example after an audio device error), the last playhead line stays drawn until rendering resumes or the Sampler window is reopened (`issue-470`).
- Count-in notes need room before the record start: recording from the very start of the session, a note released during the count-in is left out of the take (`issue-440`; a zone before bar 1 is planned, #441).
- Sampler limits for now: a sample over 30 seconds or 32 MiB of decoded audio is refused for a zone, and a kit holds at most 128 MiB of distinct audio (K110); relinking a missing sample, SFZ import, the Shaper and Modulation sections and Expand to rack are not available yet.
- Windows opens audio through native WASAPI and native ASIO only; a device that only the old cpal path could open stays closed with the reason (K111).
- A file dragged in from the file manager has no drop position off Windows: it lands as soon as the pointer moves after the drop (K113).
