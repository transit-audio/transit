# transit v0.7.0

<!-- Skeleton (ADR 0049). The release housekeeping job fills the release summary, the remaining
Highlights, Fixes, Known issues and Checksums, and removes this comment. -->

This is a feature release. transit is alpha-quality software and the session format may still change, so back up anything you care about. **Upgrading:** clip group files and track presets saved before 0.7.0 read in 0.7 only; in 0.7, import each clip group file you want to keep and export the clips again, and load each track preset and save it again, before moving to a later version ([Upgrading to 0.7.0](https://github.com/transit-audio/transit/blob/main/docs/user-guide.md#upgrading-to-070)).

v0.6.0 shipped racks, the MIDI effect slot, the ported instruments and effects, take lanes and the Filter insert ([v0.6.0 notes](v0.6.0.md)). What is new here: the inherited file identifiers are retired (Breaking for clip group files and track presets).

## Highlights

- **Breaking: clip group files and track presets carry transit's name.** Files saved before 0.7.0 read in 0.7 and convert when you write them again; 0.8.0 and later refuse them.
  transit inherited two file tags from the SoundCraft fork: clip group files (`file.export_clip_groups`) were tagged `soundcraft.clipgroup` and track presets (`track.save_preset`) `soundcraft-track-preset`. From 0.7.0 transit writes `transit.clipgroup` and `transit-track-preset`; new clip group files are named `.tclips` and new track presets `.tpreset`. Every 0.7 release still reads the old files: reading one leaves it unchanged, and the status line and the command result's `note` say to import it and export the clips again (or load the preset and save it again) "to keep it opening in 0.8.0 and later". From 0.8.0 an old file is refused with "This file was saved by a version before transit 0.7.0. Open and save it in transit 0.7.0 first", with a link to this release. A file with a tag transit does not know is refused with a message naming the tag, and one from a newer transit says so. Sessions are not affected. Session files now register as `application/x-transit-session`; on Linux, a default app you set by hand for `.transit` files needs setting once more. Files written by 0.7.0 do not open in 0.6.x ([ADR 0049](https://github.com/transit-audio/transit/blob/main/docs/adr/0049-inherited-file-identifiers-retire.md), K115).

- **Breaking: the old one-sample Sampler is gone.** Opening an older session gives each one-sample Sampler an empty Sampler kit: its sample assignment and settings are dropped, and so are the automation, MIDI mappings and rack macros that pointed at them. The sample file stays in the session (it is in the Clip List) and can be dropped onto a pad again. The load notes name every affected track. The control-channel commands `mix.sampler_load` and `mix.sampler_clear` are removed: use `mix.sampler_zone_source` or `mix.sampler_load_kit`. Tracks imported from an older session get the same empty kit, and the sample file does not come along. Built-in Sampler user presets are retired: each startup logs one line per old preset, and the files stay on disk. The Sampler's presets are now kit files (below). A session saved by this version and opened in v0.6.2 or earlier warns that it needs `sampler_patch`, has a silent Sampler, and loses the empty kit if saved there ([ADR 0041](https://github.com/transit-audio/transit/blob/main/docs/adr/0041-sampler-one-instrument-three-views.md), #455).

- **Sampler kit presets.** The Sampler's title-bar preset browser now saves and recalls the whole kit (pads, zones, slices and both marker sets, groups and round robin, every setting, the pad start note) as a `.tkit` file in the settings folder's `presets/sampler`. Samples are referenced by their file paths, not copied: relative when they sit beside or below the kit file, else absolute. A recall is one undo step, and a run of previous and next steps is one undo step too; transit asks first only when the kit has loaded pads and changed since its last recall or save. A sample that moved, changed or cannot be read loads in the missing state (hatched on the Pads view, `Kick 01.wav is missing`), the note names the path looked for, and the rest of the kit plays. Control channel: `mix.sampler_kit_save` and `mix.sampler_kit_load`; the folder fill `mix.sampler_load_kit` is now labeled Load Kit Folder ([ADR 0041](https://github.com/transit-audio/transit/blob/main/docs/adr/0041-sampler-one-instrument-three-views.md), #467).

- **Load kit asks before it touches loaded pads.** Load kit… on a kit that already has loaded pads asks what to do once the folder is picked: **Replace** makes the folder the kit from pad A1 on (each pad it fills is cleared first; later pads, the slice markers and the slice loop stay), **Fill free pads** (the default) leaves the loaded pads alone and is unavailable, with the reason, when the folder has more files than free pads, and **Cancel** changes nothing. The question previews the pads of each choice and counts the loaded pads and slices Replace would replace; either choice is one undo step. Control channel: `mix.sampler_load_kit` takes `replace: true` (#465).

## Fixes

- **Sampler samples keep their native sample rate.** A session saved after this change and opened in an earlier alpha build misplaces the regions (cues, slices, loops) of native-rate samples, because that build reads their positions at the session rate. `clip.place_source` refuses a source at another sample rate than the session (import the file to the timeline instead), and a damaged session that stores rate 0 for a Sampler source reads it at the session rate (#449, #451).
