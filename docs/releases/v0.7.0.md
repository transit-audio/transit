# transit v0.7.0

This is a feature release. transit is alpha-quality software and the session format may still change, so back up anything you care about. **Upgrading:** clip group files and track presets saved before 0.7.0 open in 0.7 only; open and save each one you want to keep in 0.7 before moving to a later version ([Upgrading to 0.7.0](https://github.com/transit-audio/transit/blob/main/docs/user-guide.md#upgrading-to-070)).

v0.6.0 shipped racks, the MIDI effect slot, the ported instruments and effects, take lanes and the Filter insert ([v0.6.0 notes](v0.6.0.md)). What is new here: the inherited file identifiers are retired (Breaking for clip group files and track presets).

## Highlights

- **Breaking: clip group files and track presets carry transit's name.** Files saved before 0.7.0 open in 0.7 and convert when you save them again; 0.8.0 will refuse them.
  transit inherited two file tags from the SoundCraft fork: clip group files (`file.export_clip_groups`) were tagged `soundcraft.clipgroup` and track presets (`track.save_preset`) `soundcraft-track-preset`. From 0.7.0 transit writes `transit.clipgroup` and `transit-track-preset`, and new clip group files are named `.transitclips`. Every 0.7 release still reads the old files: importing one leaves it unchanged and the status line says "saved before transit 0.7.0; export these clips again" (or "save this preset again") "to keep the file opening after 0.8.0". From 0.8.0 an old file is refused with "This file was saved by a version before transit 0.7.0. Open and save it in transit 0.7.0 first", with a link to this release. Sessions are not affected. Session files now register as `application/x-transit-session`; on Linux, a default app you set by hand for `.transit` files needs setting once more. Files written by 0.7.0 do not open in 0.6.x ([ADR 0049](https://github.com/transit-audio/transit/blob/main/docs/adr/0049-inherited-file-identifiers-retire.md), K115).
