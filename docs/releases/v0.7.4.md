# transit v0.7.4

This is a patch release. transit is alpha-quality software and the session format may still change, so back up anything you care about.

v0.7.3 ([v0.7.3 notes](v0.7.3.md)) kept count-in pickups before bar 1 and made rate conversion band-limited. This one gives new instruments mixing headroom, ties input paths to the input device that actually opened, and reworks the JACK backend on Linux, with fixes found since.

## Before you upgrade

- ⚠️ **Instruments whose level was never set play quieter.** Existing Sampler tracks play 12 dB quieter: the Sampler has a new Output level, -12 dB by default, and a session saved before it existed has none stored. A Macro Oscillator, Modal Voice, Resonator or Texture Synth whose Level was never set (added from Add Track or an import and never touched) plays 6 dB quieter, at the new -12 dB default; one added from the browser or with a factory preset recalled on it stored its level and plays as before. A frozen synth track keeps its frozen level until it is unfrozen. Raise the Output or Level, or the track fader, once. Nothing is migrated (#753).
- ⚠️ **Input paths now belong to the input device that actually opened.** Output paths are kept. With WASAPI, or with an input that is a separate device from the output (ALSA, macOS), the input starts from the default paths ("In 1", "In 1-2" and so on); input paths you made by hand for such an input stay in the settings file, unused. A hardware insert or External Instrument measurement whose return input cannot be established says **Measure again** and counts no latency until you measure it again. Going back to v0.7.3 or older may show default input paths (#431, #759).

## Changed behavior

- File > Bounce… is now **File > Export Audio…**, with the same shortcut and dialog; Bounce in Place keeps its name (#744).
- The `session.open` error text starts `Could not open <path>:`, followed by the reason (#719).
- A factory preset that sets no level loads at -12 dB (#753).
- A track input that does not resolve to an input path of the open input is silent and refuses to record, naming the input; it never records another channel. Plain labels such as "In 3" or "In 3-4" still read those channels while the input has them, and never wrap around to other channels (#431).
- An input you chose that is not present opens no input on ALSA, macOS and native JACK: the output keeps running and Audio Devices names the missing input. WASAPI still records from the default input and says so (#431).
- On ALSA and macOS, two connected inputs with the same name cannot be told apart: the input records with default paths, nothing is saved for it, and no measurement applies through it. No measurement is taken or applied through an input without an identity (#431).
- An I/O path cannot take the name of a bus in the session (case is ignored) (#431).
- Right-clicking a clip shows clip actions only; the Add Track rows stay on the empty lane's menu (#728).
- `transit --help` (or `-h`) prints the flags and exits; an unknown option is an error that names it, where it used to start the full app. macOS's process serial argument is ignored (#741).
- Linux, native JACK under PipeWire: with a buffer size chosen, opening can pause up to an extra half second while transit waits for the server to apply it, and a graph rate other than the one transit prepared for costs one rebuild before any audio plays (#760).

## Highlights

- **New instruments start with headroom.** The Sampler has an Output level, -12 dB by default, shown in every Sampler view and automatable; its pads and zones stay at 0 dB as trims under it. The Macro Oscillator, Modal Voice, Resonator and Texture Synth start at -12 dB instead of -6 dB. Every way of adding a built-in instrument now stores its settings in the session, so a later default change cannot move saved sessions (#753).
- **Input paths follow the input device.** Switching to another input brings that input's own paths, and switching back brings the first ones back. Paths that need channels the input lacks are listed as unavailable, with why, and kept; when no input path can be used, **Add default paths** adds the missing defaults (#431, #759).
- **Audio > Monitor Armed Tracks.** On by default, as before. Turn it off when your interface does its own direct monitoring: arming an audio track then does not monitor it, recording is unchanged, and the track's Input Monitoring button still works. Saved per machine (#730).
- **Linux, JACK: patchbay links survive a reopen.** Links you or another program made to transit's ports come back after a buffer size or rate change, Reconnect or Apply; the ones that cannot come back are named (#431).
- **Linux, JACK: Show virtual devices.** Record an application, a sink's monitor or a virtual source (#431).
- **Linux, JACK under PipeWire: rate and buffer size are read from the running graph,** which should end the device reopening after every start; not yet run on a real PipeWire machine (#760).

## Linux: JACK and PipeWire

The JACK and PipeWire changes below have run against fake and test JACK servers only, not yet on a real PipeWire machine. A tester's check on this release decides what a following patch release fixes.

- **Links made in a patchbay survive a reopen.** Before transit closes its JACK client for a reopen, it notes which other ports are linked to its ports and links them again on the new client. Links on a side whose device changed, on a port the new device lacks, or to a port that went away are not restored, and the status line and Audio Devices say which (#431).
- **Show virtual devices** under the Input list in Audio Devices (off by default) also offers every program or virtual device that has audio output ports and no hardware ports, by its client name; a sink's monitor is listed as System Audio. Ticking it reopens nothing. When a virtual device comes back with other ports, or the same ports in another order, the paths over the changed ports stay off (silent, refusing to record) until the original ports return or you press **Use the current ports** on the I/O paths page while stopped. Another program's processing delay is not compensated (#431).
- **Under PipeWire the rate and buffer size are read from the running graph,** from transit's active client, instead of before the client was active. A buffer size you chose that arrives within half a second of opening is the device's, so neither reopens the device after its start (#760).
- **Audio Devices shows Graph and "Latency reported at startup" lines** (display only: what the server reports, not a measurement, and no compensation changes), and checks transit's own links once after the device starts, naming a link it did not find. Each open makes one probe client (#760).

## Fixes

- At a converted device rate (the device runs at a rate other than the session's), starting Play or Record from a stop no longer cuts audio that is already sounding: the converter keeps running through the start. Confirmed by the maintainer on hardware with a 44.1 kHz interface and a 48 kHz session, for Play and for Record without a count-in. Record with a count-in and Locate are still open (see Known issues) (#725).
- Audio Devices > I/O paths: default input paths were missing after an older build had saved the table, and the input paths did not follow a change of input device. Both are fixed by the per-input paths above ([escape record](../escapes/issue-690.md), #759).
- Audio Devices: the status card no longer covers the button row when the status is long (seen on ASIO at 150 percent scaling); it scrolls in the space above the buttons and Copy diagnostics stays in reach (#732).
- A session this build cannot read says so in a sentence naming the file, its format version and what to do; a session saved by a newer transit names both format versions. Crash recovery says once why an autosave could not be read (#719).
- Crash recovery says how many notes played before the count-in were not recorded, as a normal stop does, and counts in the interface read right for one ("1 note", "1 audio file is missing") (#704).
- Macro Oscillator: the LFO display's trace follows the Rate knob over its whole range; it stopped stretching below about 0.25 Hz and compressing above about 4 Hz (#751).
- Real-time render: the progress count no longer counts one bar too many when the range ends on a bar line (#693, contributed in #754).
- The About window, README, attribution file and site carry the VST, ASIO, Mac and macOS trademark notices (#737).
- `audio-bench --list-devices` lists native WASAPI and ASIO devices through the app's own listing.

## Under the hood

- The render pool's wake cursor moves past the last worker it visited, so a pass no longer visits a just-woken worker again (#721, contributed in #750). Correctness was not affected.
- Native WASAPI caches the capture pairing per open instead of enumerating devices again on each query.
- A dialog layout gate: no button covers another button or text, and every button sits inside its window, at 1x and 1.5x (#735).
- Complete state records for the built-in instruments and MIDI effects in tests, which shorten the scheduling-equivalence test's post-fault window, and the realtime tests in their own CI step (#742).
- The typed transport lifecycle ([ADR 0062](../adr/0062-session-host.md), #739): groundwork, not yet wired into the app.
- Dependency licenses are checked in CI (reporting only until its first green run) and advisories in a weekly report; unused DSP code removed and the plug-in hosts' fade gate and scan cache shared (#736).
- The file-size gate exempts lookup tables it proves hold only data; the cpal patch fork moved to the project's organization at the same pinned commit; the known-issues list was checked against the code and closed or fixed entries removed.

## Known issues

- **At a converted device rate, Record with a count-in still restarts the converter when the count-in begins,** so audio sounding at that moment gets a short splice (about 0.4 ms skipped), and Locate while playing restarts it too. Still open (#725).
- **Audio clips still start at bar 1.** Audio played during the count-in stays in the take's file before the clip's start, and Bounce in Place of a take with count-in pickups prints from bar 1. Still open (#442).
- **Linux, JACK:** the virtual-device and PipeWire changes have not yet run on a real PipeWire machine (see above). With Show virtual devices, a second running transit can appear as a virtual device, a different stream that reuses the same port names is not detected, and another program's delay is not compensated ([jack-virtual-devices](../known-issues/entries/jack-virtual-devices.md)).
- **Linux, JACK:** a stored loopback calibration that does not apply says "measure again", but no build can measure a loopback calibration on the JACK system, so the note has no action to take. Such a record can come only from a hand-edited settings file or another system's record with the same device name ([jack-calibration-measure-again](../known-issues/entries/jack-calibration-measure-again.md)).
- **With Monitor Armed Tracks off, an armed track's meter does not show the input level** before recording, and turning the option or Input Monitoring on or off while audio sounds switches at once, with no ramp (#730).
- **macOS: Audio Units are not usable yet** (no editor window, no sidechain or extra buses). Use the VST3 or CLAP build of the plug-in (#755).
- **Conform to Tempo and Elastic Properties have no menu entry;** the per-clip stretch mode replaces them (#336).
- **macOS:** with an older transit disk image still mounted, the new one's window can show the old background. Eject the old one first (#727).
- Sessions with a pre-count zone or unplaced takes still need v0.7.3 or later (see the [v0.7.3 notes](v0.7.3.md)).

The full list is in the [known issues](../known-issues/README.md).

## Verifying a download

Every file of this release carries a build provenance attestation: a signed record that the file was built by this repository's release workflow from the tagged commit. With the GitHub CLI:

```
gh attestation verify <file> --repo transit-audio/transit
```

It says where and from what a file was built, not that the build is free of defects. The macOS build is also signed and notarized; the Windows installer and program are not code-signed yet. Details are in [docs/releasing.md](https://github.com/transit-audio/transit/blob/main/docs/releasing.md).
