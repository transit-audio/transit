# transit v0.7.5

This is a patch release. transit is alpha-quality software and the session format may still change, so back up anything you care about.

v0.7.4 ([v0.7.4 notes](v0.7.4.md)) gave new instruments mixing headroom and tied input paths to the input device that actually opened. This one adds Split to Mono Tracks, makes dialogs hold the app while they are open, gives plug-in editors a Scale menu on Windows and keeps hardware insert latency aligned at a converted device rate, with fixes found since.

## Changed behavior

- A modal dialog now holds the app until it is answered: it opens centered and cannot be dragged (Quantize notes, Hardware Insert and Keyboard Shortcuts could be dragged before), and keys, shortcuts, the transport and clicks behind it do nothing. A file dropped from the file manager while a dialog is open is ignored. In Recover unsaved work, Escape means Later; in Quantize notes, Enter means Apply (#770).
- A file dropped from the file manager lands the way a browser drag does: on the track under the pointer, at the pointer's time on its lane, or on a new track when dropped below the tracks; elsewhere it still lands at the cursor. A drop on a track that takes no audio (a MIDI or instrument track) is refused with the reason on the status line, where it used to land at the cursor. A dropped `.transit` or `.dawproject` file asks first to save unsaved changes, as File > Open does, and opens alone; the status line says how many other files were left out (#767).
- A hardware insert or External Instrument measurement now remembers the device rate it was taken at, and says **measure again at this rate** when the device runs at another rate. A measurement saved by v0.7.4 or older recorded no rate, so it shows that hint at every rate, the session's own included, until you measure it once more. Its figure is still used as stored meanwhile (#709).
- An armed audio track's meter shows its input level while stopped and while recording, whether it is monitored or not. Unmonitored, that is the input as the take records it, before the track's inserts and fader; nothing you hear changes (#730).

## Highlights

- **Split to Mono Tracks.** Right-click a stereo or wider audio clip and choose Split to Mono Tracks: each channel goes to a new mono track below it, named `<track> L` and `<track> R` (numbered past stereo), with the clip's timing, fades and gain. The original is muted, and the whole split is one undo step. A stereo clip's two tracks are panned hard left and right, so the split sounds as the stereo track did at its default pan. Inserts are not copied, and the status line says so when the track had any (#767, #771).
- **Dialogs hold the app.** A dialog dims everything behind it in transit's main window, and nothing behind it reacts until you answer it. Escape and Enter answer only the top dialog. Keys and buttons held when a dialog comes up are let go at once, so a held slice audition, a repeating step-entry rest or a momentary Focus Mode stops (#770).
- **Plug-in editors: a Scale menu (Windows).** On a scaled display, the ≡ menu of a plug-in window has a Scale submenu: Auto, or 50% to 200%, remembered for that plug-in on this machine. Its first line says how the editor is drawn now. An editor that takes the host's scale draws itself sharp at it. For one that cannot, **Stretched by Windows** enlarges its 100% drawing to the display's scale. Only that explicit pick stretches; Automatic never does (#153).
- **Hardware inserts and External Instruments stay aligned at a converted device rate.** On a device whose input and output run together (native ASIO, JACK) at 1x, the part of a round trip that comes from rate conversion is now recomputed for the rate in use, so a measurement stays sample-aligned when the device runs at another rate than the session's. The **measure again at this rate** hint still shows, because the interface's own delay can change with the rate. With input and output on separate streams (WASAPI, or an input on another device), a figure is used as measured ([ADR 0015](../adr/0015-io-routing-abstraction.md), #709).
- **Bounce in Place has a new dialog.** Grouped choices, the track picker beside Existing track, the range in bars and beats, and Bounce as the default button. When the source choice would silence content before bar 1, the dialog warns you on the Source row before you confirm (#731).
- **The armed track's meter shows the input** even with Audio > Monitor Armed Tracks off, so you can set levels on an interface that does its own direct monitoring (#730).

## Not yet confirmed by hand

These changes are covered by tests but still wait for a hands-on check by the maintainer.

- **Hardware insert and External Instrument latency at a converted device rate** (#709): covered by tests through a fake device that has no delay of its own, so how a real interface's delay changes with the rate has not been measured on real hardware.
- **Plug-in editor scaling** (#153): an earlier build was tried on a 150 percent display, and that check found the black stretched editor that led to "Automatic never stretches". The Scale menu as shipped has not yet been checked against real plug-ins on a scaled display.
- **The graphics fallback** (#762): checked through a simulated failure only, not yet on the machine that showed the failure, so whether transit recovers there is unconfirmed.
- **Dialogs holding the app** (#770): the behavior is covered by tests, but whether the dimmed background reads plainly as "this is a dialog" has not yet been judged by eye.
- **Split to Mono Tracks** (#767): a test shows a split stereo clip renders exactly as its stereo track did, but the results have not yet been checked by ear.

## Fixes

- When transit cannot start the graphics backend it asked for, it no longer exits without a word. A backend chosen with `WGPU_BACKEND` that fails falls back once to the platform default, with a note on the status line; when nothing starts, Windows shows an error window (other systems print to standard error) naming the failure and the log file. The [troubleshooting guide](../troubleshooting.md) covers a common cause, a stale Vulkan driver after a GPU driver update (#762).
- A mono track's mixer meter showed two identical bars that ignored the pan; it now shows one. Instrument tracks, which play in stereo, keep two (#768, contributed).
- An audio device reopen (a buffer size or rate change, Reconnect, Apply) no longer closes and reopens every MIDI input: the inputs stay open, and notes, transport buttons, MIDI Learn and mapped controls that arrive while no device is open do nothing afterward. Run by the maintainer on Windows with a real controller through buffer size changes; not yet run on Linux. MIDI outputs still close and reopen (#760).
- Linux, JACK under PipeWire: the device reopened in a loop at every start on the first PipeWire desktop that ran v0.7.4. transit now links its ports first and waits, at most half a second, for the buffer size the graph settles on, and remembers it for the next open; a chosen buffer size the graph does not run is shown as declined. Checked against a simulated server only; not yet confirmed on a PipeWire machine (#760).
- Right-clicking another target while a context menu is open (another clip or lane, for example) replaces the menu in one click; the new menu used to flash and close (#769).
- At a converted device rate, a take recorded before the device clock was ready (marked approximate) now stays within one block of what was heard (#725).
- The About window is wider, so its small print wraps to a few rows, and it fits small screens (1366x768, and 1280x720 points) with the notices list open.

## Under the hood

- A gate checks that every command is reachable from the interface or is a listed exception (#734), and the dialog layout check covers MIDI Monitor, Callback Telemetry, Keyboard Shortcuts, the plug-in not responding message, Hardware Insert and the kit questions (#735).
- Complete state records in tests for the built-in effects: Room and Plate Reverb, Filter, Compressor, Expander/Gate, Gain, Trim, EQ 7-Band, EQ 1-Band, Saturator and Tuner (#742).
- Decision records accepted for work that comes next: clip tempo and Follow Tempo ([ADR 0063](../adr/0063-clip-tempo-and-follow-tempo.md), #336) and audio clips in the pre-count zone ([ADR 0052](../adr/0052-pre-count-zone.md) amendment, #442). Neither is built yet.
- The JACK backend's records follow the PipeWire start changes ([ADR 0021](../adr/0021-native-linux-audio-over-the-jack-client-api.md), #760), and the #725 and #709 known issues state their remaining limits.

## Known issues

- **A dialog can open behind a plug-in editor window** (Windows): plug-in editors are separate windows that the dimmed background cannot cover yet, so a dialog opened while an editor is in front can be hidden behind it. Making transit's dialogs real windows that come to the front is planned as its own design (#770).
- **At a converted device rate, Record with a count-in still restarts the converter when the count-in begins,** so audio sounding at that moment gets a short splice (about 0.35 to 0.4 ms skipped with a 48 kHz session on a 44.1 or 96 kHz device; the size depends on the rate pair), and the first click's timing does not move. Locate while playing restarts it too, cutting audio that sounds across the locate. Both are accepted limits; run the audio device at the session's rate to avoid them ([issue-725](../known-issues/entries/issue-725.md), #725).
- **Hardware insert and External Instrument latency at another device rate:** a measurement used at another rate than it was taken at still says "measure again at this rate". With input and output on separate streams the figure is used as measured. After playing at another speed with the device at another rate than the session's, figures say "timing changed: stop at 1x, then measure again" until you stop or locate at 1x ([issue-709](../known-issues/entries/issue-709.md), #709).
- **The graphics fallback acts only on an error the graphics library returns;** a crash inside the graphics library itself gets no retry and no message ([issue-762](../known-issues/entries/issue-762.md), #762).
- **Stretched by Windows can show a black editor** with plug-ins drawn by the graphics card. Pick The plug-in's own zoom (no stretch) or Automatic in the same Scale submenu; the editor comes back on its next open ([editor-stretch-black](../known-issues/entries/editor-stretch-black.md), #153).
- **macOS and Linux: the plug-in window has no Scale menu yet.** macOS scales editors itself; on Linux only editors that take a scale from transit can be scaled ([K74](../known-issues/entries/K74.md)).
- **macOS and Linux: a file dropped from the file manager lands where the pointer next reports after you let go,** so a pointer moved before then imports the file onto the track it reached, or is refused there when that track takes no audio ([K113](../known-issues/entries/K113.md)).
- **Audio clips still start at bar 1.** Audio played during the count-in stays in the take's file before the clip's start, and Bounce in Place of a take with count-in pickups prints from bar 1. The decision record is accepted; not built yet (#442).
- **Linux, JACK under PipeWire:** one case still reopens in a loop: when only a link another program made to transit's ports puts transit on a graph at another sample rate. transit stops after three attempts and Audio Devices offers Reconnect; link transit's ports through its own device choice instead, or set the graph's rate ([K69](../known-issues/entries/K69.md)). The virtual-device limits from v0.7.4 still apply ([jack-virtual-devices](../known-issues/entries/jack-virtual-devices.md)), and a stored loopback calibration that does not apply still says "measure again" with no way to measure on the JACK system ([jack-calibration-measure-again](../known-issues/entries/jack-calibration-measure-again.md)).
- **Turning Monitor Armed Tracks or Input Monitoring on or off while audio sounds switches at once,** with no ramp (#730).
- **macOS: Audio Units are not usable yet** (no editor window, no sidechain or extra buses). Use the VST3 or CLAP build of the plug-in (#755).
- **Conform to Tempo and Elastic Properties have no menu entry;** the per-clip stretch mode replaces them (#336).
- **macOS:** two transit disk images mounted at once can show each other's background. Eject the older one first (#727).
- Sessions with a pre-count zone or unplaced takes still need v0.7.3 or later (see the [v0.7.3 notes](v0.7.3.md)).

The full list is in the [known issues](../known-issues/README.md).

## Verifying a download

Every file of this release carries a build provenance attestation: a signed record that the file was built by this repository's release workflow from the tagged commit. With the GitHub CLI:

```
gh attestation verify <file> --repo transit-audio/transit
```

It says where and from what a file was built, not that the build is free of defects. The macOS build is also signed and notarized; the Windows installer and program are not code-signed yet. Details are in [docs/releasing.md](https://github.com/transit-audio/transit/blob/main/docs/releasing.md).
