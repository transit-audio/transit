# transit v0.7.2

This is a patch release (in progress). transit is alpha-quality software and the session format may still change, so back up anything you care about.

v0.7.1 ([v0.7.1 notes](v0.7.1.md)) fixed audio files, levels, the Sampler's engine and typed values. This one continues with fixes found after it.

## Highlights

- **Sample-rate conversion no longer depends on the audio block size.** When the device runs at a different rate than the session, the output is the same whatever the callback size, so a ramp no longer carries wrong frames at block edges.
- **Recovered sessions and long takes save safely.** A session recovered after a crash keeps its long takes and offline files pointing at its own folder, and Save As copies long take files into the new session folder.
- **Preset names keep their dots.** "Bass v1.5" and "Bass v1.2" are two presets.

## Fixes

- Playback: the device-rate converter renders the next block as soon as an output frame needs it and keeps the previous block's last frame, so its output no longer depends on where blocks are cut; equal rates stay bit-exact. The converter is still linear interpolation, and its measured limits are listed under known issues (#525).
- Presets: a dot in a saved preset name is part of the name, so "Bass v1.5" and "Bass v1.2" write two files; `track.save_preset` appends `.tpreset` unless the name already ends in it, and a device preset's Save As appends the format's extension. Saving over an existing preset file is now refused (see the next line) (#487).
- ⚠️ **Saving a preset over a file that exists is refused unless the call says `replace: true`.** `track.save_preset`, `mix.sampler_kit_save` and `plugin.preset_save` used to replace the file without asking; now they fail with a message naming the file, and a script that overwrites on purpose passes `replace: true`, as `session.save_template` already has it. The Sampler's kit browser asks before it replaces a kit file, and Save on a loaded plug-in preset still replaces it (#487).
- Recovery: a session recovered from an autosave belongs to its own folder, not the deleted autosave folder, so the next save keeps the paths of long takes and offline files (#572).
- Save: Save As, Save Copy In and the first save of an untitled session copy a long take's file into the session's Audio Files when it lives anywhere else, checked and without replacing a file; if the copy fails, the save fails naming the file and the earlier session file stays as it was (#573).
- Save: after Save As (or the first save of an untitled session) copies a long take into the new session folder, the open session plays, renders and saves that take from the copy at once, with no gap if it is playing, and lets go of the old file, so the old folder can be deleted or its drive ejected without reopening the session. A later save whose take file has gone copies the file the session names instead of failing. If a take cannot be moved onto its copy, the save still succeeds and the status line says it, naming the take and the file it still plays from (with the first warning and a count when a save has several; all are in the log), and the next save moves it. Save Copy In still leaves the open session on its own files (#629).
- Recording: Record pressed while the cycle is already playing, anywhere in the loop, cuts the audio take into one take per lap, as it does MIDI: the first take runs from where you pressed Record to the loop end, the rest are whole laps. It used to make one clip that ran on past the loop end (#567).
- Recording: cycle recording no longer drops everything after lap 1,000 without a word. Every lap is a take, up to 10,000 laps (over five hours of a one-bar loop in 4/4 at 120 BPM); when a recording reaches that, it stops by itself, keeping every lap, and the status line says it ended at its limit. Press Record to go on. A last lap shorter than an eighth of the loop is still not a take, but the status line now says so (#522, #634).
- Recording: while a cycle recording runs, the growing strip on each armed track shows only the lap being recorded, starting again at the loop start after each wrap, where that lap's take will be placed, and the live waveform under it is that lap's. MIDI recorded in laps from the loop start used to draw one strip on past the loop end, and audio recorded from inside the loop lost its strip after the first wrap (#634).
- Recording: recording runs at normal speed only. Record is refused while Half-Speed Playback plays, and the status line says "Cannot record at half speed: recording runs at normal speed only. Press Stop, then Record." Half-Speed Playback is refused while a recording is pending or under way ("Half-Speed Playback is not available while recording: recording runs at normal speed only."). If the transport is no longer at normal speed when a held start finally runs, the recording does not start and the status line says "Recording could not start: the transport was not at normal speed." (#522).
- Plug-ins: a preset picked in a hosted VST3 or CLAP plug-in's own editor no longer shows as modified at once. transit used to send the preset's values back to the plug-in slightly rounded (and, for VST3, back to its editor side too); now the plug-in gets exactly what it reported, and nothing at all where it already has the value (#651).
- Plug-ins (macOS): the app can load third-party VST3 and CLAP plug-ins. v0.7.1's app was signed so that macOS refused every plug-in not signed by transit itself, so the device menus said "No VST3 effects found" however many were installed; its signature now allows plug-ins signed by their own vendors, and the release build checks that it does. On every system, when a scan finds plug-in files and none of them loads, the device menu and the log now say how many were found and the first error, instead of "none found". Files that failed under an older build are loaded again by the first scan after updating, and Audio > Scan Plug-ins now rescans everything: every plug-in file is opened again and the scan cache is rewritten, so nothing is skipped; asked for while another scan runs, it runs right after that scan instead of being dropped (#659).
- Sessions: paths to recorded takes that were not placed now follow the same rules as every other file a session refers to. A take whose saved path is on another computer or drive, other than the session's own network share, stays listed as not placed, with a note, instead of being looked for.
- Playback: a long take played from disk whose file cannot be read (a drive unplugged, a file moved) no longer renders as silence without a word: bounces, exports and other renders that play it are refused with a message naming the take and its file, the audio health check lists it, and playback tries the file again the next time you press play (#523).
- Playback: editing a MIDI clip while it plays no longer leaves notes hanging: a note the edit removes, mutes, re-pitches, shortens or moves (or whose clip, track timing, MIDI Track Offset or tempo changes) is released at once, on hosted and built-in instruments and on external MIDI outputs (#556).

## Added

- **Consolidated stems and MIDI for session interchange.** Export one full-length stem for every audio, instrument and MIDI track and a MIDI file for every MIDI or instrument track, plus a tempo file, for moving a session into another DAW. Contributed by @BlueJayLouche.
- **Run without audio hardware.** `transit --null-audio` starts transit on a built-in silent device: no audio hardware is listed or opened, hosted plug-ins still load and open their editors, and the transport and meters run. Fixed at 48 kHz stereo with 512-sample blocks; recording is unavailable and no MIDI ports are opened in this mode. See Troubleshooting, "Running without audio hardware".
