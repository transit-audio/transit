# transit v0.7.2

This is a patch release (in progress). transit is alpha-quality software and the session format may still change, so back up anything you care about.

v0.7.1 ([v0.7.1 notes](v0.7.1.md)) fixed audio files, levels, the Sampler's engine and typed values. This one continues with fixes found after it.

## Highlights

- **Sample-rate conversion no longer depends on the audio block size.** When the device runs at a different rate than the session, the output is the same whatever the callback size, so a ramp no longer carries wrong frames at block edges.
- **Recovered sessions and long takes save safely.** A session recovered after a crash keeps its long takes and offline files pointing at its own folder, and Save As copies long take files into the new session folder.
- **Preset names keep their dots.** "Bass v1.5" and "Bass v1.2" are two presets.

## Fixes

- Playback: the device-rate converter renders the next block as soon as an output frame needs it and keeps the previous block's last frame, so its output no longer depends on where blocks are cut; equal rates stay bit-exact. The converter is still linear interpolation, and its measured limits are listed under known issues (#525).
- Presets: a dot in a saved preset name is part of the name, so "Bass v1.5" and "Bass v1.2" write two files; `track.save_preset` appends `.tpreset` unless the name already ends in it, and a device preset's Save As appends the format's extension. Saving over an existing preset file still replaces it without asking (#487, still open for that part).
- Recovery: a session recovered from an autosave belongs to its own folder, not the deleted autosave folder, so the next save keeps the paths of long takes and offline files (#572).
- Save: Save As, Save Copy In and the first save of an untitled session copy a long take's file into the session's Audio Files when it lives anywhere else, checked and without replacing a file; if the copy fails, the save fails naming the file and the earlier session file stays as it was (#573).
- Recording: Record pressed while the cycle is already playing, anywhere in the loop, cuts the audio take into one take per lap, as it does MIDI: the first take runs from where you pressed Record to the loop end, the rest are whole laps. It used to make one clip that ran on past the loop end (#567).
- Recording: cycle recording no longer drops everything after lap 1,000 without a word. Every lap is a take, up to 10,000 laps (over five hours of a one-bar loop in 4/4 at 120 BPM); when a recording reaches that, it stops by itself, keeping every lap, and the status line says it ended at its limit. Press Record to go on. A last lap shorter than an eighth of the loop is still not a take, but the status line now says so (#522, #634).
