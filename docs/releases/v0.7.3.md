# transit v0.7.3 (in progress)

This is a patch release (in progress). transit is alpha-quality software and the session format may still change, so back up anything you care about.

v0.7.2 ([v0.7.2 notes](v0.7.2.md)) fixed recording, saving and plug-in hosting. This one continues with fixes found after it.

⚠️ **Changed behavior** (details under Fixes): a stereo audio track routed to a mono input records and hears that one input on both sides; it used to take that input and the next one.

## Fixes

- Linux, JACK system: the input device picked in Audio > Audio Devices is the one that opens. transit used to take the input from the output's device whatever was picked, and said the picked input was not available. If the output device has no inputs and none is picked, the first device that can record is used (#682).
- A stereo audio track can take a mono input. On a device with one input channel its input menu used to list nothing; now a stereo track's input menu lists the stereo inputs, then the mono ones, and a mono input is recorded and heard on both sides. A stereo track with no input set reads "In 1" on such a device, which is what it records. Changed behavior: a stereo track already routed to a mono input (a session edited through the control channel, or a stereo input path narrowed to one channel in Audio Devices > I/O) used to take that input and the next one (#681).
