# transit v0.7.3 (in progress)

This is a patch release (in progress). transit is alpha-quality software and the session format may still change, so back up anything you care about.

v0.7.2 ([v0.7.2 notes](v0.7.2.md)) fixed recording, saving and plug-in hosting. This one continues with fixes found after it.

⚠️ **Changed behavior** (details under Fixes): a stereo audio track whose input is a mono input records and hears that one channel on both sides; it used to take that channel and the next one. This includes a track made stereo from a mono track on a named mono path.

## Fixes

- Linux, JACK system: the input device picked in Audio > Audio Devices is the one that opens. transit used to take the input from the output's device whatever was picked, and said the picked input was not available. If the output device has no inputs and none is picked, the first device that can record is used (#682).
- A stereo audio track can take a mono input. On a device with one input channel its input menu used to list nothing; now a stereo track's input menu lists the stereo inputs, then the mono ones, and a mono input is recorded and heard on both sides. A stereo track with no input set reads "In 1" on such a device, which is what it records. Make Stereo on a mono track whose input has no stereo pair (the one input of a one-input device, or the last input of an odd count) keeps that input on both sides instead of refusing; a numbered input with a pair still becomes the pair ("In 3" becomes "In 3-4"), and a named input path is kept. Tracks wider than stereo and FX channels are unchanged. Changed behavior: a stereo track whose input is a mono input, including a track made stereo from a mono track on a named mono path, now records that one channel on both sides where it used to take that channel and the next (#681).
- Audio Devices > I/O: a device whose saved I/O table had no inputs (saved while its input did not open) gets the default input paths ("In 1" and so on) when it opens with inputs. Paths you made stay, and a default you removed stays removed (#690).
- Baking a looped MIDI clip no longer moves notes that sit before the loop start onto the clip's first tick: they stay where they are, as playback plays them (#441).
- Dragging several clips toward the start now previews every clip stopping together, where the drop has landed since v0.7.1 (#441).
