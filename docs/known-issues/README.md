short kebab-case slug, with a hidden `status` and `follow-up` block and the issue text under it. The table
below is generated and is not committed by contributors: `main` regenerates it after the merge
([ADR 0050](../adr/0050-generated-indexes.md), [CONTRIBUTING.md](../../CONTRIBUTING.md)). The 125 rows that

## Release-note caveats

- Published Windows builds open audio through native WASAPI and native ASIO only (ADR 0046,
  `../releasing.md`); a device only the retired cpal path could open stays closed with the reason (K111).
- Windows builds are unsigned. macOS builds since v0.7.3 are signed with a Developer ID and notarized by Apple, confirmed on Apple silicon (#674); earlier macOS builds are ad-hoc signed and not notarized.
- Creating a heavy plug-in (a large instrument) can block the UI for the duration of the create.
- Live MIDI input is WinMM-based and its timing may be flagged approximate when the device clock
  fit is unavailable (`../contributing/knowledge/clocks.md`).
- Sample rate and buffer-size selection depend on the backend and driver; report the device, driver
  and settings with any timing issue (`../contributing/evidence/hardware-and-ci.md`).
- Audio Devices: an ASIO driver other than the one that runs is not described until Apply opens
  it, so its rate and buffer lists are the standard choices marked "updates after Apply".
- From v0.7.0, transit reports itself to plug-ins as "transit" (CLAP and VST3; it
  said "SoundCraft" before). Plug-ins that keep settings per host see a new host once: a first-run
  dialog or per-host defaults may come back.
