A plug-in editor that neither takes the host's scale (VST3 `IPlugViewContentScaleSupport`, CLAP `set_scale`) nor reads the monitor's DPI itself draws at 100% on a scaled display (#101). Since #153, on Windows, the editor window's Scale menu (Auto, 50% to 200%, remembered per plug-in on this machine) settles it: under Auto an editor that refuses the host's factor is stretched by Windows to the display's scale (its content container is DPI-unaware, so the plug-in reads 96 DPI and is never scaled twice; the drawing is softer than a sharp one), and an editor that accepts the factor draws itself at it. An editor that accepts the factor and keeps drawing at its own size cannot be told apart by its answer: Auto sends it the factor, the menu shows a hint when its size did not change, and the user picks the plug-in's own zoom or the Windows stretch for it. A stretch turned on or off applies the next time the editor opens; a new factor applies at once. A VST3 plug-in that applies the factor only once attached gets it again after `attached` (#105); one that refuses before `attached` is stretched and not asked again. The info log shows, per editor, whether it accepts a factor, the factor in use, the mode and each resize. On Linux only editors that accept a factor can be scaled, and the window has no menu there yet (K94); macOS scales editors itself and its window has no menu either (K116).
