A plug-in editor that neither takes the host's scale (VST3 `IPlugViewContentScaleSupport`, CLAP `set_scale`) nor reads the monitor's DPI itself draws at 100% on a scaled display (#101). Since #153, on Windows, the editor window's Scale menu (Auto, 50% to 200%, remembered per plug-in on this machine) settles it. Under Auto an editor that accepts the factor draws itself at it, and an editor that refuses it keeps its own 100% drawing, opened exactly as before #153; the menu's hint line says that Stretched by Windows can be tried. Only the explicit Stretched by Windows mode stretches; Automatic never does, at any step (a percentage a refusing editor cannot draw itself is not realized in Automatic, and the menu says it needs Stretched by Windows), because a GPU-drawn editor came up black stretched (see the known issue on black stretched editors). Picked for a plug-in, Stretched by Windows enlarges such an editor to the display's scale (its content container is DPI-unaware, so the plug-in reads 96 DPI and is never scaled twice; the drawing is softer than a sharp one). An editor that accepts the factor and keeps drawing at its own size cannot be told apart by its answer: Auto sends it the factor, the menu shows a hint when its size did not change, and the user picks the plug-in's own zoom or the Windows stretch for it. A stretch turned on or off applies the next time the editor opens; a new factor applies at once. A VST3 plug-in that applies the factor only once attached gets it again after `attached` (#105); under Auto it is asked again whatever it answered before, and with a setting the user picked one that refuses before `attached` is not asked again. A VST3 view to be stretched is released and made again inside the DPI-unaware context; a controller that gives back the same view object is detected and that editor is not stretched, but one that makes a new view reusing what it cached from the first (the monitor's DPI) cannot be told apart, and such an editor would be scaled twice (an assumption the probe checks). The info log shows, per editor, whether it accepts a factor, the factor in use, the mode and each resize. On Linux only editors that accept a factor can be scaled, and the window has no menu there yet (K94); macOS scales editors itself and its window has no menu either (K116).
