On macOS the first armed serial render (panics firing through the full render path) allocated one extra 64-byte block compared with the same panics measured outside the render (GitHub's macOS runners, x86_64 and aarch64: 14 allocations and 504 bytes against 13 and 440, frees equal); Windows and Linux add nothing. Hypothesis (inference): a lazy unwind-info cache in Apple's libunwind filled the first time the render's frames are unwound. `crates/mix/tests/strip_panics.rs` now warms the render path once before measuring and keeps the strict assertion; if the macOS runner still fails after this change, the tolerance returns and the row stays open.
