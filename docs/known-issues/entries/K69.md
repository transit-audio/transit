Native JACK (ADR 0021): a server quantum or rate change while the device runs reopens it (the transport stops; a take is kept). Under PipeWire's JACK library that happens when another program forces a quantum, when a forcing client leaves, when the node moves to another driver or when the driver resumes; PipeWire does not change the quantum just because another client asks for a smaller one, since every JACK client locks the quantum by default and only a forced quantum overrides the lock (#760, ADR 0021 amendment, rule 7). The rate and buffer size are taken from the active client, and a chosen buffer size that arrives within half a second of opening is the device's (#760, slice 1); a graph rate other than the one transit prepared for costs one rebuild before any audio. On the first PipeWire desktop that ran v0.7.4 the device still reopened in a loop at every start: each new client read one buffer size right after it became active and ran another once its ports were linked (#760, 2026-11-21 report). Since then transit, under PipeWire, links its ports before it settles the device's figures, then waits at most half a second for the first process cycle after the links, or for the buffer size the graph ran when transit last saw it, which it remembers across a reopen (a server shutdown forgets it). Links made outside transit that the reopen brings back are restored before the device settles, so a link that moves transit to another buffer size does not reopen it again; a chosen buffer size the graph does not run is shown as declined and the device settles on what runs; a rate that changes once transit's ports are linked costs one rebuild, not an alternation. A buffer size that moves after the start still reopens the device once, and that reopen settles on the new size instead of reopening again. Checked against a simulated server only; not yet confirmed on a PipeWire machine.
