A VST3 plug-in binary that changes on disk (#380) while transit has it loaded (an installer, or a new build copied over it) cannot be loaded again until transit restarts: a new instance of it fails to load, and the log says "changed on disk or was removed since transit loaded it; restart transit to load it again". Running instances keep the code loaded before, and transit never unloads a module. A binary written over in place on Linux or macOS can crash those instances; a rename-over is safe, and Windows refuses to write a loaded DLL. The check compares the binary's size and modification time, and on Linux and macOS its device and inode: a `touch` also counts as a change, and a same-size copy that carries the loaded file's own modification time does not when it is written in place, nor on Windows when it replaces the file. #379 does the same for CLAP plug-ins (#348).
