Recording under very heavy load (#184). One run, with two compiles and a Linux gate on the same machine, recorded a 4.7 s stretch of exact digital silence in both armed inputs at the same place, and nothing was logged; it has not recurred in a longer run under heavier load. The cause is not known: either the take writer fell behind until the input queue was full (transit then records the lost input as silence so the take keeps its timing), or the interface delivered zeros while still running. transit now counts the input it records as silence in place of input it did not have: input refused because the take writer fell behind, the zeros WASAPI puts in place of lost input after a discontinuity, and invalid samples (not a number or infinite). A loss of 1 ms or more shows on the status line while recording and goes to the log when it begins; at Stop every counted loss is named, with how long and from how far into the take (or that it started before the take began, in a count-in or pre-roll). Invalid samples reach the log only at Stop. Not counted: a JACK input port with no buffer and an ASIO input channel without a buffer, which affect the whole stream rather than a stretch of it. Separately, the log notes any stretch of exact digital silence of 100 ms or more between signal in a take.
