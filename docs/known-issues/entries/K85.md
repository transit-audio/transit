CLAP binaries are never deinitialized at exit: `clap-host` keeps every loaded bundle for the life of the process, and `clap_entry.deinit` runs only when a bundle is dropped, which never happens. They are not counted by the cleanliness check (`shutdown_plugin_hosts`, #104), so a session with only CLAPs always reads clean and exits normally; a CLAP whose static destructor waits on a worker thread that only `deinit` stops could still hang a quit, as in E56. No such plug-in is known. Tracked in #112.
