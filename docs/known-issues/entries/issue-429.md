Linux recording through cpal ALSA under PipeWire (#429). The native JACK system on PipeWire records (confirmed on v0.7.3); the ALSA path is not confirmed. The refusal "recording start fell outside retained input history" seen at a 2048-frame period is not an undersized history (it holds 4 s at any period and channel count): it means the output's playback-time estimate and the input's capture-time estimate disagree on that machine. A start that maps less than one input block (at most 100 ms) before the first retained frame starts the take there, marked approximate; further than that it is still refused (#587). An input period of 100 ms or more (a PipeWire quantum of 4800 frames or more at 48 kHz) lets the input clock map go stale between callbacks: a record start on a separate input then waits up to a second for a current map and is otherwise placed by the last validated one, marked approximate. The input of an ALSA server or default PCM ("default", "pipewire", "pulse", sysdefault) whose widths run contiguously from 1, a converting plug-in, opens stereo (else mono): those widths are an upmix of one source, not separate inputs. Every other device keeps its widest width, including a card (cpal lists it as plughw) and an interface whose widths change per rate band; where that widest width does not exist at the chosen rate the input does not open.
