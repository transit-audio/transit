A plug-in that never returns on the plug-in host thread (Guitar Rig 7 browsing presets in its editor, #205; the companion of K89 on the host thread) cannot be stopped: its editor window turns into Windows' "not responding" ghost, and End Task on the ghost ends transit, because the window belongs to it. Audio keeps playing and saves keep that plug-in's stored state. transit names the plug-in and the call in a message, in the log (when it first runs past its budget and every 60 s after) and in Copy diagnostics (Plug-in host). Give up quarantines the thread (ADR 0018 amendment 2026-10-29): its plug-ins are never called, freed or reused again and their stored state is saved, but the thread and the ghost stay until transit exits; the hide of its windows takes effect only if the thread retrieves messages again. Give up hides a plug-in's own modal dialog too when that dialog still pumps messages, so a hang the plug-in would have recovered from (the user answering its dialog) becomes permanent for that thread: choose Later first, and Give up only when audio must keep going and the plug-in does not come back. A new instance of the same plug-in, made on the fresh host thread (a session reopened, the plug-in added again), may block on locks the stuck call still holds in that plug-in's library, so each reopen can wedge one more host thread. Live slots on a stuck or given-up thread carry the Unresponsive marker in the mixer insert row, the device card and the arrange track header (#213), also after Give up and after the stuck call returns; the hover text names the stuck call and how long it has run while the call is live, and says you gave up afterwards; the marker clears when the call returns, unless you gave up on the thread.
