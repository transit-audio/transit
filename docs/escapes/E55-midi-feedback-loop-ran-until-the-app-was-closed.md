# E55: A MIDI feedback loop ran until the app was closed

1. **Failure.** Build 6f7670c, Windows (#99): an External Instrument track whose Out was the Arturia KeyStep Pro's own port, record-armed, with the controller's MIDI thru on. One key press started a stream (the MIDI Monitor showed CC 64 0 and CC 123 going out and coming back about every millisecond) that stopped only when transit was closed.
2. **Mechanism.** The ingress worker echoed every admitted input message of an armed or monitored external track to the track's port, with no notion of where the input came from. The controller forwarded the echo back to its input, which was echoed again. Channel-mode messages (CC 120 to 127) were echoed like any controller, so transit's own Sustain off and All Notes Off joined the loop. Nothing on the input path bounded a port's message rate.
3. **Why checks missed it.** The echo tests (`device/external_tests.rs`, `midi_out/tests.rs`) used separate fake input and output ports; no fixture modeled a device that returns what it is sent. There was no earlier self-echo guard that regressed: the echo path never compared input and output devices.
4. **Regression tests.** `crates/playback/src/player/native/tests/feedback.rs`: a fake device whose output is looped to its own input (`Thru`). `a_looped_device_with_echo_allowed_and_no_detector_storms` reproduces the storm. `by_default_input_is_not_echoed_to_its_own_device_so_no_loop_forms` fails at runtime with the self-echo guard removed (`port_routes`). `with_echo_allowed_the_storm_detector_mutes_the_port_and_releases_its_notes` fails at runtime with the detector removed. `channel_mode_messages_are_never_echoed_and_all_notes_off_in_sends_no_release` fails at runtime with the channel-mode filter removed. `a_dense_sequencer_stream_is_echoed_and_never_muted` and the stamped-time tests in `player/ingress/storm.rs` bound false positives (1,000 and 1,900 messages a second, a 1/128 ratchet, Clock at 300 BPM and a Clock flood, an NRPN sweep at 500 updates a second and encoder ticks at 300 a second). A first version counted any identical message, which muted NRPN sweeps and relative encoders and tripped `step_tap_overflow_resets_the_ui_then_accepts_new_input` (384 identical CC 64 on a port with no echo route) in review; repeats now count only when they match transit's own recent echo to the port's device, and only ports with an echo route are watched.
5. **Gate class.** No self-echo or storm guard on the MIDI input path: any path that sends live input to an output must be tested against a device that returns what it is sent.
6. **Protocol change, owner, blind spot.** A row in `docs/contributing/evidence/gates.md` requires the looped fake device for changes to echo, MIDI thru or output routing. Owner: MIDI output maintainers. Blind spot: the device rule's WinMM id comparison is unverified on hardware (names are compared too), and a loop slower than a 4 ms round trip with few messages stays under both bounds (K68).
