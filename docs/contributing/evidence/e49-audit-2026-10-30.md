# E49 test audit: threads, render workers, host threads and backends (2026-10-30)

Issue [#226](https://github.com/transit-audio/transit/issues/226). Phase 1 is the table; phase 2 fixed every FIX row and added `cargo xtask timing` rule (e) (see [Phase 2](#phase-2-the-fix-rows-and-rule-e)). The table records each test as phase 1 found it. Read it with [E49](../../escapes/E49-echo-latency-test-wall-clock-bound.md) and the timing rules in [gates.md](gates.md).

## Why

In the 24 hours after v0.4.1 four tests failed on CI runners while they passed locally and on the other runners. Each depended on how fast a thread woke or on the order of asynchronous steps, and none was a product defect:

1. `strip_panics::parallel_panicking_instruments_drop_no_payload_on_a_render_worker` (macOS arm64) inherited the default strip deadline, so every strip could be late and nothing was home to raise a panic.
2. `render_workers::continuity_through_a_real_worker_set_with_stalls_and_live_midi` (macOS) had no `expect_from(0)` baseline, and its closing blocks ran at the short deadline.
3. `render_workers::a_plan_waits_while_a_worker_holds_a_strip` (macOS x86_64) waited for any away strip instead of the strip it had held.
4. `audio-asio stream_tests::a_session_orphaned_while_the_host_was_stuck_is_swept` (Windows) let a free host thread sweep between the drop and the read; the host is now held inside a request.

Earlier E49 recurrences have the same shape: a tight bound, a sleep that decides the outcome, or a poll for an effect other than the one asserted. The rule, in one sentence: **a test that takes a pool or host-thread path decides every outcome itself, with a completion signal, an observable state, a held worker it waits on, an explicit instant or a far deadline; a wall-clock bound may only be a stall bound, and a default deadline is never inherited.**

## Method and scope

- Read-only, by static reading of each test body and the helpers it waits through. Nothing was run.
- A scan of every `#[test]` in `crates/mix`, `crates/rt`, `crates/plugin-host`, `crates/audio-asio`, `crates/audio-io`, `crates/playback` and `crates/ui-studio` (2,186 tests) selected those that start a thread, sleep, yield, park, wait on a channel with a timeout, set or inherit a strip deadline, hold a worker, read a clock, or render through the worker set. Tests that only mention one of those words in a comment were dropped by reading them.
- `crates/audio-io` has no test that starts a thread or waits (its tests decode and encode files), so it has no rows.
- Every test in `crates/mix/tests/` that takes the worker path is listed whether or not it sets a deadline, because that is the class (a test that renders on workers without a deadline would otherwise be invisible to a keyword scan).
- The playback runtime starts render workers for every engine (`plan_bridge.rs` calls `start_render_workers` unless `force_serial` is on) and the worker path engages at four phase-1 strips (`PARALLEL_STRIPS`). No playback or ui-studio test builds four or more strips and asserts audio on the device thread: the largest builders use three tracks, and they assert state or captured state. So the gates.md rule about `force_serial(true)` has no violator today; a scan cannot see a track count passed through a helper, which is why the proposal below includes a runtime guard.
- "Waits on" names what decides the outcome. Verdicts: **OK** (a completion signal, observable state, injected or explicit instants, a frame count, or a far deadline; any wall-clock bound is a stall bound of seconds), **JUSTIFIED** (a wall-clock element remains and the reason is stated: the product behavior under test is itself a timeout, the sleep sits before a negative assertion that a slow host cannot fail, the bound is one-sided, or the assertion is liveness over thousands of seeded blocks), **FIX** (a slow host can fail it; the fix shape is in the row).

Rule (e) also found five places that ran their closing blocks at the short deadline before a stuck-note check (`a_plan_waits_while_a_worker_holds_a_strip`, `stop_while_a_strip_is_away_drops_what_was_parked_for_it`, `an_overflowing_ring_while_a_strip_is_away_leaves_nothing_stuck`, the `parked_then_settled_then_released` helper, and `render_graph::continuity_across_upstream_missed_skips`, named under the FIX table); each now sets a far deadline first. Five justified tests carry markers: the two continuity tests and the two allocation tests (`explicit-deadline`: injected stalls longer than an explicit short deadline, assertions that hold for any schedule) and `strips_unstarted_before_their_first_render_are_holes_too` (`held-worker`). Run against the test files as they were before the 2026-10-29 and 2026-10-30 recurrences, the rule flags both recurrences and every mix FIX row.

Still open: the runtime backstop below (follow-up). The #147 `run_loop` timer test and the `editor_x11` tests were re-audited when #147 merged (rows below; one product fix, E64). #220 (a timing rule for a pool test that neither sets a deadline nor holds the workers) closes with this work.

Known blind spots of rule (e), follow-ups until the runtime backstop exists (the scan is keyword-based; review still checks order and targets): a bare `.finish(` or `run_at(` anywhere in the evidence counts as explicit instants (a hasher's or builder's `finish()` too); any deadline other than `None` counts as the test's own for refusal 1, a medium one (such as 200 ms) included; deadline names resolve file-wide, first match, so a `let d` in one test can classify another test's `d`; a hold and its `holding` read are not checked for order or strip; a host test's give-up is any `from_secs(N >= 5)`, a normal `shutdown` included; refusal 4 sees only a reset of a plain local (`x = Instant::now()`, with or without the `std::time::` path), not a field, and a break on the same or the next line; refusal 5 sees only `stall_ns.store(`, `hold.store(false` and `HOLD.store(false` in the fn, not a release through a guard's `Drop`, `release_all` or a helper; helpers in another file are not followed.

## `cargo xtask timing` rule (e), as proposed

Implemented in phase 2 (`xtask/src/timing_pool.rs`; the rule as built is in [gates.md](gates.md)). Differences from this proposal: a bare `transit-rt` worker set is not a trigger (its `finish` takes each block's deadline, so there is no default to inherit) and a pool test must render a block; refusal 3 is the positive `while ..render_workers_settled()` loop only (the negation waits for every strip to come home, which is the completion signal); refusal 4 applies to any test fn or helper, always refuses a `while` exit on the reset clock, and allows only a no-progress guard of 5 s or more that breaks into a later assertion (or panics), per E62; the refusal tests are in `xtask/src/timing_pool_tests.rs`, not `timing_tests.rs`; `explicit-deadline` also covers injected stalls longer than an explicit short deadline when every assertion holds for any schedule.

Before it, the timing gate (`xtask/src/timing.rs`) saw short literals, sleeps and short polling loops. It could not see a deadline a test inherits, or a wait that is satisfied by the wrong event.

**Which files it scans.** Test code as the gate already defines it (`#[cfg(test)]` modules, `tests/`, `tests.rs`, `*_tests.rs`), in these crates only: `mix`, `rt`, `plugin-host`, `audio-asio`, `playback`, `ui-studio`. A test fn is a pool or host-thread test when its body, or a same-file helper it calls (the one-level resolution rule (d) already uses), contains any of: `start_render_workers`, `start_render_workers_with`, a `rig(`/`keyed_rig(`/`Rig::new(` call in a file that also names `common::workers`, `WorkerSet`/`set_of(`, `Host::new`/`Host::spawn_after`/`slow_host(`/`host(` in `plugin-host` tests, `rig_watching(` or `hold_host(` in `audio-asio`.

**What it requires.** Each such fn must show one of the following, in its body or a same-file helper, or carry a marker on the fn line or the line above:

- a far deadline: `set_strip_deadline(Some(Duration::from_secs(N)))` with N at least 10 (marker `// timing: far-deadline <reason>` when the literal is a named constant in another file, e.g. `FAR`);
- a held worker: a `.hold.store(true` (or the file's hold helper) **and** a read of its `holding` or `entered` flag before the assertion (marker `// timing: held-worker <reason>`);
- explicit instants or a zero deadline: `set_strip_deadline(Some(Duration::ZERO))`, or `set_block_deadline(` / `run_at(` fed an `Instant` built from `Instant::now()` plus or minus a literal (marker `// timing: explicit-deadline <reason>`);
- serial rendering: `MixEngine::force_serial(true)` for a worker-using engine that is not under test (marker `// timing: serial <reason>`);
- for host-thread tests: a gate channel or state poll with a 5 s or longer give-up, which rule (d) already checks, plus `// timing: host-timeout <reason>` where the test's subject is the host's own timeout.

**What it refuses.**

1. A pool or host-thread test with none of the above (the inherited default deadline: E49 recurrence 2026-10-29).
2. A short strip deadline (`from_micros(N)`, or `from_millis(N)` below 100) in a fn that does not also hold a worker or use `Duration::ZERO`: a short deadline with no hold leaves "who misses" to the scheduler.
3. A loop `while ...render_workers_settled()` (or its negation) used to find "a strip away" in a fn that also stores `stall_ns` and later asserts a per-strip outcome (`Queued`, `StaleBinding`, `midi_dropped`, `held_tracks`) without reading `holding` first: the wait must be on the strip the assertion is about (E49 recurrence 2026-10-30). The marker `// timing: any-strip <reason>` allows a test that really means any strip.
4. A quiet-period wait: a loop that exits when a value has not changed for N ms (an `Instant` reset inside the loop on change, as in `no_render_promotion.rs::settle`). The exit must name the state.
5. A closing block sequence before a coverage assertion (`assert_time_covered`, `hole_samples`, `stuck_notes`) that does not run at a far deadline after the last stall or hold is released.

**What it cannot see**, and the backstop (not built in phase 2: playback applies the default share itself through `set_block_deadline`, `plan_bridge.rs` `set_callback_deadline`, every block, so a guard keyed on "no `set_block_deadline` call" would never fire for the playback and ui-studio tests it is meant to cover; it needs a test-only flag distinct from the block deadline, a follow-up). Helpers in another file (the shared rig in `common/workers.rs`), and playback or ui-studio tests that reach four strips through a helper. A runtime guard covers both: in `cfg(test)` or `testing` builds, `StripPool` counts a block rendered under the inherited default share and fails the test on drop unless the test called `set_strip_deadline`, `set_block_deadline`, or `MixEngine::allow_default_deadline()`. That turns the keyword rule's blind spot into a deterministic failure on the first local run. The two together are the gate class for E49 recurrences 2026-10-29 and 2026-10-30; the xtask part needs tests in `xtask/src/timing_tests.rs` for each refusal above and its marker.
